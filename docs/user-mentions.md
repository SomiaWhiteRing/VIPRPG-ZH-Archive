# 讨论版与评论的用户提及

## 参考与取舍

2026-10-02 通过直接 HTTP 阅读了 [Mastodon 官方发帖文档](https://docs.joinmastodon.org/user/posting/#mentions)：输入 `@` 提供用户候选，提及与回复是不同操作，被提及用户接收通知。尝试读取 [X 的提及与回复帮助](https://help.x.com/en/using-x/mentions-and-replies)，但被访问验证拦截；未将 X 或微博的当前界面行为作为已核实事实，也未进行浏览器交互。

本平台的讨论版与评论共用 `BodyEditor`，因此搜索、插入、撤销与复制统一实现。按需求，键入 `@` 和点击工具栏的 `@` 按钮都打开依附正文输入区的非模态搜索面板，焦点进入搜索框；复用表情选择器的 Popover 定位方式，不使用居中面板或遮罩。@ 和图片工具按钮仅显示图标，保留悬停提示及无障碍名称。键入中文后接 `@` 也能触发；常见邮箱中的 `@` 保持普通文本。粘贴文本不会强制打开面板。

本平台没有独立的公开用户名字段，昵称不能充当身份键。候选显示昵称与头像，正文存储稳定 ID 和选择时的昵称快照。账户改名后链接仍指向同一用户，历史正文保留原昵称。服务器校验新提及的 ID 与昵称，搜索后发生改名、停用或注销时要求重新选择，不能伪造他人的提及标签。

## 交互与范围

- 适用于讨论主题、楼层、楼内回复，以及作品、作者和角色评论，包括各自的编辑入口。
- 支持昵称包含搜索或精确用户 ID；250 ms 防抖，取消过期请求，最多返回 20 个活跃账户。接口要求登录，不返回邮箱、角色或其他账户私有字段。空查询不枚举用户。
- 方向键浏览、Enter 选择、Escape 或收起按钮取消，点击外部关闭且不夺取点击目标焦点；中文输入法组合期间不提交搜索选择。取消直接输入触发的面板后，保留原来的 `@`。选择后插入完整提及节点与空格。
- 提及节点可整段删除、撤销、复制，并可恢复为可编辑草稿；正文展示为指向用户主页的 `@昵称`。字数按可见昵称计数，摘要与搜索索引使用可见文字，图片偏移继续按持久化正文计算。
- 全屏讨论编辑时面板挂载到全屏容器，避免被其 `inert` 隔离；普通模式挂载到页面，避免父级面板的变换影响定位。

## 通知

发布与通知处于同一数据库批次：讨论以本次 revision 为门槛，普通评论以发布 request key 或紧接更新的 `changes()` 为门槛。失败、权限冲突或发布重试不会独立产生通知。

每条内容最多提及 20 位不同用户；同一对象的重复提及去重，不通知自己或非活跃账户。编辑只处理相对旧正文新增的用户；事件键保证删除提及后重新加入也不重复提醒。同一内容已经给该用户发送回复或作品评论通知时，保留既有通知，不追加第二条。

复用现有 inbox 内容关联与 `metadata_json.mention`，无 schema 迁移：普通评论提及进入评论通知，讨论提及进入讨论通知，显示“在评论中提及了你”或“在讨论中提及了你”。读取通知时沿用内容公开性检查；不可用内容不展示正文和发送者信息。普通评论链接沿用目标页面评论区入口，讨论通知沿用楼层定位。

## 验证边界

使用现有 TypeScript、ESLint、UI 静态检查和讨论版契约检查。没有新增测试代码；既有契约检查不包含新提及功能的专项断言。真实浏览器的输入法、触屏键盘、焦点、嵌套面板、全屏和通知端到端行为仍需人工验收授权。未推送、部署或写入正式数据。
