# 角色素材库

角色详情的素材区按固定顺序显示「脸图」「行走图」「怪物／战斗图」「插图及其他」，空分类不显示。分类使用清单的 `kind`，不根据文件名或图片外观推测，也不直接显示日文来源栏目标题。图片平铺，悬停时显示手形指针，点击打开灯箱；灯箱右上角提供当前图片的原图下载入口，切换图片后下载目标随之更新。

桌面端（宽度大于 980px）进入素材标签时收起左侧资料，离开时展开，也可通过圆形箭头按钮手动切换。收起后只露出按钮的右半圆，资料宽度和素材可用宽度平滑过渡；系统选择减少动态效果时不播放动画。移动端始终显示资料，不显示折叠按钮。

脸图继续使用 `face_sheets` 和现有角色绑定及头像格子规则。其他三类由 `character_materials` 保存原文件 blob、分类与尺寸，`character_material_bindings` 保存角色关联。同一图片可属于多个类别或角色，分类内按素材去重。公开图片接口只开放有角色绑定且 blob 可用的素材。

后台素材工作台首屏只读取当前角色的绑定。素材库按类别和搜索词在服务端筛选，每页 48 条，按需加载后续页；绑定草稿与搜索结果分别保留，切换类别或搜索不会丢失尚未保存的选择。[统一初始化 SQL](../migrations/0001_init_archive_schema.sql) 包含素材分页和角色评论计数索引。

`data/character-materials/manifest.json` 是已确定或人工接受的素材导入清单，原图位于相邻 `assets/`。清单保存完整来源、原文件名、栏目路径、HTML 图片顺序 `sourceOrder` 及归属决定；请求时使用数据库中的角色 ID，不按名称临时匹配。角色合并迁移素材绑定及排序。素材引用纳入现有垃圾回收排除条件与数据库清理保护。

三类素材在各自分类内按源站 HTML 中的图片出现顺序排列，顺序写入 `character_material_bindings.sort_order`。共享图片按当前角色对应的来源排序：优先采用角色资料中的来源页顺序，其他来源页按 URL 的页码排序；同一来源页内采用 HTML 顺序。同一图片多次出现时取首次位置。脸图沿用已有的来源／绑定排序。

## 本地导入

常规开发通过[固定种子](./local-demo-data.md)恢复已审核的数据库及 R2 快照。显式从素材清单导入时，数据库必须已具备[统一初始化 SQL](../migrations/0001_init_archive_schema.sql)定义的当前结构及清单引用的角色，然后执行 `npm run db:local:character-materials`。空库的 schema 可通过 `npm run db:local:migrate` 建立；已经登记旧版同名初始化文件的数据库不会由此升级，备份与重建按本地展示数据手册执行。

`node scripts/import-character-materials.mjs --dry-run` 校验三类非脸图素材的文件、角色映射及来源顺序，不上传或写入；它跳过脸图导入阶段，不能据此宣称脸图也已校验。

素材库构建器从 `output/playwright/character-materials/<页码>.json` 保存的源站正文 HTML 提取顺序。已有清单可运行 `node scripts/character-material-source-order.mjs` 刷新来源顺序，再重新导入。HTML 缺失或找不到对应图片时中止，不用哈希顺序代替；正常导入只读取清单，不依赖采集缓存。

脸图和其他素材分阶段导入，各阶段先检查文件路径、哈希、大小、图片尺寸和角色归属；名称使用当前日文默认名或唯一日文别名匹配，缺失或歧义会中止该阶段。原图增量上传到本地 R2，之后按批次登记 blob、素材及绑定。重复执行可续跑，不删除已有角色或绑定，不重置开发数据库。不执行远端部署或写入。

自动生成角色的明确来源归属保存在 `data/character-classification-bootstrap.json` 的 `materialAssignments`：以来源页、成员章节前缀或逐图文件名限定范围。只有页面本身明确是单人页面时才采用整页；多人共用素材可关联多位角色。不会根据“同一个页面”把一家的素材全部绑定给每位家人，也不会因旧词典没有该角色而丢弃素材。

素材构建时，匹配到逐图文件名的明确归属优先于旧的页面脸图锚点归属，避免重建后把士兵 X/Y 等成员的专属素材重新分配给普通士兵。

补采后运行 `node scripts/complete-character-source-materials.mjs`，它校验缓存原图并把这些归属合入现有脸图和素材清单。常规素材构建器同样执行这一步，避免重建时丢失新增角色绑定。图片尺寸读取原始字节；不符合 48 像素格子规范的脸部图片保留为「插图及其他」，不拉伸或裁掉原图。

脸图绑定与默认头像是两项独立数据。补采脚本会列出已绑定脸图但缺少 `defaults` 的名称；需核对人物和格子后补入脸图清单，再导入本地数据库。多人共用脸图按各自所在格子选择，不能把所有成员自动设为首格；没有可确认头像的成员保留缺项提示。

本地素材导入会先登记脸图对象、数据库脸图记录及角色绑定，再导入其他素材。已存在的脸图审核状态、角色绑定和默认头像不被重置；清单配置的默认头像只补给尚无默认头像的角色。显式导入前应确保新成员已存在。固定开发种子则保留快照中全部角色与其绑定，不依赖导入时的名称匹配。

图片 MIME 类型以原文件实际格式为准，保留来源文件名及原始字节。当前清单中两张 `.png` 文件实际为 BMP，导入时登记为 `image/bmp`。

登录用户可从脸图素材的「收藏为表情」进入选格工作台，将单个 48×48 格子加入个人表情库，见[表情库契约](./face-emoji-library.md)。
