# 永恒之海

`/sea` 是单一公共聊天室。消息由独立的 SQLite Durable Object 保存，通过 WebSocket 实时同步；首次打开、刷新和重连均展示最新 100 条公开对话。底栏第二行将入口与 `https://afdian.com/a/whitering` 并列。

“エターナルの海”对应新建 RPG Maker 工程时一面海水的空白地图，并关联“エターなる”的永远未完成、放弃制作之意。参见[ニコニコ大百科](https://dic.nicovideo.jp/a/%E3%82%A8%E3%82%BF%E3%83%BC%E3%83%8A%E3%83%AB%E3%81%AE%E6%B5%B7)和[もしもシリーズ設定 wiki 条目](https://w.atwiki.jp/moshimorpg/pages/348.html)。背景使用 RTP 2000 `ChipSet/基本.png` 的默认海水自动图块，不使用战斗背景。

## 渲染基准

- 默认海水为 16×16 图块，来源矩形 `(phase×16,64,16,16)`。参照 EasyRPG `TilemapLayer::GenerateAutotileAB` / `GenerateAutotiles`；慢速每 24 个游戏帧切换，序列为 `0,1,2,1`。GIF 每帧 400ms；减少动态效果时显示静态首帧。
- 对话窗口 320×80，名称独占第一行，正文占余下三行。头像 48×48，按消息顺序左、右交替。左侧头像起点 `(16,16)`、文字起点 `(80,10)`；右侧头像起点 `(256,16)`、水平翻转，文字起点 `(8,10)`。行距 16。
- 对话框按 2× 显示，宽度上限为 640px。可用宽度不足时，对话框占满扣除左右各 16px 页面边距后的宽度，并保持原比例。海水图块固定按 2× 显示，为 32×32，不随页面宽度变化。
- 采用 CP936 Gothic 字体查找顺序：WenQuanYi 优先，Shinonome Gothic 回退，最后使用替代字形。字宽取原始字形的 6/12 像素定义。
- System 默认字体颜色与阴影按 `Font::RenderImpl` 的像素位置生成；窗口按 `Window::RefreshBackground` / `RefreshFrame` 生成，选择背景拉伸模式。
- 每行限制 38 个半角单位（228px）。正文最多 106 个半角单位（全角算两个），加上引号后最多三行。正文第二、第三行默认以一个全角空格缩进，自动折行和手动换行都预留这 12px 的字宽；两行缩进合计占用四个半角单位。缩进仅影响显示，不改写输入或复制内容。输入时截住超出容量的后缀，不显示计数或容量提示；已有换行和空行原样保留到容量边界，换行不占横向字符单位。长名称仅在第一行内省略，保留完整消息名称。不支持的字形使用 EasyRPG 的替代字形。
- 输入区在上方，placeholder 为“把握”；对话列表初始定位到底部。Enter 和 Shift+Enter 均换行，点击输入区右下角的“发言”按钮提交。按钮沿用方角绿底白框的 RM2K 样式；空白或超出容量时禁用，输入法组字期间不提交。
- Android 客户端内使用整页滚动，输入区吸附在上方；初始定位和新消息跟随读取文档滚动位置。原生下拉刷新据此只在最旧对话顶部触发，不再抢占列表内部查看旧消息的手势。这项网站侧适配不需要更新 APK；普通浏览器继续使用内部列表滚动。
- 未登录可进入原型并本页发言，署名“无名的VIPPER”、使用亚历克斯头像。登录后默认使用自己的头像与账号名，点击头像切换到亚历克斯时，发言署名也切换为“无名的VIPPER”；切回自己的头像时恢复账号名。
- 对话里的账号头像用独立图片层按原图平滑缩放，不压入 320×80 的像素画布；位置和大小仍沿用 48×48 的逻辑矩形，右侧水平翻转。图片加载失败时显示亚历克斯脸图。RTP 脸图仍按原像素渲染。
- 服务端先用原文字宽排版，再将名称、正文与逐字绘制内容替换为无意义的汉字。客户端加载配套字体，通过字体显示原字形，不把字符串解回原文。画布先放大绘制字形，再采样回原像素并应用原有 System 颜色与阴影；透明选区层使用同一字体和服务端给出的逐字坐标。名称省略、正文缩进、行距、窗口与头像位置不变。
- 底层原文节点及翻译同步逻辑已移除。消息原文不会出现在公开响应或 DOM 中；复制得到混淆文字，网页翻译与无障碍工具也无法读取原文。复制仍只接管对话选区，保留手动换行与跨消息分隔，不插入视觉折行。这是提高通用爬虫提取成本的措施，拿到字体后仍可进行字形匹配或 OCR。
- 路由优先预加载海洋背景（减少动态效果时使用静态图），背景至少显示一帧后优先加载输入区窗口、默认脸图和当前账号头像；输入区准备好后先显示并可立即输入、发言。输入区至少显示一帧后再挂载对话列表，等待配套字体、图片和初始滚动就绪后一次性显示整个列表。字体请求失败沿用连接重试，不增加提示、按钮或刷新流程。仅逐字复制层使用 `content-visibility: auto` 跳过屏幕外排版。对话框尺寸、初始滚动位置和跟随规则不变。
- 输入使用原生 textarea 以支持输入法；输入控件不作为像素一致性基准。发出的消息中，窗口、文字和 RTP 脸图使用位图画布，账号头像使用独立图片层。没有运行 EasyRPG 参考画面的像素对照，不宣称已通过视觉一致性验收。

## 资源再生成

```powershell
python scripts/import-eternal-sea-assets.py --rtp-collection ../RPGRewriter-Ownuse/modules/RTPCollection/rtp-content.zip --player ../Player
```

生成脚本需要 Pillow，只读取源 RTP 和 Player。RTP 字节与当前目录指纹核对；来源摘要写在 `public/assets/eternal-sea/sources.json`。生成字体来源与声明保存在同目录 `font-notices.txt`。

混淆字体的私有模板通过下列命令生成，需要 Pillow、fontTools：

```powershell
python scripts/generate-sea-font.py
```

脚本读取现有 `font.png` 和 `eternal-sea-glyphs.json`，生成 `app/.server/sea/font-template.json`。模板只包含压缩的字形及字体表，不含字符映射、原 Unicode 字形名称，也不作为公共资源发布。沿用 `font-notices.txt` 的来源及许可。更新原位图字库时需同步再生成模板。

## 每日字体轮换

- 唯一聊天室 DO 保存当天和前一天的随机映射，每天香港时间 03:00（UTC 前一天 19:00）通过自身 alarm 轮换。首次访问也按当前日期检查；对象休眠、重新实例化或部署后复用已保存的当天映射，不会因冷启动换表。无需修改站点 cron 或部署配置。
- 字体采用 WOFF，字形压缩表复用私有模板，运行时只组装当天字符映射及字体校验字段。`GET /api/sea/fonts/:id` 返回对应版本字体，浏览器可按版本 URL 缓存；保留前一天版本用于跨整点的在途加载，过旧版本返回 404。已下载的字体不会因服务端轮换而失效。
- 页面 loader、消息 GET、提交成功回包及 WebSocket 的快照和增量统一返回 `font: { id, url, expiresAt }`。消息的 `name`、`body`、`glyphs[].character` 均为混淆文本；`glyphs` 的坐标、行号和字宽由服务端原文排版生成。数据库与受权限保护的审核接口继续使用原文，提交请求仍使用用户输入。
- alarm 推送同一消息窗口的新字体快照，即使消息 revision 未变也更新。客户端先加载新字体，再整体切换字体与消息；不整页刷新，保留输入区、草稿与滚动位置。新版本的增量先于快照到达时重新获取完整窗口，延迟到达的旧版本响应不能覆盖新版本。重新连接和返回前台沿用既有同步机制。

## 服务与权限

- `worker.ts` 导出 `EternalSeaRoom`，`SEA_ROOM.getByName("public")` 是该环境的唯一聊天室。模板沿用 `exports` 的 SQLite 声明；staging 与 production 的 binding 都属于自己的 Worker，配置校验禁止跨 Worker 绑定。
- DO 保存消息、单调编号、窗口版本号、限流状态、禁言和审核日志。前台展示查询固定为最近 100 条未隐藏消息；历史保留，未设置自动删除。左右头像由永久消息编号的奇偶决定，移出最旧消息时其余对话保持原侧。
- `GET /api/sea/messages` 返回最新窗口，`POST /api/sea/messages` 提交正文与 `own/alex` 头像选择。名称、身份、时间和编号均由服务器生成；服务器将所有选择 `alex` 的发言（包括已有记录）署名统一显示为“无名的VIPPER”，限流、禁言仍关联原身份。沿用相同字形宽度和行布局校验，拒绝空白、超限及非法控制字符。请求体上限 4096 字节。
- 每次提交具有 UUID，同一身份重试相同 UUID 返回原消息；相同 UUID 携带不同内容返回 409。客户端在提交失败时保留草稿与 UUID，成功后同步服务器窗口；实时与 HTTP 更新按编号去重。
- `GET /api/sea/socket` 显式检查 Origin，直接转发 DO 握手响应。使用休眠 WebSocket，25 秒发送一次自动响应的心跳；连接断开后逐步退避到 30 秒。快照前的增量暂存，版本缺口触发完整窗口同步。每个 IP 最多 20 个同时连接，聊天室最多 1000 个。
- 登录用户每次提交读取当前会话；失效登录态返回 401，不自动换成游客身份。游客使用 30 天 HttpOnly、SameSite=Lax 的 HMAC 签名 cookie，署名固定为“无名的VIPPER”。请求来源只使用边缘 cf-connecting-ip；本地开发使用独立的 local 标识，忽略转发 IP 头。
- 每个身份至少间隔 3 秒、固定分钟窗口最多 20 条；每个 IP 每分钟最多 60 条。限流在 DO 中处理，不占用认证邮件和浏览统计的配额。重试已提交消息不重复消耗配额。
- 账号头像关联用户 ID；读取窗口时批量解析当前头像，沿用现有用户头像的资源引用保护。已注销账号选择 `own` 的发言显示“账户已注销”，使用亚历克斯脸图；选择 `alex` 的发言仍署名“无名的VIPPER”。
- `/admin/sea` 按新到旧分页管理全部历史，每页 100 条，包含标明状态的已隐藏发言；可隐藏发言、禁言 30 分钟和解除禁言。后台显示发帖人的当前账号名与头像，匿名发言在账号名后标注“（匿名）”，游客显示“无名的VIPPER（匿名）”，注销账号显示“账户已注销”。`GET /api/sea/moderation?page=1` 返回该页、总数、实际页码与当前禁言，超过末页的页码回落至末页；账号身份字段仅通过受权限保护的后台接口返回，前台与 WebSocket 仍使用匿名署名。接口分别校验 `sea.message.moderate_any` 与 `sea.user.mute_any`；`0033_eternal_sea_permissions.sql` 赋予 admin、super_admin，并同步固定开发种子。审核日志与审核操作在 DO 同一 SQLite 事务中保存。

浏览器交互、移动设备输入和 EasyRPG 参考画面对照需单独验收，静态检查或 HTTP 检查不替代这些结果。
