# 本地展示数据

种子以 2026-09-16 本地数据库与 R2 快照为基础，持续同步 schema 和演示场景。它包含已审核的角色分类、真实来源素材，以及日常开发使用的虚构作品、账号和互动场景。

预生产使用审核过的角色资料、默认表情及八个已发布链接，不恢复完整开发快照；使用 `npm run db:staging:prepare` 生成允许的数据集，操作与验收见[预生产初始化与验收](staging-deployment.md)。

## 固定快照

`data/local-seed/database.sqlite.gz` 保存完整 SQLite 数据库，包含 schema、迁移账本、全文搜索索引、主键序列及演示记录。快照中的 `d1_migrations` 记录已同步的迁移，恢复时应用仓库中尚未登记的有序迁移。

`manifest.json` 保存数据库校验和、逐表数量及 R2 对象清单；对象文件按 manifest 路径复用仓库角色素材或 `data/local-seed/objects/`。文件格式与更新约束见[种子说明](../data/local-seed/README.md)，领域字段和权限以当前迁移链及对应契约为准。

首次初始化空环境：

```powershell
npm run db:local:seed
```

恢复前停止本地服务器。脚本先校验快照和全部对象，再写入本地 R2，通过 SQLite backup 恢复 D1，并应用仓库中尚未登记的 migration。已有业务数据时拒绝覆盖；只有明确要重建开发库时，才在自行备份后运行 `npm run db:local:reset`，再恢复种子。空库仅需 schema 时运行 `npm run db:local:migrate`。正式初始化后，已应用的初始化文件不再修改，后续有序迁移由该命令升级。历史开发库若与同名初始化不符，需另行决定并备份后重建；正式库不得套用开发重建流程。固定种子同步 schema 与迁移账本，禁止把真实正式账户或会话捕获为开发种子。

以后需要将新的人工审核结果作为种子时，暂停编辑和上传，再运行：

```powershell
npm run db:local:seed:capture
npm run db:local:seed:verify
```

capture 只读当前本地数据库和 R2，通过 SQLite 在线备份纳入 WAL 中已提交的内容，覆盖种子文件，保留全部当前记录（包括本地账号、审核状态和会话表）。它不会更新正在使用的数据库。只在本地开发环境使用这份种子。

脚本使用 `wrangler.jsonc` 的本地 binding，关闭远程 binding，默认状态目录为 `.wrangler/state`。可通过 `--persist-to <目录>` 选择隔离的 Wrangler 状态目录，例如 `node scripts/dev-seed.mjs --persist-to output/seed-restore`。capture 读取当前 Miniflare 的本地存储结构，恢复通过 R2 API 和 SQLite backup 完成。每次操作的快照与校验报告保存在被 Git 忽略的 `output/local-seed/<时间>/`。

词典、分类 bootstrap 和素材导入清单供显式整理工具使用，日常 seed 直接恢复快照。提交种子时，应一并提交 manifest 引用的新增素材文件。

## 类型样例

`0008_work_genre.sql` 为作品增加可空的自由文本类型字段。固定快照已同步迁移与账本，并在既有虚构作品中保存以下示例；这些值仅供界面演示，不是对真实作品的分类结论。

| 入口 | 类型 |
| --- | --- |
| `/games/10001` 寄往雪原的信 | `読むゲ / 短編 RPG`（保留日文原文） |
| `/games/10002` 寄往雪原的信（中文译本） | `阅读型 / 短篇 RPG` |
| `/games/10003` 夏祭之后的约定 | `观赏型 / 解谜 / ksg 合集` |

详情页右侧「作品资料」显示此字段；登录已有上传者后可在 `/me/uploads/10001` 等入口编辑，管理员也可在作品维护表单中编辑。其他作品留空，详情页不显示空行。上传页 `/upload` 可填写同一字段。

`0009_work_genre_groups.sql` 将上述三种写法登记为独立类型组并初始化公开计数，未预先合并任何类型。后台 `/admin/genres` 可以预览、合并筛选归属；名称和作品原文保持不变。详情点击类型进入作品库的类型筛选，上传候补分别显示已有公开名称，无需二次确认。

## 账号

固定快照中的活跃账号密码均为 `dev123456789`，只用于本地开发；停用和注销账号用于展示状态边界。

## 展示入口

`0031_home_recommendations.sql` 已同步到固定快照与迁移账本，推荐清单初始为空。超级管理员可在 `/admin/home-recommendations` 搜索并添加允许首页展示的游戏，推荐名单不设数量上限；候选与保存均限定 `member_works` 且 `show_on_home=1`，包含所有人可见及登录用户可见的作品。首页「站长推荐」位于「最近原创」与「随机作品」之间，没有右侧按钮，每次加载时按访客登录态过滤后随机抽取，沿用卡片网格断点显示 4／3／4 个游戏；登录用户可见的作品仅向登录用户展示，不再满足首页展示条件的作品自动停止展示。

主站和论坛开发使用 `npm run dev`（默认 `http://localhost:3000`）；验证生产 Worker 构建产物时使用 `npm run preview`（默认 `http://localhost:4173`）。以下均为相对路径。

| 功能 | 入口与场景 |
| --- | --- |

| 公开与隐私主页 | `/users/10001` 为公开资料；`/users/10003` 关闭简介、收藏、历史、目录、评论和讨论公开展示；恢复时保留快照中的隐私设置 |

| 脸图表情 | 开发正文使用真实脸图格子引用，旧停用示例显示不可用文字；默认清单留空，由后台选择 |

`0014_comment_likes_and_deleted_placeholders.sql` 为普通评论增加点赞通知引用，并保留删除主评论后的公开楼中楼。主评论及楼中楼删除后展示匿名占位，删除位置参与回复分页；已有回复的图片不会因父评论删除而被自动清理。新点赞通知进入收件箱的「点赞」分类，自赞不提醒，取消后再次点赞不重复提醒；种子保留原有点赞记录，不补发历史通知。
