# 产品方向

本文定义当前产品边界和信息架构。认证、角色、授权和审计以[认证与权限基线](./authentication-authorization.md)为准；游戏资料和归档对象以[游戏领域架构](./game-domain-architecture.md)为准。[灵感笔记](../灵感笔记.md)由人类开发者维护，不作为现行产品契约。

VIPRPG.org 是围绕 RPG Maker 作品发现、游玩、下载和讨论组织的玩家空间。

## 1. 产品边界

### 玩家空间

- 根路径始终是作品发现首页；登录状态只改变账户动作，不切换到另一套首页。
- 作品是公共导航、搜索结果和详情页的主对象。
- 作品详情第一屏回答：这是什么、能否在线游玩、如何下载。
- 作者、角色、标签和目录是发现与筛选工具，不与作品争夺首页主层级。
- 作品详情承载作品讨论：登录用户可以发表主楼评论、同主楼回复和点赞。作品、作者与角色页的短评论不生成互动提醒；论坛提醒见[提醒契约](./inbox-design.md)。
- 评论正文支持纯文本与角色脸图表情，输入时直接显示图片，不提供评分、Markdown、附件或匿名评论。
- `/discussions` 提供独立的站内讨论区：多 TAG 主题、普通楼层、单级楼中楼和精品；复用本站账户、个人表情库与权限，不建立作品关联或分区。公开性、删除占位、搜索和管理边界见[讨论区契约](./forum-discussion-design.md)。
- `/resources` 为“资源”一级导航，展示软件和参考网站，页面大标题下不显示说明文字；宽度达到 1024px 时分两列，更窄的视口保持单列，使用全站 `PageContainer` 的统一宽度（最大 1280px），同一行卡片等高、操作区底部对齐。图标使用各项目实际图案、普通白底边框与 8px 内边距；标题保留 RM2K 按钮的绿色渐变、白色描边和像素阴影，宽度随文字收缩。正文卡片的上沿线通过图标与标题的垂直中心；采用紧凑尺寸，移动端／桌面端图标框为 48px／64px、标题为 18px／20px，正文 14px，左内边距 18px／24px。操作区以横线分隔，按钮靠右排列。条目仅含名称、介绍与操作链接，不附加副标题、使用附注或来源页脚；内容由根管理员通过后台统一维护，软件下载指向本站已发布的原始文件；版本号、更新顺序与平台推荐均由本站控制，详见[资源与软件托管](./resources.md)。

### 上传空间

- 上传是围绕 Work 完成的一次操作，不是长期任务项目管理；`/upload` 只创建新作品，已有归档作品从“我的上传”按 Work ID 进入新版本上传。
- 2k 系游戏的文件准备与作品资料填写并行进行，两者就绪后自动提交；其他引擎填写作品资料与唯一外部下载地址后直接发布。
- 浏览器 Worker、文件白名单、哈希、去重、preflight、commit、引用关系和服务端 import job 是完整性边界；服务器的 `processing` 只表示上传处理，不是长期作品草稿。
- source ready 后的草稿可以在同一浏览器、同一账号下跨刷新或浏览器重启恢复，并由浏览器锁阻止两个标签页重复接管；不承诺 source ready 前恢复、跨设备接力或长期本地任务历史。
- “我的上传”展示用户可以维护的 Work；ImportJob 历史只在管理员控制台提供只读观测。

### 管理空间

- 管理空间承载内容维护、角色管理、归档一致性、存储维护和审计。
- 管理页面可以展示内部字段与危险操作，但不能反向决定公共页面结构。
- 危险操作必须保持权限检查、确认、状态转换和审计边界。

## 2. 信息架构

```text
公共空间
  首页：最近公开作品、最近原创、关于本站
  作品：搜索、筛选、分类浏览
  作品详情：简介、截图、在线游玩、下载、游玩统计、讨论与收藏
  讨论：最新主题、精品、多 TAG 筛选、帖子流与楼中楼
  辅助索引：作者、角色、标签、目录
  资源：工具介绍、软件下载、站外参考网站

账户空间
  我的账户、提醒、我的上传、上传权限状态、最近游玩、我的评论、我的讨论和收藏

上传空间
  新建作品、已有作品的新版本、当前页进度、source-ready 草稿恢复

管理空间
  内容、讨论与举报、讨论 TAG、归档版本、上传任务、用户、审计、维护
```

“最近更新”只能表示真实的新版本或新归档。没有对应数据时使用“最近加入”“热门下载”等可由现有数据解释的分区，不用文案伪装推荐、讨论、收藏或历史能力已经存在。

## 3. 产品规则

- 一个事实只有一个生产来源；UI、标签映射和文档不分别维护同一规则。
- 公共玩家路径、上传、管理和在线游玩按各自任务组织，不为视觉统一引入共享业务抽象。
- 只保留有生产消费者、外部契约或数据安全职责的复杂度。
- 行为变化必须说明影响范围和验证路径；废弃内部模型直接删除，不保留兼容层。
- 不把旧截图、已完成计划或部署记录作为当前产品指令。

## 4. 非目标

- 未登录 HERO、品牌宣传页或另一套首页。
- 在普通用户页面解释 Work、ArchiveVersion、manifest、D1 或 R2 关系。
- 用户画像、协同过滤、复杂推荐事件、评分系统和作品／作者／角色短评论通知。
- 匿名评论、Markdown、HTML、附件、@通知、评论表情反应和反垃圾服务。
- 把作者、角色、标签和目录做成首页平级功能墙。
- 把一次上传扩展成跨会话长期任务中心。
- 为视觉效果新增泛型 UI 抽象或依赖。

## 5. 必须保留的能力

- Work / ArchiveVersion 边界及作品关系。
- manifest、SHA-256、blob、core pack、白名单与引用校验。
- import job、preflight、单次 commit 和失败后的显式重试。
- EasyRPG 本地安装、缓存与存档隔离。
- 认证、权限、审计、GC 和危险操作保护。

## 6. 变更验收

- 测试分层遵循根目录 `AGENTS.md`，只运行与改动直接相关的最小检查。
- 人工界面验收只在任务明确包含时执行；届时检查受影响视口的主任务路径、长文本换行、焦点、溢出和控制台错误。
- 验证入口仍可发现，且未把管理或归档内部信息推回公共首屏。
