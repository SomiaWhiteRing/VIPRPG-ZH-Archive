# 时间线

时间线将成功的业务操作记录为可阅读的活动，复用 D1、现有鉴权、内容可见性和 React Router 页面。它不是管理审计、通知收件箱，也不增加游戏状态模型或新的 Cloudflare 服务。

## 产品语义

- 默认在顶栏、公开个人主页和个人设置提供「时间线」入口。时间线设置页的「将时间线设为主页」位于「开启时间线」下方，仅在时间线开启时显示，默认关闭并随时间线设置一并保存；开启后 `/` 按默认范围读取时间线，顶栏用「探索」替换「时间线」，`/explore` 展示原主页。下方的「默认显示」可选择好友或全站时间线，默认好友，保存到账号，同时用于 `/timeline` 和主页时间线。关闭时间线时隐藏这些选项并保留已保存的偏好；记录开关和主页隐私仍按原有规则生效。未登录或关闭主页偏好时 `/` 仍展示原主页。
- 动态包含收藏、目录、主楼评论、发帖、上传、初次游玩、吐槽、加入、改名。类型筛选仅提供前七项，加入和改名只在「全部」中展示。不记录喜爱展柜变化、评论楼中楼、讨论回帖或楼中楼，也不将评论／讨论编辑记录为新动态。
- 只记录新增性质的内容：新收藏、创建目录、发表主楼评论、发布讨论、上传新作品或新归档版本、初次游玩和发表吐槽。取消收藏、修改收藏备注或标签、修改／删除目录，以及目录条目的添加、修改、移除等操作不产生动态；历史中的这些活动也不再展示。
- 用户总开关默认开启，从启用时间线后开始记录；不自动导入旧操作。旧账号迁移时，已关闭全部七项旧主页隐私的账号保留关闭状态。
- 关闭总开关立即停止新的业务动态记录，保留已有历史；重新开启后继续记录，关闭期间的业务操作不补记。加入和改名始终记录，不受总开关、分类或 `timeline.use` 控制。关闭时设置页隐藏分类等其他选项，保留总开关和保存按钮，已选分类不会丢失。
- 六项业务分类开关只控制后续业务记录，新账号注册和旧账号迁移时默认全部勾选，包括评论与发帖。吐槽没有独立分类开关，只受时间线总开关与发布权限控制，仍可作为动态类别筛选。旧系统没有吐槽配置，不需要额外转换。`0035_timeline_defaults.sql` 修正已应用 `0034` 的初始配置；已关闭全部七项旧主页分区的账号和注销账号仍保留关闭业务记录的状态。时间线没有单独的隐藏选项，个人主页与时间线入口始终可访问；业务活动继续遵守相应主页分区及来源隐私，吐槽与回复检查作者当前状态及删除状态。
- 吐槽支持文字、现有表情库和配图，不支持 @ 提及；文字中的普通 @ 不触发链接或通知。不强制归属作品或讨论主题；发布后不可编辑，具有删除权限的作者可撤下，具有独立时间线审核权限的管理者可移除，并记录私有审核日志。删除后不展示原动态、删除占位或删除活动记录。
- 时间线吐槽及其回复不计入「超展开」的活动列表、累计计数或最近活跃时间。「超展开」只读取讨论主题，以及作品、作者、角色页面的评论；这些来源在时间线中的派生活动不会重复计入。
- 隐藏或删除来源内容后，不从时间线复制出的历史正文泄露内容。
- 不记录身份凭证、账户安全、权限审批或管理审计等私密行为。
- 本人可以删除除加入、改名以外的自己的所有动态，完整个人时间线、主页概览和其他时间线列表均提供对应入口。删除吐槽会清除正文，移除其他动态只影响时间线记录，不修改原来的收藏、目录、评论、讨论、上传或游玩记录；操作前统一提示「确认删除这条时间线？」，不显示附注，确认按钮为「删除」。

旧隐私表单不能重新隐藏时间线，其遗留的 `showTimeline` 字段被忽略。时间线上线前的表单保留未展示的好友与好友提醒设置，新表单为好友复选框提交显式关闭值。注销账号保留资料页及加入／改名记录，不提供好友操作或吐槽互动入口。

## 权限

权限业务对象目录新增「社区管理 > 时间线」，每项可独立授予角色或对账号封禁，不借用讨论版权限：

- `timeline.use`：开启与记录时间线；公开浏览不需此权限。撤销后停止新记录，已有记录仍遵守隐私，用户仍能关闭总开关。
- `timeline.status.create`：发布独立吐槽，还需 `timeline.use` 和已开启时间线总开关。
- `timeline.status.delete_own`：删除自己的吐槽并清除正文，不依赖总开关。
- `timeline.event.delete_own`：移除自己的其他活动动态，不修改业务源内容。
- `timeline.status.moderate_any`：移除任意用户的吐槽并审计。
- `timeline.event.moderate_any`：移除任意用户的其他活动动态并审计。
- `timeline.follow.create`：关注其他活跃用户，不依赖时间线总开关或 `timeline.use`。
- `timeline.follow.delete_own`：取消本人发起的关注，不依赖新增关注权限。
- `timeline.status.like`：点赞／取消本人点赞。
- `timeline.reply.create`：回复公开吐槽。
- `timeline.reply.delete_own`：删除本人回复并清除正文。
- `timeline.reply.moderate_any`：删除任意回复并记录私有审核日志。

点赞与回复不依赖自己的时间线总开关，也不借用论坛权限。

基础用户角色默认获得四项本人时间线权限、两项关注权限、点赞与本人回复的三项权限；管理员和超级管理员额外获得三项审核权限。自定义角色按显式配置授权，账号权限封禁优先于所有角色；不提供编辑或恢复删除内容的能力。前端按相同能力显示按钮，服务端与数据库更新条件仍单独校验权限。权限不足只跳过派生活动，不阻断原有收藏、评论、讨论、上传和首玩资格消费；权限恢复不补录。

## 单向好友与好友动态

个人主页使用「加为好友／解除好友」；本人已添加该用户时，在名称与 UID 右侧显示橘色语义样式 `text-accent` 的「/是我的好友」，不在头像附近展示关注／粉丝人数。桌面概览在收藏、游玩、目录、评论、讨论或展柜等内容分区开启时使用双栏，右栏最多展示 15 位好友的头像和昵称；这些分区全部隐藏时，时间线改占主栏并恢复原单列宽度，好友概览放在其下；窄屏也直接展示主栏时间线。双栏模式窄屏只提供导航入口，不展示右栏概览。好友概览空名单保留标题和「更多」入口，概览与完整好友列表均不显示空列表提示。隐私页的「在个人主页展示好友」默认开启，关闭后不读取或展示概览、隐藏导航入口，两个方向的完整列表页面和列表 API 均返回 404；不改变好友关系、关系状态、提醒或好友时间线。完整列表包含本人添加的好友及「谁把你／TA 加为好友」两个方向。底层沿用唯一的 `user_follows` 单向关系和现有 API，禁止添加自己；对方无需批准，回加才形成两个方向的关系。停用、注销账号不出现在公开名单中；解除好友前使用统一确认框询问「要将xxx移出好友列表吗」，确认后只删除本人发起的一条关系。

实际新建关系时，在同一 D1 batch 中向对方写入好友提醒：「请求与你成为好友」；若对方已经添加自己，则发送「通过了你的好友请求」，并将本人收到的该用户添加提醒标为已读。关系写入无变化不生成提醒；同一方向、同一种类的未读提醒去重，读过后取消再添加可产生新的提醒。收到请求时提供「同意／忽略」，同意沿用回加流程；忽略只写个人已读状态，不删除对方的关系，也不发送拒绝回执；解除好友不发送提醒，不删除历史提醒。不补发既有关系的通知，也不把添加好友记录为时间线活动。好友提醒复用 `inbox_items` 的 `system_notice` 与 `metadata_json.friend=added|returned`，在提醒页单独归入「好友」。

隐私页提供「接收他人的好友提醒」，默认开启并随隐私设置保存。关闭时，同一关系写入批次读取收件人的当前设置，跳过新添加提醒和回加回执；关系仍正常建立，双方的关系状态、好友列表和时间线不受影响。已有提醒继续保留，重新开启不补发关闭期间的提醒。此项与「在个人主页展示好友」独立。

时间线的「好友动态」包含本人及本人添加的好友当前可公开的历史，不要求互相添加，也不从添加时刻截断历史。它使用同一份事件记录和同一套作者、主页分区及来源隐私过滤，在分页 LIMIT 前筛选好友；不复制事件，不生成添加好友的时间线活动。关闭本人时间线只停止记录新动态，不妨碍阅读本人或好友的公开历史。

全站时间线页面未指定范围时，登录用户按已保存的默认范围读取好友或全站动态，未登录用户默认读取全站动态且不显示范围切换按钮；显式范围参数继续生效。切换、类别筛选和分页链接明确携带当前范围，页面内切换不修改账号的默认范围。个人主页时间线只显示该用户的公开信息及分页，允许展开阅读回复；不显示发布框、类别工具栏、设置、刷新、点赞或回复发布。本人访问时，除加入、改名以外的动态按服务端删除能力显示删除／移除入口；访问他人的个人主页不显示删除入口。时间线入口始终展示，业务内容继续遵守相应来源分区的隐私设置。

切换时间线范围或类型会回到最新页。关注关系增删时，数据库触发器原子更新关注者的 `following_revision`，重复请求不改变版本。关注流游标绑定账号、版本、类型及时间／ID 边界；关系变化后 API 返回 `timeline_cursor_changed`，页面移除旧游标并回到最新。关注列表按关系时间和用户 ID 游标分页，出站与入站方向均有索引。

接口：`PUT /api/users/:userId/follow` 关注，`DELETE` 取消；同路径 `GET` 读取人数与本人状态。`GET /api/users/:userId/follows?view=following|followers` 读取公开列表；`GET /api/timeline?view=following` 读取当前账号的关注流。关注流和「我的时间线」需要登录，不能指定其他账号的私人阅读范围；响应均为 `private, no-store`。

## 吐槽互动

动态底部显示相邻的「点赞」与「回复」，有互动时显示人数，不显示零计数。回复默认收起，点击后才查询并展开，使用现有楼中楼样式；回复编辑器共用普通评论的「回复某人／取消」布局和底部工具栏，表情与配图在左，「发布回复」在右，支持 Ctrl+Enter 提交，取消保留草稿。回复仅一层，支持文字、表情和配图，不支持提及。回复与点赞不生成时间线事件或通知。

吐槽和回复沿用评论的配图操作：选择、粘贴或拖入 PNG、JPEG、WebP、GIF，最多 10 张，每张非空且不超过 2 MiB，使用同一图片处理器。发布前展示可移除的预览；上传失败保留文件与上传标识，重试读取同一上传记录。正文仍需 1–500 字。列表复用评论图片组件：单图保留比例，多图展示前三张缩略图和剩余数量，点击使用同一大图查看器。

配图复用 `comment_images`、图片 API 与不可变 R2 对象，迁移新增吐槽／回复归属和索引，图片只可归属一条内容。发布批次校验当前账号、图片状态和未使用归属，原子绑定顺序；提交指纹包含配图顺序，重复提交不重复关联。每次图片读取检查吐槽作者的账号和删除状态，回复还检查回复者及父吐槽；作者停用或内容删除后立即停止公开图片读取。删除内容的配图进入现有七天回收候选，临时隐藏主页不触发回收。

点赞以吐槽和当前账号组成唯一键，PUT／DELETE 幂等。回复绑定当前账号、吐槽和请求标识，重复发布不新增回复，标识内容变更返回冲突。回复按 ID 正序游标分页，每页 30 条；隐藏或删除回复不计入人数，停用作者不公开。读取、点赞与回复均检查吐槽作者当前状态、吐槽隐藏状态；停止记录不影响已有吐槽互动，作者停用后回复接口不可读取，恢复活跃后可读取未删除内容。

接口：`PUT|DELETE /api/timeline/:id/like`、`GET|POST /api/timeline/:id/replies`、`DELETE /api/timeline/replies/:replyId`。发布吐槽每分钟最多 5 次，回复每分钟最多 10 次；删除后的内容仍计入当前限流窗口，相同标识和内容的重试不新增记录；长度最多 500 个字符，表情按一个字符计。`0036_timeline_account_history.sql` 为包括已删除吐槽的限流查询增加独立索引。

## 信息流展示

- PC 端的全站时间线和公开个人主页概览复用 `PageContainer`，最大宽度 1280px；个人主页的单栏分区恢复原来的 `max-w-5xl`（1024px）容器及 `px-4 sm:px-6` 水平留白。`DetailPageLayout` 在超过 980px 时采用主内容加 300px 侧栏。个人主页使用原有头像／资料头部和横向导航。概览首页在桌面且至少一个内容分区开启时展示双栏，收藏、游玩历史、目录、评论、讨论、完整时间线及好友列表等分区均为单栏，不查询或展示概览右栏数据；这些分区的导航保留时间线入口，好友入口遵守好友隐私。概览右栏容器与主内容等高，内部内容按自然高度排列；该规则不延长时间线卡片的边框或背景。右栏展示该用户最新 5 条公开时间线及好友概览。时间线直接复用个人时间线的信息流组件，保留日期分组、正文、作品预览及时间戳；侧栏回复数只显示为静态信息，不提供回复展开入口或加载回复列表；侧栏动态不显示作者头像或名称，也不保留头像占位，正文占用完整内容宽度。吐槽不显示「发表了吐槽」，也不保留作者行的空白。右栏不显示分页，完整列表通过「更多」链接进入。时间线与好友导航按钮不按单双栏或桌面／移动端隐藏，时间线入口始终展示；概览右栏同时保留「更多」链接，窄屏隐藏两个右栏概览。全站时间线的右栏复用个人入口与首页讨论区，不展示好友名单；窄屏隐藏辅助栏，保留原有发布、筛选和动态流程。作为首页时复用同一时间线查询和布局，范围、类别与分页链接保留在 `/`，全站范围显式携带 `view=all`。作品预览按所在主栏的实际容器宽度切换两列／四列，不按浏览器宽度强行挤入四列。

- 页面不重复显示「时间线」标题；类别位于输入区下方。范围使用一个按钮，点击后切换范围和颜色并保留类别筛选。桌面上按钮显示当前的「全站时间线」或「关注时间线」，位于类别左侧，各控件等高并垂直居中；移动端隐藏设置与刷新，范围按钮改为圆形的地球／用户图标，位于发布框字数计数左侧；没有发布框时放在类别左侧。移动端类别只保留一行，不换行，超出宽度时横向滚动。「我的时间线」由个人主页的时间线入口承接。类别统一为「全部、收藏、目录、评论、发帖、上传、游玩、吐槽」；加入和改名不提供独立筛选，仅在「全部」中展示。缩短文案不改变主楼评论与初次游玩的记录规则。
- 发布和回复草稿使用与讨论版相同的 IndexedDB 自动保存方式，按账号、草稿类型和吐槽编号隔离；发布草稿跨时间线范围、类别和分页共用。每次输入或配图变动立即排队保存，保存原始文件与已上传资料，预览 URL 由编辑器重建；刷新或重新打开发布框时恢复，不增加离开拦截、放弃确认或手动清空操作。关闭、切换和失败均保留草稿；服务端发布成功后清空对应输入、配图和本地缓存，之后刷新列表失败也不恢复已提交草稿。清理缓存时核对提交标识，保护离开后新写的另一份草稿。个人主页只展示信息，不加载发布或回复草稿。
- 全站与个人时间线使用同一份信息流，按站点 UTC+08:00 日期分组，今天与昨天使用相对日期；分组不会改变原始事件顺序或分页游标。
- 动态（包括加入与改名）和吐槽回复的时间每秒更新，依次显示「X秒前、X分钟X秒前、X小时X分钟前、X天X小时前、X月X天前、X年X月前」；保留相邻第二单位的零值，例如「1分钟0秒前」。日历时长由 date-fns 及其时区配套库计算，统一采用站点时区，月份不按固定天数折算。悬停展示准确的「YYYY-MM-DD HH:mm:ss」，不附带时区提示；服务端渲染与首次客户端渲染共用根加载器的时间，之后切换为实时更新。
- 动态正文实际高度超过十行文字高度时默认折叠，可展开、收起；按当前行高和自动换行后的高度判断，容器宽度、字体或表情布局变化时重新计算。全站、个人时间线及主页侧栏统一使用此规则，配图、作品预览和互动区不纳入折叠。
- 未登录时顶部只显示类别，不显示登录提示、范围、设置或刷新。吐槽只显示作者和正文，不显示「发表了吐槽」。评论主句为「AA 在 BB 下发表了评论」，游玩动作为「初次游玩了」；其他动态将用户、动作与来源名称连成主句。收藏备注与评论摘要居中呈现，时间和管理操作位于底部。简单活动缩小间距，同一天连续出现的同一用户简单活动省略重复头像，但保留用户名和主页链接。
- 收藏、初次游玩、上传、作品评论和带作品引用的目录活动显示当前公开作品的封面、名称、原名、类型与引擎。简单活动使用紧凑预览；有正文或上传活动使用较大的预览，复用现有封面组件。
- 目录类只显示创建目录的活动，链接指向该目录；修改目录与增删改目录条目不产生动态。
- 评论摘要显示文字、表情和当前评论配图，与吐槽共用表情和图片展示；超过 180 个字符时显示省略号，表情按一个字符计，截断不拆开表情标记。发帖只显示主题信息，不读取或展示正文。评论与发帖可通过主句中的来源名称进入原页面，底部不再重复显示「参与讨论／查看讨论／查看评论」入口，继续在来源页面互动，不建立另一份评论系统。
- 作品预览与来源计数只从现有公开投影读取，不突破个人主页隐私或来源可见性；除加入记录外不回填业务历史、自动发帖、通知或共享样式。

## 账号永久记录

加入记录显示「加入了VIPRPG.org」；改名显示「由 **旧名称** 改名为 **新名称**」，保留变更当时的名称。两类记录只显示文字和时间，全站加入记录另显示账号名称作为文字；不显示头像、来源、图片、互动或删除操作。

`0036_timeline_account_history.sql` 为所有用户（包括关闭记录、停用及注销账号）按 `users.created_at` 补齐唯一的加入记录，新注册账号同步生成。之后真实显示名变更与改名记录在同一事务提交；同名保存和注销时的匿名化不生成改名记录。不会伪造迁移前缺乏时间线记录的历史改名。

两类记录由数据库约束永久保留，作者和管理员均不能修改、隐藏或删除。停用期间不公开；注销后资料页和时间线仍保留这两类记录，其余业务动态遵守原有账号状态规则。

## 初次游玩

初次游玩与最近游玩共用 `/api/works/:workId/played` 和 `recordWorkPlayed`：网页在线启动成功、点击 ZIP 下载、点击外链下载页，以及 Android 安装完成均可触发。仅打开加载页、安装网页资源、启动失败、Android 本地启动不触发站点上报。首次标记、时间线动态和最近游玩时间在同一 D1 batch 中提交；公共计数故障仍允许更新个人历史和首次记录。

每个账号和作品最多记录一次，跨设备、版本和重复请求去重；重复上报只刷新最近游玩时间，不改变首次时间。关闭总开关、游玩分类或记录权限时，有效登录账号的统计上报仍消耗首次资格，但不生成动态；之后重新开启也不补记。匿名上报只参与公共计数，不写个人历史或首玩标记。

已有 `last_played_at` 无法还原首次时间。迁移建立的历史抑制标记继续保留；切换路径前已有最近游玩历史但缺少首次标记的账号／作品，在下一次上报时只补齐空时间的历史标记，不生成首玩动态。删除首玩动态不重置首次资格。

新客户端只发送既有最近游玩的统计请求，不另发首玩请求；Android 安装完成通过原生任务的现有上报接入，离线启动只更新设备本地最近游玩。记录是在线、可认证的尽力上报，不将离线请求排队补发。已存在的 `/api/works/:workId/first-play` 保留给现有客户端，内部也调用同一 `recordWorkPlayed`，不保留独立的首玩处理路径。

## 数据和一致性

增量迁移增加时间线与首玩标记，不修改已发布迁移。业务源行触发器或同批次事件语句读取数据库中的最新用户记录开关，和业务变更原子提交；不依赖 `waitUntil` 或客户端自行声明操作者与事件类型。

列表使用稳定游标和按时间／用户索引；每次查询重新检查作者状态、相应主页分区、来源和父级对象的公开状态。响应不进入共享 CDN 缓存。总开关与全部分类开关只参与后续记录，不用于历史展示过滤。

评论和讨论按事件引用的来源 ID 查询当前公开视图，避免先物化全站评论及论坛数据。公开帖子已校验主题及其作者状态，主题元数据再按该帖所属主题 ID 读取。可见性过滤位于 `LIMIT` 之前，保留 `limit + 1` 和 `(created_at,id)` 稳定游标；图片与表情只装配本页结果。

吐槽限流使用 `timeline_status_user_recent` 索引统计用户最近一分钟的吐槽，包括已隐藏或删除的记录，删除不能释放限流额度。

事件保存来源引用；评论、讨论等正文从当前公开来源装配。吐槽和回复由服务端校验并拆分为安全文字与表情片段；表情引用在内容写入的同一 D1 batch 中登记。通知系统保持原有职责。

## 验收

持久契约入口为 `npm run test:timeline`，见[维护与回归手册](./maintenance-regression.md)。契约在独立内存 SQLite 中应用真实迁移，调用实际业务函数和隐私／好友接口，仅适配 D1、R2 和计数传输。覆盖：

- 迁移与注册默认值、旧隐私表单保留好友设置且不能隐藏时间线、记录开关和分类、权限与当前公开来源、首玩去重及作品合并。
- 注销主页资料读取、好友关系和通知的幂等及原子回滚、好友列表隐私、关注范围认证与关系变更后的游标失效。
- 点赞与回复去重、权限撤销和审核删除、回复分页、删除后的限流、配图顺序和独占归属、绑定失败回滚、当前隐私读取及七天回收边界。
- 按注册时间补齐所有账号的加入记录、关闭记录后的改名原子保存、永久记录不可修改／删除／互动，以及迁移完整保留旧事件、互动、表情与配图归属。

PR 验证和 Deploy 候选检查均运行该契约；候选失败阻止预生产或正式发布。固定开发种子同步增量迁移及账本，不用种子代替契约夹具。

人工 UI 验收获授权后使用隔离本地 D1/R2 和开发账号检查启停、发布、回复、配图与窄屏导航。

本地浏览器测试不等于 Android 实机验收；PR 中分别记录实际执行的检查、未执行部分和限制。不在正式站创建测试账号或写入测试内容。
