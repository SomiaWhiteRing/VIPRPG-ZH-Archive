# 角色分类

公开页面为 `/characters`，后台分类编辑为 `/admin/characters/index`；角色资料编辑使用已有的 `/admin/characters/[characterId]`。

## 数据模型

`characters` 是角色的唯一身份和资料来源。不存在同名的目录条目、占位入口或主角色绑定。

- `character_categories`：分类名称、来源原名、来源链接、父分类及同级顺序。只有分类可以包含子分类。
- `character_category_memberships`：角色直接属于哪些分类、分类内顺序，以及当前分类选用的中文显示名 `display_name` 和日文显示名 `original_name`。主键为 `(category_id, character_id)`，同一角色不能因为名字不同而在同一分类重复出现；没有独立目录身份。
- `character_sources`：角色自己的来源链接及顺序。同一来源页面可以分别用于多位角色，同一角色可以保存多个来源。

角色的默认名称、可选别名、头像、说明和作品数来自角色资料。分类关系选定显示名称，公开列表只显示这组中日文名字，不展示或展开全部别名。角色可以属于多个明确分类；公开数量按角色 ID 去重。家族、种族等合集作为分类，例如「王国军 → RTP 以外 → 亚历克斯的家人」。具名多人共用来源页拆为各自的角色，直接列在所属分类下。

选择默认中文名或日文名时，对应字段保存为 `NULL`，读取时使用角色当前默认名；选择别名时保存该名字，只影响这一条分类归属。两种语言分别选择，候选限于该角色对应语言的默认名和别名，不根据别名数组顺序猜测翻译配对。已保存的明确名字不依赖别名行 ID，因此后续整理别名不会清空历史选择；编辑时也允许保留该归属已选的名字。例如同一角色在魔王军显示「布鲁／ブロウ」，在王国军的 2003 队伍显示「巴恩斯／バーンズ」。

分类只向分类引用父节点，角色直接向分类建立归属，因此结构中没有角色从属于角色、更不存在角色从属于自身的关系。删掉分类归属不会删除角色或来源。含成员的分类不可删除；移动分类必须避免自身及后代。角色合并迁移所有分类归属和来源，并保留合并前的显示名字；重叠分类保留目标角色的选择，通过联合主键去重。

## 后台操作

左侧显示分类和真实角色，名字与公开列表保持一致。右侧选中分类时编辑名称、来源和父分类，选中角色时编辑所属分类、中文显示名、日文显示名与角色来源，并可进入角色资料页编辑默认名称、头像、别名和说明。角色资料页也可直接返回该角色的分类编辑。修改角色默认名会更新使用默认名的归属，明确选用别名的归属保持自己的名字。

分类支持创建子分类、创建真实角色、搜索并批量加入已有角色，以及混合排列子分类和角色。批量选中后，每位角色都可分别选择使用的中文名和日文名，再加入分类；保存接口验证名字属于该角色，不能指定另一角色的名字。创建角色复用现有身份校验，随后可从角色资料页进入分类编辑。上移、下移调整同级顺序，更换分类会保留所选名字并排在目标分类末尾。若角色已在目标分类，直接移除当前归属即可。

没有分类的角色在后台单独列出，并可搜索和加入分类。未分类角色不自动进入公开列表。归类时优先采用已有一级分类下的「其他」，无适用分类时才使用独立一级「其他」。不在运行时推测阵营或重新匹配名称。

后台按操作独立授权，页面允许持有相应写权限或 `character.admin.read` 的用户进入；只读权限不授予写入能力。写接口逐操作校验权限，并复用同源和有效登录验证。

| 操作 | 权限 |
| --- | --- |
| 角色管理只读 | `character.admin.read` |
| 创建角色 | `character.create` |
| 修改名称和别名 | `character.metadata.update_any` |
| 合并重复角色（含别名冲突确认合并） | `character.merge_any` |
| 维护已有脸图绑定与默认头像 | `character.portrait.manage_any` |
| 上传、公开并绑定新脸图 | `character.portrait.upload` |
| 创建／修改／删除空分类 | `character_category.create` / `character_category.update` / `character_category.delete` |
| 添加／修改或移动／移除分类归属 | `character_membership.create` / `character_membership.update` / `character_membership.delete` |
| 混合排列分类和角色 | `character_index.reorder` |
| 编辑角色来源链接 | `character.sources.update_any` |

角色来源单独保存，不要求角色已有分类，也不会连带修改分类归属。创建角色命中已有身份时只返回该角色，不再隐式添加中文别名。资料表单仅提交有权修改的区块；服务端在任何写入之前拒绝越权字段，合并两个方向均校验合并权限。脸图上传权限允许上传即公开、绑定，其他绑定和默认头像仍由维护权限控制。

作品提交中的登场名称仅写入 `work_characters.display_name`，不自动写入角色全局别名。随作品新建角色时，`primaryName` 用于初始化角色中文名，`displayName` 用于本作登场名称；两者初始相同，修改登场名称不会修改角色中文名。命中已有角色时保存作品关系与脸图绑定。作品提交成功时，本次选中的本人上传脸图直接进入角色公开素材库，包括作为头像来源的整张脸图；公开状态与作品关系在同一事务中保存，单独上传文件或取消选择不会公开素材。自己的已入库脸图可继续绑定其他角色，已拒绝素材仍不能使用。本作头像选择不会覆盖角色默认头像。

「选择本作头像」复用表情库的 `FaceSheetGrid`：桌面三列、窄屏两列，直接在整张脸图中选择格子，旁侧或底部显示 96×96 头像预览，两侧不显示脸图名称。头像选择、沿用默认头像及上传素材的添加和移除都先暂存，点击「确定」后统一应用并关闭弹窗；直接关闭或按 Escape 不更改原值。重新打开时定位已确认头像所在的脸图。已有脸图沿用角色素材顺序，新上传素材在前，不改变表情收藏。

[统一初始化 SQL](../migrations/0001_init_archive_schema.sql) 直接定义 `character.admin.read` 和内置管理员的细分权限；自定义角色的写权限需在权限矩阵明确授予。维基人模板包含创建与资料、脸图、分类和归属整理能力，但不包含角色合并或分类删除。角色合并本身授权迁移该角色的关联数据，不要求分别获取每项关联的编辑权限。作品发布与作品资料维护中的登场角色登记沿用对应作品权限，包含新角色登记、显示名及作品脸图提交；上表控制独立角色管理后台。角色评论使用全站 `comment.manage_any`，公开阅读及已登录用户的本人评论操作不需要后台权限。

涉及多行的保存使用 D1 原子批次，来源仅接受 HTTP(S) URL；外键和联合主键保持角色、分类和来源完整。分类移动在写入时检查循环。没有双写或旧模型回退路径。

## 初始化与显式导入

[统一初始化 SQL](../migrations/0001_init_archive_schema.sql) 建立当前分类、归属与来源结构。日常开发通过[固定种子](./local-demo-data.md)恢复已审核的角色 ID、分类、来源和素材绑定。

`npm run db:local:character-index` 是显式整理来源清单的工具，只写本地 D1。运行前数据库必须具有当前 schema，并已包含清单引用的基础角色；仅运行 migration 得到的空库不能替代基础角色数据。它不是完整开发环境初始化入口。

`data/character-classification-bootstrap.json` 包含分类、角色归属、角色来源及明确需要新增的角色，不参与页面请求。首次导入作为一个事务写入；已有分类时保留后台编辑，只补建清单中仍缺失的角色及这些新角色的归属和来源。不会重新覆盖已有角色的名字、归属或顺序。缺失基础角色或身份歧义会中止导入。

每条初始化归属都包含可空的 `displayName` 和 `originalName`，含义与上面的分类显示名规则相同。一次性分类转换、补全和名称选择的范围见[角色数据整理记录](./archive/2026-09-character-data.md)。

## 来源与身份整理

来源清单保留已核实的身份、合集成员和「其他」归属，不与线上 Wiki 实时同步。补全按来源页中的明确角色章节建立成员与素材归属，不把“复数素材”“未分类”或服装差分当成角色。同名但不同身份的角色使用有来源上下文的原名消歧，例如 RTP 树人与使用「トレント」别名的法尔子分别保留。

分类采集覆盖率、角色素材覆盖率和未确认拼图分别统计；“已建角色都有素材”不能证明分类树完整。来源采集见[素材采集](./character-material-collection.md)，游戏资料补充候选见[角色历史游戏分析](./research/character-history-game-analysis.md)。

RTP2003 怪物中的「死灵法师／ネクロマンサー」与无所属人类中的「涅克罗／ネクロ（ネクロさん）」是独立角色。前者的来源和素材限定为 RTP2003 怪物页的「ネクロマンサー」章节，后者保留「ネクロさん」独立页面；不把「死灵法师」「ネクロマンサー」登记为涅克罗的别名。

「个性鲜明的士兵团」包括士兵、女兵士、士兵 X、士兵 Y。源页以普通文字而非链接标注 X/Y，不能仅按页面内链接提取成员。逐图归属区分女兵士与 X/Y 的专属素材，共用图保留多人绑定；未命名换色和表情差分不作为独立角色。

## 前台浏览

角色索引按右侧内容宽度显示三列、两列或单列卡片，同一行只包含同分类下连续排列的角色。卡片显示头像、当前分类选定的中日文名字、简介摘要、公开作品数、公开评论数和可用素材数；索引不展示来源链接，角色详情保留来源资料。评论数包含公开回复，排除隐藏根评论下的回复及不可见作者；素材数与详情素材区使用相同的审核和文件可用条件。

索引右侧的分类标题按树深度区分：一级使用大标题，二级使用强调竖线和中号标题，三级及以下使用进一步缩进的小标题。滚动时，当前分类及祖先标题紧贴站点导航底部，按实际高度逐层吸顶，离开各自分类范围后退出。导航高度通过尺寸观察动态测量，吸顶和目录跳转共用该偏移，不使用固定像素间距。分类标题保持挂载，角色条目继续虚拟化；左侧目录跳转为祖先标题预留空间。

二级及以下分类以连续竖线贯穿标题和组内卡片，组尾使用短横线收口并留白；卡片随所属层级缩进，移动端缩小缩进。子分类后重新出现上级直属角色时，在这段角色前显示「其他 {上级分类名}角色」提示。提示和收口仅为展示行，按当前浏览树生成，不新增分类或改变角色归属；收口行不参与目录跳转，分类吸顶范围包含自身收口行。

角色详情位于 `/characters/[id]`，角色索引中的名字、作品页的角色与搜索结果均可进入。角色身份本身公开，没有公开作品也可查看详情及参与评论。

详情沿用作者页的容器与作品列表样式，桌面左侧为头像、中日文名、别名、所属分类、简介与来源，右侧通过「登场作品／素材」标签切换内容；移动端资料排在内容上方。登场作品仅包含已发布作品，同一作品的多条角色记录合并展示，含剧透的登场信息默认折叠。素材区的分类、布局、资料栏折叠、灯箱和下载规则统一见[角色素材库](./character-material-library.md)。

评论区位于标签内容下方，切换标签保留评论状态。角色评论复用现有评论、回复、点赞、删除、表情和分页体系；[统一初始化 SQL](../migrations/0001_init_archive_schema.sql) 定义评论的角色目标，约束每条评论只能属于作品、作者、角色三者之一，回复必须保持相同目标。个人评论列表链接到角色详情；角色合并同时迁移评论，保留楼层关系和点赞。

前台按数据库分类、归属和顺序生成展示树，不再保存另一套角色目录。展示行标识仅用于虚拟列表定位，由分类 ID 和角色 ID 计算，不构成持久内容实体。

桌面目录吸顶并独立滚动，正文跟随窗口滚动并按需挂载角色行。移动端在分类抽屉中选择，关闭抽屉后定位。小型筛选器位于左侧目录顶部，移动端位于分类抽屉内，仅包含输入框和搜索按钮。点击搜索或按回车后在当前页面应用，不跳转、不改变 URL；搜索只影响左侧目录，右侧完整列表保持不变。搜索支持分类路径、中文名、日文名和别名，按 NFKC 规范化，多词同时匹配；目录展开有匹配角色的分类及祖先，无结果分支的所有层级递归折叠，保留可见的最高层分类。输入非空文字期间不更新结果，清空输入立即恢复完整目录，保留清空时所有层级的展开、折叠状态。重复提交相同搜索也会重新应用目录的展开、折叠状态；桌面与移动端共用目录状态。
