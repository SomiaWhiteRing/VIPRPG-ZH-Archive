# 站内讨论区产品与界面设计

状态：现行产品与界面契约

本文定义站内讨论区首版的信息架构、布局、交互、搜索、内容状态和授权边界。产品定位见[产品方向](./product-direction-plan.md)，授权原则见[认证与权限基线](./authentication-authorization-baseline-plan.md)，权限目录与系统角色授权由 [PERMISSIONS / SYSTEM_ROLE_PERMISSIONS](../lib/authz/permissions.ts) 发布；字段、约束、图片存储及搜索模型由[统一初始化 SQL](../migrations/0001_init_archive_schema.sql) 直接定义。

## 1. 产品定位

讨论区提供由本站自行托管、管理和备份的公共讨论空间，承载攻略、求助、考据、资源信息、制作交流和站务讨论。它不依赖第三方论坛账号或第三方内容审核结果。

讨论区采用单一公开帖子流：

- 不设置分区或板块；
- 不建立主题与 Work、Creator 或其他资料实体的关联；
- 每个主题可以使用多个由发帖者编写或从既有建议中选择的 TAG；
- 管理人员可以把公开主题标记为精品；
- 用户通过最新回复、精品和 TAG 找到内容；
- 主题、楼层回复和楼中楼进入独立的站内搜索范围。

根路径继续是作品发现首页。讨论区是一级公共导航，但不替代作品详情中的短评论。

## 2. 首版边界

### 包含

- 公开主题列表、多 TAG 筛选和精品列表；
- 发布主题、楼层回复、单级楼中楼、编辑和软删除；
- 首帖与普通楼层的图文混排，图片由本站 R2 托管；
- 帖子点赞；
- 帖子回复与点赞的站内提醒，接收对象、去重、已读和入口规则见[提醒产品与界面契约](./inbox-design.md)；
- 主题锁定、内容隐藏与恢复、加精与取消加精；
- 帖子举报和管理处理；
- 主题及回复正文搜索；
- 个人中心和公开主页的最近讨论、完整分页列表及独立隐私设置；
- 桌面端、平板和移动端完整界面；
- 复用现有账号、角色、权限、头像、自定义表情和审计边界。

### 不包含

- 分区、子版块或私密版块；
- 作品关联、推荐主题或算法信息流；
- Markdown、HTML、通用文件附件或楼中楼图片；
- 私信、群组、关注、勋章、等级或积分；
- @通知、订阅或邮件摘要；
- 实时聊天、投票、活动日历或 Wiki 帖；
- 匿名发帖、匿名回复或匿名点赞；
- 独立于本站账号体系的论坛账号或角色系统；
- 搜索联想、拼写纠错或语义搜索；
- 递归楼中楼、无限滚动和跨页面编辑器草稿。

正文中的文字支持纯文本、安全自动链接和站点自定义表情短代码；所有用户文本按纯文本转义，不接受用户 HTML。插图规则见[连续正文与插图](#连续正文与插图)。

### 外部参考边界

- [Discourse](https://github.com/discourse/discourse) 提供主题列表、帖子流和作者栏的信息层级参考；不复制商标、图标、源代码、CSS 或页面素材。
- NGA 提供标题前多个自由编写的方括号 TAG 的体验参考；本站标题与 TAG 分开保存，具体规则见第 7 节，不照搬版块和内部编码。
- 百度贴吧提供主题弹窗、底部 minibar 和单级楼中楼的交互参考；回复结构以第 5、6 节为准。

界面使用本站现有组件、颜色、字体和间距独立实现，视觉取舍见第 11 节。

## 3. 信息架构与 URL

| 入口 | 用途 |
| --- | --- |
| `/discussions` | 最新回复主题流；`view=featured` 切换精品，重复 `tag` 参数取交集 |
| `/search?scope=discussions&q=查询` | 标题与正文搜索；支持 `tag` 与 `featured=1` |
| `/discussions/{topicId}?page={page}` | 主楼页；每页 20 个位置，包括首帖和匿名占位 |
| `/discussions/{topicId}/posts/{postNumber}` | 主楼永久入口 |
| `/discussions/{topicId}/comments/{commentId}` | 楼中楼永久入口 |
| `/me/discussions` | 本人的公开发帖和回帖，按发表时间倒序分页 |
| `/users/{userId}/discussions` | 用户允许在个人主页展示的公开发帖和回帖 |
| `/admin/discussions`、`/admin/discussion-tags` | 论坛管理与 TAG 管理 |
| `/discussions/sitemap.xml` | 公开主题 sitemap 索引 |

讨论搜索位于全站 `/search?scope=discussions`，`/discussions/search` 重定向到该入口。主题列表每页最多 30 项，搜索每页最多 20 项，均以 `page` 翻页，返回精确总数，复用全站数字页码、首页／末页、上一页／下一页和输入跳页控件。主楼和楼中楼仍返回精确位置数，支持任意数字页码；无效页码按第一页，越界取最后一页。`floor` 指定展开的主楼，`commentPage` 指定楼内页，`comment` 指定聚焦评论；`from` 保留站内论坛列表返回地址。

首帖为 #1，仅在主楼第一页显示。所有主楼、评论编号包含隐藏、删除和账号禁用形成的占位。主楼页码直接由 `post_number` 计算；楼中楼页码由连续 `comment_number` 计算，均为 `ceil(number/20)`，不扫描历史位置。主题下新主楼和父楼下新评论各自连续分配序号；失败、幂等重试及冲突不得占号。

公开列表和搜索使用预渲染页面壳，论坛导航不读取身份。主题 SSR 只含标题、首帖、必要附件和简要作者，metadata 与正文共享请求内读取；其他主楼及默认预览分别通过 JSON 加载。论坛链接关闭自动预取。主楼翻页更新两个数据区域；展开或跳转楼内页只更新对应容器。公开正文不缓存，读取接口为 `no-store`。

### 个人中心、用户主页与隐私

个人中心概览和公开用户主页均提供“最近讨论”，通过“更多”进入完整列表，每页 20 条。主题首帖作为一条“发帖”记录，普通楼层标为“回帖”，楼中楼标为“楼中楼回复”；三者合并按发表时间倒序，同一时间按内容类型、记录 ID 倒序稳定排列。同一主题内的多次发帖或回复各自保留，编辑内容不改变排序时间。记录展示主题标题、正文摘要、类型和发表时间，链接使用已有主楼或楼中楼永久入口。

隐私页提供独立的“在个人主页展示讨论”开关，由 [统一初始化 SQL](../migrations/0001_init_archive_schema.sql) 定义，默认关闭。关闭后不显示公开主页概览及导航，直接访问公开讨论分栏返回不可用；公开查询也核对当前开关。本人仍可通过个人中心查看这份列表，账号注销时关闭该开关。隐私设置只控制个人主页聚合，不改变讨论版原帖的公开性。

个人中心与公开主页均只读取现有公开内容视图；隐藏、删除的主题或内容，以及被禁用账号的内容不进入列表。楼中楼是否可见继续遵守父楼规则：隐藏父楼屏蔽其楼中楼，删除父楼仍允许公开楼中楼。该列表不承担隐藏或删除内容的管理入口。

## 4. 讨论首页

### 桌面布局

页面沿用公共页面的 `w-[min(1180px,calc(100vw-2rem))]` 主容器。`lg` 及以上使用 `192px minmax(0,1fr)` 两列和 `24px` 列间距：左侧是无卡片外框的窄导航，右侧是主题列表；不增加第三栏。主列表最小宽度为零，长标题由主栏吸收，不把页面撑出视口。

```text
┌────────────────────────────── 站点页头 ──────────────────────────────┐
│ VIPRPG.org  首页  游戏库  讨论  目录  上传      搜索       用户菜单 │
└─────────────────────────────────────────────────────────────────────┘

┌──────────────┬───────────────────────────────────────────────────────┐
│ 讨论         │ 讨论                              [搜索讨论] [发主题] │
│              │ ───────────────────────────────────────────────────── │
│ ● 最新       │ [求助] 游戏启动时报错                    12  203  5分 │
│   精品       │        用户名 · 最后回复者                              │
│              │ ───────────────────────────────────────────────────── │
│ 常用 TAG     │ ★ 精品 [攻略] [汉化] 某作品完整流程        8  418  2时 │
│ 求助         │        用户名 · 最后回复者                              │
│ 攻略         │ ───────────────────────────────────────────────────── │
│ 汉化         │ [制作] [变量] 操作问题                      3   91  1天 │
│ ……           │        用户名 · 最后回复者                              │
│ 全部 TAG     │                                                       │
└──────────────┴───────────────────────────────────────────────────────┘
```

左栏只承担视图切换和 TAG 筛选：

- “最新”按维护的活动时间倒序，同一时间按主题 ID 倒序；
- “精品”按加精时间倒序，同一时间按主题 ID 倒序；
- “常用 TAG”只包含启用或已停用的 TAG，按最近 `90` 天创建且当前公开的主题使用数倒序生成；同一主题每个 TAG 只计一次，使用数相同时按 TAG ID 升序，只展示前 `10` 个；
- 点击“常用 TAG”直接切换选中状态，可多选，最多选择 `5` 个筛选项；不提供单独的 TAG 筛选按钮或选择面板；
- 当前入口使用文字、背景和 `aria-current` 同时标记，不只依赖颜色；
- 左栏在 `lg` 及以上以 `top-20` 粘滞显示，高度超过视口时自身纵向滚动，不能覆盖站点页头。

主栏使用现有紧凑 `PageHeader` 的层级：标题为“讨论”，右侧依次为“搜索讨论”和主操作“发布主题”。搜索在桌面端是带持久可访问名称的输入框，在中小屏降为图标按钮并打开搜索层。没有额外的欢迎语、功能说明卡或统计卡。

常用 TAG 在桌面侧栏保持原有纵向文字链接样式，中小屏在列表上方单行横向滚动。桌面链接使用 `aria-current` 标记已选项，视觉样式保持不变；中小屏选中项使用勾号、背景和 `aria-pressed` 标记。再次点击取消；每次切换立即更新 URL，保留最新／精品视图并回到第一页。达到五项后只能取消已有选择。已选标签单独显示移除入口，包括从链接进入但不在常用榜中的标签。搜索页只提供关键词搜索，不展示常用 TAG 或精品筛选。

### 主题列表行

主题列表采用 Discourse 式高密度行，不用独立圆角卡片。桌面行使用 `minmax(0,1fr) 72px 72px 96px` 网格，纵向内边距 `16px`，各行以一条底边分隔：

- 主信息：全部主题 TAG、精品标记、主题标题；
- 次信息：主题作者、最后回复者和必要的状态标记；
- 数值列：回复位置数、浏览数、最后活跃时间；
- 锁定主题显示“已锁定”，隐藏主题不进入公共列表；
- 标题最多显示两行，用户名称和时间不可挤压标题的最小可读宽度；
- 整行可以悬停高亮，但主题标题仍是明确的主链接。

标题、TAG、具有公开主页的作者和最后回复者分别是独立链接；已注销账户显示本站统一名称和默认头像，不链接到不可用主页。数值列不是链接。不能在整行外包一个链接，否则会破坏内部 TAG 和用户链接的点击、键盘及辅助技术语义。鼠标悬停或键盘焦点进入行内任意控件时，整行使用 `bg-primary/5` 作为同一条目的反馈。

主题行的状态与截断规则固定如下：

- TAG 在标题前依用户选定顺序排列，可以换行；标题至少保留一行完整可读宽度；
- 标题最多两行，超出使用省略，不把 TAG 或标题裁成单字碎片；主题详情中的标题不截断；
- 次信息第一位是主题作者，只有最后回复者不同于作者时才追加“最后回复：{用户名}”；
- “回复”包含所有主楼与楼中楼回复位置（含匿名占位），排除首帖；“浏览”表示主题详情在浏览器中可见展示的次数，同一次页面访问中的普通分页、楼中楼展开和重试不重复累计；允许最终一致，不由预取、服务端抓取或健康检查请求直接增加，不声称是独立访客数或能识别所有伪装浏览器的自动访问；
- “活跃”只在新回复时更新，没有回复时取主题发布时间；编辑、恢复不顶帖，隐藏、删除不回退。最后回复不可见时显示匿名占位，不回溯历史作者；
- 锁定和精品始终显示文字状态；被停用 TAG 仍显示，被隐藏 TAG 不占空白位置。

表头在数值列上显示“回复”“浏览”“活跃”。数值使用站点等宽字体和等宽数字，时间显示适合列表扫描的相对值并以 `title` 提供完整时间；主题详情直接显示完整日期时间。列表排序变化后焦点留在触发控件，结果区域通过状态文本宣布已更新。

列表使用数字页码分页。页码和筛选共同写入 URL，刷新或重新打开链接仍可前后翻页；切换“最新”“精品”或 TAG 后回到第一页。选择多个 TAG 时只显示同时包含全部所选 TAG 的主题。

### 移动布局

小屏幕隐藏左栏和“浏览”列，在标题下方提供两层紧凑筛选：

```text
讨论                         [搜索] [发主题]
[最新] [精品]                 [筛选 TAG ▾]
──────────────────────────────────────
[求助] [运行] 游戏启动时报错
用户名 · 12 回复 · 5分钟前
──────────────────────────────────────
★ 精品 [攻略] [汉化] 某作品完整流程
用户名 · 8 回复 · 2小时前
```

筛选控件保持单行可操作；已选 TAG 在下一行显示为可移除的紧凑 token，不把全部可用 TAG 铺成标签墙。主题标题、TAG 和回复数优先于浏览数与最后回复者头像。移动端主题行不显示头像、浏览数或最后回复者，只显示主题作者、回复数和活跃时间；整个列表不产生横向滚动。

### 主题头

- TAG 按用户选定的顺序独立排列在标题上方，使用辅助字号；标题本身单独作为一级标题。精品、锁定等状态位于状态区；
- 精品必须同时使用图标和“精品”文字，不能只改变标题颜色；
- 标题可以换行，不截断；
- 公开页面不把数据库 ID、内部审核原因或权限名称作为界面文案；URL、锚点和永久楼层号使用本设计规定的标识；有权操作者的管理对话框可以显示目标和管理原因字段；
- 具备加精或审核能力的用户通过主题右上角“更多”菜单执行管理动作。

### 帖子流

桌面端帖子采用 `136px minmax(0,1fr)` 的“作者栏 + 正文栏”结构，两栏间距 `24px`。作者栏显示 `40px` 头像和名称，不显示等级、积分、勋章或签名；正文栏顶部显示完整时间、编辑状态与永久楼层号。每个帖子使用上下分隔线，不包进独立卡片。正文下方只显示当前用户可执行的动作；匿名用户在回复入口位置看到登录入口。

移动端把作者信息折叠到正文上方，形成 `32px` 头像与名称的头部；楼层号、发布时间及已编辑标记集中在正文和图片之后的工具栏左侧，不在头部重复。正文保持至少 `1.7` 的行高，段落空行保留，长链接和连续字符必须换行。桌面正文最大可读宽度为 `76ch`，但楼中楼和操作栏可以占满正文列。

普通楼层固定按楼层号正序排列，首版不提供倒序或只看楼主。每个普通楼层具有页面内锚点 `#post-{postNumber}`，楼层号单调递增且删除后不复用。楼层号链接和搜索结果使用 `/discussions/{topicId}/posts/{postNumber}` 永久入口，不使用依赖当前分页的临时 URL。普通楼层每页 `20` 个位置，包含首帖与占位；第一页为 `#1–#20`，页码直接取 `ceil(post_number/20)`。帖子流末尾提供普通分页，视口底部提供状态允许时的“回复主题……”入口，翻页后焦点移至首个加载出的楼层标题。

普通楼层底部采用左侧次要信息、右侧操作的排列：左侧为“#楼层 · 发布时间 · 已编辑”，右侧为“赞图标及数量／回复图标与文字／省略号更多”。零赞显示“赞”，已赞使用本站 primary 色，操作保持至少 `40px` 触摸目标。

- “赞”仅作用于首帖或普通楼层，使用 `aria-pressed` 表达当前状态；首版不给楼中楼点赞；
- “回复”打开该楼层的楼内回复编辑器，不创建普通楼层；
- “举报”、作者自己的“编辑／删除”和管理动作进入“更多”菜单，桌面与移动端顺序一致；
- 底部 minibar 的“回复主题……”才打开普通楼层 minibar，并在提交成功后进入新楼层所在页。

### 百度贴吧式单级楼中楼

这里采用[百度贴吧对楼中楼的定义](https://baike.baidu.com/item/%E6%A5%BC%E4%B8%AD%E6%A5%BC/16684691)：围绕某个普通楼层发生的讨论，集中显示在该楼内部。底部 minibar 的“回复主题……”创建新的普通楼层；每个普通楼层正文下方的“回复”在该楼内部打开楼中楼输入框。两种入口必须分开，避免用户误把楼内对话发成新楼层。

楼中楼遵循以下单级关系：

- 每条楼中楼只归属于一个普通楼层；首帖 `#1` 也可以拥有自己的楼中楼；
- 回复普通楼层时，回复目标是该楼层作者；回复某条楼中楼时，回复目标改为被点选的楼中楼作者；
- 回复楼中楼后，新内容仍与其他楼中楼并列显示在同一个楼内，文案为“用户乙 回复 用户甲：……”；
- 楼中楼内部不再生成子列表、第二层缩进或新的普通楼层号；系统显式保存所属楼层和可选回复目标，不从正文中的 `@用户名` 反推关系。

没有楼中楼且编辑器未打开时不显示空容器。有 `1–5` 个可显示条目时全部按创建时间正序显示；超过 `5` 个时默认显示正序前 `5` 个，并提供“查看全部 N 条回复”。这里的 `N` 包含为了保持对话顺序而显示的删除或隐藏占位；主题列表的“回复数”也包含回复位置占位，排除首帖。展开后仍在当前楼层内按正序浏览，每页 `20` 个可显示条目，入口变为“收起回复”，楼中楼页码只改变该容器，不挤占普通楼层分页或滚动到页面顶部。

楼中楼行使用“用户名／可选的回复对象／正文／时间／操作”的紧凑排列，不重复大头像、楼层号或点赞按钮。作者名和回复对象在主页可公开时显示用户链接；已注销账户使用统一名称。回复目标已删除、隐藏或因账户禁用不可公开时，上下文改为“回复一条已不可用的回复”，不保留目标正文、原姓名或用户链接。正文与回复上下文保持在同一阅读流中。桌面端“回复”和“更多”在该行获得悬停或焦点时出现，触屏端始终显示紧凑操作入口，不能依赖悬停。

楼内回复编辑器是贴吧式内联编辑器，不使用 底部 minibar：

- 点击普通楼层的“回复”后，编辑器出现在该楼楼中楼容器底部，目标为楼层作者；
- 点击某条楼中楼的“回复”后复用同一编辑器，目标切换为该用户，并显示可移除的“回复 {用户名}”上下文条；
- 编辑器包含正文、站点表情、“取消”和“回复”四类必要控件，不重复显示标题或 TAG；
- 作者编辑自己的楼中楼时在同一位置切换为“编辑回复”模式，预填原正文，操作改为“取消／保存修改”；不能把楼中楼送入底部 minibar；
- 桌面和移动端都保持内联；移动端打开后滚动到编辑器并聚焦正文，提交按钮位于软键盘上方可见区域；
- 切换楼层或切换到普通楼层 minibar 时，遵循[草稿与提交](#草稿与提交)的上下文切换规则；
- 新增成功后自动展开楼中楼、解析新回复当前所在页、聚焦并短暂高亮新回复；不能假定有并发新回复时最后一页仍包含本次目标。编辑成功后留在原条目所在页；失败时保留正文和回复目标；
- 回复目标在提交前失效时显示“回复目标已不可用”，保留正文，由用户取消定向回复或放弃，不能自动改为回复楼层作者。

楼中楼容器使用 `bg-muted/10`、左侧 `2px` 的 `border-border` 和 `12px` 内边距形成紧凑区域，不做卡片套卡片，不使用阴影。每条楼中楼具有页面内 `#comment-{commentId}` 锚点，但不占用普通楼层号；搜索定位使用 `/discussions/{topicId}/comments/{commentId}` 永久入口。从永久入口或搜索结果进入时，页面先定位父楼层，再自动展开正确的楼中楼页并聚焦目标；链接不能把楼中楼伪装成独立楼层。

楼中楼展开状态如下：

| 状态         | 界面与行为                                                                                    |
| ------------ | --------------------------------------------------------------------------------------------- |
| 折叠         | 显示正序前 `5` 条和“查看全部 N 条回复”                                                        |
| 首次展开中   | 保留预览，展开按钮显示“正在加载…”，禁止重复请求                                               |
| 展开成功     | 显示当前 `20` 条、楼中楼分页、“收起回复”和楼内回复入口                                        |
| 展开失败     | 保留预览与总数，原位显示“加载失败，重试”                                                      |
| 分页中       | 保留当前页，页码控件禁用并显示忙碌状态，成功后聚焦新页首条                                    |
| 目标直达     | 自动展开目标所在页，目标获得焦点和短暂高亮                                                    |
| 收起         | 回到前 `5` 条；再次展开恢复本页临时记忆的页码并重新核对内容，不能用旧缓存重新展示已隐藏的正文 |
| 空但正在回复 | 只显示内联编辑器，不显示“0 条回复”标题                                                        |

普通楼层分页不受楼中楼数量影响；主题列表公开回复数见[主题列表行](#主题列表行)。

### 内容状态

内容状态为 `published`、`hidden`、`deleted`；锁定和精品是主题上的独立状态。以下规则约束正文公开性和写入；回复位置计数不随公开性变化：

| 对象或状态         | 公开展示                                                                       | 普通用户动作与恢复边界                                                                                                             |
| ------------------ | ------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------- |
| 公开且未锁定的主题 | 显示主题头和帖子流                                                             | 活跃用户可新增回复；作者可以编辑自己的公开内容，删除仍受下述所有权与主题删除条件约束                                               |
| 锁定主题 | 既有内容继续按公开规则展示；新增与编辑入口替换为原因明确的状态提示 | 禁止新增与编辑主题、普通回复和楼中楼；仍可点赞、举报及删除自己符合条件的公开内容 |
| 隐藏或删除主题     | 整个主题不进入公共列表、搜索或公开计数，所有公开入口统一不可用                 | 作者也不能编辑；只有隐藏主题可由审核人员恢复，删除主题不可恢复                                                                     |
| 已删除普通回复     | 保留楼层号与“该回复已删除。”占位；其余满足公开条件的楼中楼仍可读               | 整个楼内禁止新增，原作者不能恢复；楼中楼作者在主题未锁定时仍可编辑自己的公开回复，也可删除自己的公开回复                           |
| 已隐藏普通回复     | 保留“该回复已由管理员隐藏。”占位，其楼中楼不在公共界面或搜索中出现，位置计数保留 | 禁止作者编辑或删除该隐藏楼层，禁止楼内新增与编辑；审核人员恢复父楼后，子回复再按各自状态显示，不能把单独隐藏或删除的子回复一并恢复 |
| 已删除或隐藏楼中楼 | 在可浏览的父楼中保留紧凑占位，删除文案为“该回复已删除。”；不显示作者、正文、点赞数或用户操作 | 不可作为新回复目标；删除不可恢复，隐藏只允许审核人员恢复；同楼其他回复不受该条状态影响 |

首帖 `#1` 与主题具有相同作者和内容状态，创建、编辑标题／首帖正文、隐藏、删除和恢复必须保持一致。首帖的“编辑”进入主题编辑；首帖的删除或隐藏动作作用于整个主题，不提供只删除或隐藏 `#1` 而保留公开标题的路径。

主题作者只有在主题仍公开，且除首帖外不存在任何未删除的普通回复或楼中楼时，才可以删除整个主题。检查覆盖所有楼层，包括已删除父楼下的公开楼中楼、隐藏回复及因账户状态暂不可见的回复，不以公开计数是否为零判断，也不区分回复是否由主题作者自己发布。不满足条件时提供“请求处理”，按主题举报进入队列；审核人员可以隐藏主题。删除不级联清除其他内容记录，不能绕过此条件消除他人的可恢复贡献。

公开账户语义沿用本站：`active` 和已匿名化的 `deleted` 账户贡献可以公开；`disabled` 账户的正文不公开，其普通楼层保留通用“内容不可用”占位，楼内讨论暂不可浏览；其楼中楼在可浏览父楼内保留同样的匿名占位。主题作者被禁用时，整个主题不可公开；恢复账户后仍需检查每条内容自己的状态，不自动撤销隐藏。普通楼层已删除不单独阻断其楼中楼公开性，这是父楼状态检查的明确例外；主题不可见、父楼隐藏或父楼作者禁用仍会阻断。占位只证明序列中有一个位置，不公开隐藏正文或内部原因。

编辑不改变内容的发布状态；作者不能通过修改正文自行解除隐藏。内容“恢复”仅指 `hidden → published`，不得复活 `deleted` 内容。主题恢复保留原锁定状态；隐藏或删除主题时取消精品，恢复后若需要精品必须重新加精。TAG 状态按第 7 节处理。

## 6. 发布与回复编辑器

编辑器借鉴贴吧的分场景交互：主题新建和编辑使用主题表单，普通楼层回复和编辑使用底部 minibar，楼中楼始终使用父楼内的内联编辑器。三种外壳共享正文、表情、草稿和提交逻辑，首版不提供富文本预览。

### 主题表单

桌面端点击“发布主题”或编辑主题后，打开居中弹窗，最大宽度 `880px`、最大高度 `85dvh`，带遮罩和受约束的键盘焦点。标题、可选多个 TAG token、正文在表单内滚动；弹窗标题、关闭按钮和底部工具栏／发布操作保持可见。主题作者可以编辑标题、TAG 和首帖正文；管理人员通过主题管理动作只调整状态或 TAG，不冒充作者改写正文。

移动端保留站点页头以下的全屏主题表单，输入区域独立滚动，TAG token 可以换行。响应式断点只改变外壳布局，不能重新创建草稿或更换目标。

### 普通回复 minibar

桌面和移动端使用同一个紧凑回复入口：主楼（#1）在阅读视口内可见时，minibar 位于主楼下方的正常文档流中；主楼完全离开阅读视口（包括被固定页头遮住）时，才固定到视口底部，与页面主容器对齐。不含主楼的分页直接使用固定态。切换位置保留文档占位，不重建编辑器，保留草稿、选区和撤销记录。

默认态显示“回复主题……”；左侧显示当前登录用户的头像，展开编辑时保持同一身份，未设置头像时沿用站点头像占位规则。仅显示入口不创建编辑草稿，也不抢夺阅读焦点。未登录时提供保留当前主题、分页、定位和返回筛选的登录入口；主题已锁定或不可回复时展示对应状态。讨论列表和详情页隐藏全站页脚，避免与回复入口争夺视觉焦点。

- 点击入口进入激活态，正文默认约两行，工具栏与提交操作位于输入框下方；不设置大面积上下文标题栏或紧凑／展开两档切换。
- 新回复的可访问名称包含主题标题，输入框提示“回复主题……”；编辑普通楼层时显式标注“编辑 #楼层号”，仅允许修改正文。
- 正文随输入增高至限定高度后在内部滚动；站点表情、图片、字数、收起、取消和提交保持可用。工具按钮有明确的可访问名称。
- 点击收起或编辑器之外的页面区域可以收起回复，保留当前页面内的草稿，显示回复目标、正文摘要；有修改时显示“未提交”。恢复后继续编辑原草稿。收起不等于取消，不弹舍弃确认。
- 外部点击收起不能干扰表情弹窗、菜单、舍弃确认或输入法组合输入；不以正文失焦作为收起条件。提交中和有错误／冲突待处理时保持编辑器展开。
- 固定态的页面底部留白和滚动定位避让随 minibar 实际占用高度变化，回到主楼下方时取消额外避让；末楼和底部分页必须可见、可操作。分页仍在帖子流末尾。
- 移动端回复默认不全屏接管；底栏处理安全区，并按 Visual Viewport 调整键盘出现后的底部位置和输入区高度。移动端视口模拟不等于真实软键盘验证，真机键盘体验在设备验收时确认。

楼内回复维持父楼内联，仅复用紧凑正文和工具栏，不提供图片或链接帮助按钮。楼中楼底部时间靠左，回复与省略号更多靠右。楼内编辑期间底部普通回复入口可以继续显示，但点击后须按单一草稿规则切换，不能静默把楼内草稿变成普通回复。

### 连续正文与插图

#### 编辑与发布

主题首帖与普通楼层支持正文中的图文混排，图片可插入任意光标位置并在图片前后继续输入，编辑时保留原位置；楼中楼仅支持文字与表情。原始文件每张最多 2 MiB（2,097,152 字节），支持 PNG、JPEG、WebP、GIF。每帖最多 10 张，合计最多 20 MiB；浏览器与格式自身能力不足时明确报错。主题标题必填；主题正文和普通回复允许为空，但必须至少有一张有效图片。正文 HTTP(S) 网址继续安全自动链接，发布器不提供链条按钮，楼层与楼中楼不提供复制链接按钮。

正文使用 Tiptap／ProseMirror 的单一连续编辑区，统一处理文字、换行、图片、光标、选区和撤销记录，不拆成多个输入框。空白提示只出现一次；图片独占一行，不提供文字环绕、尺寸拖拽或自由排版。新帖弹窗／移动页面与回复 minibar 共用编辑能力；长正文在限定高度内滚动，收起保留编辑器、光标与撤销记录。

图片按钮记住正文选区，文件选择、粘贴截图和桌面文件拖放均在插入点加入图片，多图按选择顺序插入；选区被替换，原有后文保留，插入后光标在最后一张图片之后。图片参与方向键导航、跨图选区、复制／剪切／粘贴、删除和统一撤销／重做。编辑时点图为选中，显示选中边框和删除按钮；不常驻上移／下移工具栏，不打开阅读查看器。桌面支持拖动图片，移动端可以选中删除及使用系统剪切／粘贴。粘贴仅接受文字、换行和当前草稿已知图片，不导入外部 HTML 样式或任意远程图片。

选择文件先检查原始大小、实际格式及容器结构，再由浏览器串行 Worker 处理并于正文内生成预览；点击发布才逐张上传到 R2，然后提交图片 ID、顺序与正文位置。显示上传进度及单图结果，失败保留文字、本地文件和成功图片，重试复用已成功结果，不静默只发文字。结果不确定时保留同一上传标识、最终字节与指纹，一分钟后可核对 R2 对象并补齐状态，缺失时受控重传，不另建对象。剪切移动保留图片身份；复制出的第二份图片使用独立上传标识但复用已处理字节，不重新压缩。编辑原图、移动、撤销重做及上传重试均不触发有损重编码；复制已发布图片通过本站读取接口携带同源凭据。图片从正文移除后本地资源仍保留到草稿结束，以支持撤销。草稿比较包含稳定图片标识、顺序与位置，图片进度不改变请求幂等标识；收起摘要显示图片数量，关闭或切换沿用舍弃确认。页面离开后不承诺恢复本地草稿。

图片集合参与编辑冲突核对。冲突保留整份草稿，读取当前版本后由作者明确确认并手动重试，不做自动合并。保存成功前不解除原关联。帖子按正文中的 UTF-16 光标位置交替展示文字与图片，保留透明度、显示尺寸比例及动画；懒加载并限制展示尺寸，点击全屏深色遮罩查看，支持上一张、下一张、方向键、Esc、触控滑动和缩放。

#### 浏览器图片处理

静态 PNG 使用 UPNG.js（cnum=256），JPEG 使用 @jsquash/jpeg 的 MozJPEG（quality=85），静态 WebP 使用 @jsquash/webp（quality=85、method=4、lossless=0、alpha_quality=100）。保持格式、正常显示方向和尺寸，只编码一次；输出有效且更小时采用输出，否则使用原文件。编码异常或无效输出报错并保留既有草稿，不静默降级、不循环编码。JPEG 方向在浏览器解码时处理一次，不把旧 EXIF 方向复制到编码结果。GIF、APNG、动态 WebP 保留原始字节。

编码器及 WASM 固定依赖版本、按格式懒加载并随本站打包，不访问 CDN，不使用 SharedArrayBuffer 或全站 COOP/COEP。处理取消或编辑器销毁时终止 Worker，释放预览资源，禁止过期结果写回。压缩可能改变像素、颜色及 EXIF 等元数据，不承诺固定压缩率、无可见损失或永久保存；这不是游戏资源的无损归档。

图片的存储、绑定、读取权限和人工清理见[图片存储与清理](#图片存储与清理)。浏览器画质、真实手机内存与交互需单独验收，构建和静态检查不代表已完成这些验证。

### 草稿与提交

同一页面同时只有一个编辑上下文。明确取消、关闭主题弹窗、切换回复目标或会卸载草稿的站内导航／分页／浏览器前进后退，均在有修改时先执行舍弃确认，无修改则直接关闭或切换。刷新或关闭标签页使用浏览器支持的离开提醒；不承诺跨页面或刷新恢复内存草稿。未提交修改以载入或新建时的标题、TAG、正文、图片和定向回复对象为基线比较，预填的上下文主题标题不算用户输入。舍弃提示为“舍弃当前未保存内容？”，取消确认后保留原输入与目标。

主操作按模式显示“发布主题”“发表回复”“回复”或“保存修改”。请求进行中禁止重复提交、取消、收起、切换目标和会卸载编辑器的站内导航；阅读和滚动仍可用。新增主题成功后进入首帖，普通回复成功后恢复默认 minibar 并定位新楼层；编辑成功定位原主题或楼层，不跳到帖子流末尾。

登录失效时保留当前页面内的草稿，显示“登录状态已失效，请重新登录”，提供在新标签页重新登录后继续提交的入口。网络失败保留正文并展开错误。编辑冲突时保留草稿和可复制的输入，读取当前版本后由用户解决差异再提交；不能要求刷新页面同时假定内存草稿仍会保留。请求去重与版本冲突遵循第 9 节的数据不变量。

### 输入反馈

标题最多 160 字符，首帖最多 20,000、普通主楼 5,000、楼中楼 2,000；首帖和普通主楼各最多 10 张图片、每张 2 MiB。文本请求解析前上限为 128 KiB。频率限制由实现代码中的命名常量发布；TAG 的产品边界见下一节。界面需要提供以下反馈：

- 未登录：“登录后可以发布主题和回复。”并提供登录入口；
- 缺少必填内容：在对应字段旁说明缺失项；正文与图片的互补规则见[连续正文与插图](#连续正文与插图)，TAG 可以为空；
- TAG 超出数量或长度限制：保留全部输入并指出需要修改的 TAG，不静默截断；
- 主题锁定：“主题已锁定，不能继续回复。”；
- 频率受限：“操作过于频繁，请稍后再试。”；
- 网络或服务错误：保留输入并显示“发布失败，请重试。”；
- 内容状态已变化：说明主题或帖子已被删除、隐藏或锁定，并停止提交。

## 7. TAG 与精品

### TAG

TAG 参考 NGA 的多重方括号标题前缀：每个主题可以没有 TAG，也可以包含最多 `5` 个 TAG；发帖者既可以从现有建议中选择，也可以输入尚不存在的名称作为新 token，随主题提交创建。显示形式为 `[求助] [运行问题] 标题`，顺序由发帖者决定。方括号只由展示组件生成，不进入 TAG 名称或标题正文。

TAG 之间地位相同，不设置“主 TAG”，也不强制第一项代表内容类型。精品和锁定是独立状态。每主题最多 `5` 个是本站为标题可读性和滥用控制设置的边界。

#### 阅读状态

- 主题列表、主题详情和搜索结果中的 TAG 使用字面方括号短链接，不使用圆形 `Badge` 或彩色胶囊；
- TAG 使用 `text-primary`，悬停或聚焦时显示浅色背景与下划线，默认没有边框和阴影；
- 同一主题的 TAG 优先整体换行，TAG 与标题之间保留一个文字空格；单个 `[TAG]` 长于可用行宽时允许内部换行，保证名称完整可读，不靠横向滚动显示；
- 点击 TAG 进入只包含该 TAG 的最新主题流；在已有组合筛选中点击筛选 token 的移除按钮只移除该项；
- 停用 TAG 在历史主题中照常显示并可筛选，同时在管理界面标记“已停用”；隐藏 TAG 不在公开标题中留下空括号或占位。

#### 编辑状态

新主题和编辑主题均复用现有 `TokenPicker` 与 `TokenInput` 的键盘、焦点、移除按钮和本站视觉，再为论坛增加上限反馈和排序能力：

- 输入后自动查询候选，按 ID 游标每次最多读取 100 个启用 TAG，并提供继续加载；
- 建议项只显示 TAG 名称，不附带使用次数聚合；完全匹配既有启用 TAG 时只允许选择，不显示创建项；停用或隐藏同名项按下表拒绝新增；
- 没有已知的同名项时，建议末尾显示“创建‘{name}’”；服务端仍须核对隐藏记录与并发创建。按 Enter 选择当前高亮项，没有高亮项时选择第一项；
- 空输入按 Backspace 移除最后一个 TAG；方向键移动建议高亮；Escape 关闭建议；所有行为兼容中文输入法组合输入；
- 已选 TAG 以本站 `TokenChip` 呈现，支持删除和键盘重新排序；拖放只作为指针设备增强，不能成为唯一排序方式；
- 达到 `5` 个后保留现有 token，禁用继续创建或选择并显示“每个主题最多使用 5 个 TAG”；不能静默丢弃第六项；
- 主题作者可以在主题未锁定且仍可编辑时增删或重排 TAG；管理人员可以通过主题管理入口纠正 TAG，不改写标题或正文。

#### 名称与唯一性

单个 TAG 为 `1–16` 个用户可感知字符。先拒绝原始输入中的控制字符和换行，再按 Unicode `NFKC`、去除首尾空白、连续空白折叠为一个半角空格的顺序处理；随后生成不区分拉丁字母大小写的唯一比较键。长度按规范化后的用户可感知字符计算，而不是 UTF-16 code unit；浏览器与服务端使用相同的规范化、大小写比较和字符计数规则。

规范化后的名称不能包含方括号、控制字符或换行，不能是纯空白或纯标点，也不能与“精品”“已锁定”等系统状态保留名称相同；保留名称集合由共用命名常量发布。规范化后重复的主题 TAG 合并为第一次出现的位置。唯一比较键在全部 TAG 状态中唯一；同名只复用允许选用的既有 TAG 并沿用其显示名称，不创建大小写或全半角变体，也不能借创建同名项绕过停用或隐藏。

首位创建者提供初始显示名称。输入新名称时先在草稿中建立 token，实际 TAG 随主题成功发布或保存时创建；取消或失败不产生孤立 TAG。用户创建 TAG 属于普通发帖能力，不要求 `forum.tag.manage`。TAG 状态和同名提交规则如下：

| 状态 | 展示与筛选                                                                                      | 新增关联与编辑历史主题                                                                                        |
| ---- | ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| 启用 | 可展示、搜索、筛选并进入发帖建议                                                                | 同名复用；并发创建同名项时返回既有启用 TAG，主题与关联一起成功，不重复创建                                    |
| 停用 | 历史主题照常展示、搜索和筛选；不进入新增建议                                                    | 同名新增返回“此 TAG 当前不可选用”，保留输入；已有关系可以保留、重排或移除，保存时按数据库原关系判断是否为新增 |
| 隐藏 | 名称不出现在公共正文外的 TAG 展示、筛选、搜索投影或建议中；用户正文中的同名文本仍按正文规则处理 | 不允许新增关联；同名提交只返回通用“此 TAG 当前不可选用”，不返回隐藏记录、创建者或内部原因                     |

隐藏 TAG 的既有关系保留以支持管理恢复，但不作为普通用户编辑器的 token。作者修改并保存 TAG 集合时，以其看到并确认的启用／停用 TAG 集合替换关系，原隐藏关系随该次保存移除；只修改标题或正文时保留原 TAG 关系。编辑器应说明“修改并保存 TAG 时会移除已不可见的标签关联”。所有主题实际关联数始终不超过 `5`，不能通过隐藏、恢复或并发保存突破上限；主题在载入后被改 TAG、改名、合并或改变 TAG 状态时，按编辑冲突处理，不能静默丢弃用户选择。

TAG 链接和筛选使用数字 ID，不把可变名称作为标识。管理改名不改变 ID，也遵守上述名称、唯一性和状态规则；改名不能解除停用或隐藏。恢复操作将停用或隐藏 TAG 设为启用，确认界面明确说明将重新公开并允许选用。合并要求目标是不同的启用 TAG：源主题关系迁往目标，仅有源项时保留源项位置，已有目标时去掉源项并保留目标原有位置。关系迁移、去重、统计与源 TAG 删除一起完成；源 ID 不复用，不建立旧 ID 转发或别名，旧筛选链接按第 3 节无效 TAG 规则处理。管理人员调整主题 TAG 也遵守同样的数量、状态和顺序规则。

`forum_tags` 独立于作品标签。作品标签描述游戏内容，论坛 TAG 描述讨论性质；两者不共享管理权限、URL、建议来源或数据库关系。

### 精品

精品是独立的策展状态，不实现为 TAG。只有当前公开主题可加精；主题保存加精时间和操作者，重复加精不刷新时间，取消后重新加精使用新的时间。取消加精不会改变主题已有 TAG。精品列表按加精时间排序，使新加精内容可被发现；账户或主题状态导致主题不可公开时，公共精品列表同样排除它。

主题列表、主题详情和搜索结果统一显示精品标记。普通用户不能申请自动加精；如需推荐某帖，使用主题“请求处理”入口，选择“其他”并填写加精建议，进入同一管理队列，不增加单独的推荐流程。

## 8. 搜索设计

搜索首帖、普通主楼和楼中楼正文，主题标题只计入首帖。查询与索引共用 NFKC、小写化及 Unicode 码点二元编码；查询规范化后限 2–64 个码点。连续匹配保留中文两字、大小写和兼容字符规范化，不提供单字搜索或相关性评分；返回精确总数，结果标题和摘要使用客户端文本高亮。

使用统一普通 FTS5 表 `forum_search_index` 和 `forum_search_documents` 映射表。映射只保存递增搜索序号及源主楼/评论引用；既有记录按创建时间、类型和 ID 初始化，新记录按发布顺序追加。源内容、映射和索引在同一受保护事务中提交；删除清除索引但保留映射序号。首帖修改同步标题及正文索引。

先用相同的全文索引查询和公开性、TAG、精品条件统计精确总数，再按搜索序号降序通过 LIMIT/OFFSET 读取指定页，每页最多 20 条。无效页码按第一页，越界取最后一页；不回退到全库正文 LIKE。正文预览最多 180 字符，仅返回定位信息和当前公开作者。结果链接继续使用永久入口。

`scope` 列只保存 `public` 或空字符串，表示当前公开性。主题、父楼、评论隐藏/恢复及账号启停在同一事务中更新该值；SQL 仍按源数据实时核对公开性。用户输入只能成为固定宽度十六进制 ASCII token，不作为任意 FTS 表达式执行。精确统计和深页 OFFSET 会增加读取成本。

TAG 筛选是独立、实时的主题关系过滤；TAG 名称和作者名称不作为全文匹配字段。关键词通过搜索按钮或回车提交，不自动逐字搜索。搜索页不使用 TAG 或精品筛选，分页只保留搜索范围与关键词；常用 TAG 多选和精品切换仅用于讨论版主题列表。

## 9. 数据与状态边界

以下是设计层的对象职责，不替代 migration 中的最终字段定义：

| 对象                    | 职责                                                                                       |
| ----------------------- | ------------------------------------------------------------------------------------------ |
| `forum_tags`            | 规范化 TAG、显示名称、创建者、使用状态和公开使用统计                                       |
| `forum_topics`          | 标题、作者、公开状态、精品、锁定、最后活跃时间和公开计数                                   |
| `forum_topic_tags`      | 主题的多个 TAG 及其显示顺序                                                                |
| `forum_posts`           | 所属主题、稳定楼层号、作者、正文和内容状态                                                 |
| `forum_post_comments`   | 所属普通楼层、作者、可选楼中楼回复目标、正文和内容状态                                     |
| `forum_post_likes`      | 用户对帖子的唯一点赞关系                                                                   |
| `forum_content_reports` | 举报人、唯一目标（主题、普通楼层或楼中楼）、原因、处理状态和处理结果；请求处理复用同一对象 |
| `forum_images` | 图片上传状态、对象键、楼层绑定、正文位置与人工清理状态；详见下节 |
| 讨论搜索投影            | 统一 FTS、搜索序号与源记录映射；可从源数据离线重建                                 |

必须保持的领域不变量：

- 创建主题、首帖、新建 TAG 及 TAG 关系作为一个原子操作成功或失败；
- 每个主题只有一个 `#1`，普通回复楼层号在主题内单调递增；
- 每条楼中楼必须属于一个普通楼层；楼中楼回复目标若存在，必须属于同一普通楼层；
- 楼中楼之间只记录回复目标，不允许以父子关系继续递归；
- 同一主题不能重复关联规范化后相同的 TAG；TAG 显示顺序稳定；
- 一个用户对同一帖子最多有一个点赞；
- 主题维护全部回复位置数、活动时间和最后回复目标；编辑、恢复不顶帖，隐藏、删除不回退，不扣减位置数；
- 锁定阻止新增与编辑内容，但不改变已有内容的公开性；具体删除、点赞和举报规则见第 5 节；
- 删除资格、所有权、状态转换及 TAG 状态在写入时原子核对；不能先读取“没有回复”后再无条件删除主题，也不能让隐藏与并发编辑互相覆盖；
- 公开查询按第 5 节核对主题、普通楼层、楼中楼和作者账户，显式包含删除父楼下楼中楼可读的例外；
- 一个举报只指向一个真实目标，并核对目标与主题、楼层的归属；同一举报人对同一规范目标最多有一个待处理记录；
- 管理动作、对应举报处理结果和审计原子提交；失败不把举报标成已处理，也不丢失已经提交的内容变化证据；
- 编辑保存核对载入版本；同一次发布尝试的网络重试返回既有结果，不重复分配楼层、创建楼中楼或增加 TAG 关系；不能按正文相同就合并两次独立发布；
- 主题并发版本只使用 `forum_topics.revision`，API 原样返回该不透明令牌；主题内容或 TAG 关系变更更新此版本，全站 TAG 的改名、合并、停用、隐藏和恢复在同一事务中更新受影响主题的版本。写入原子比较主题版本，TAG 快照仅保留在管理审计中，不再参与版本摘要或并发比较；
- 讨论数据使用离线命令导出；搜索索引由源数据派生，并与源修改同事务维护。

### 图片存储与清理

`forum_images` 保存本站图片 ID、上传者、客户端标识、最终文件 SHA-256、状态、R2 对象键、格式、实际大小、显示宽高、所属楼层、顺序与 UTF-16 `body_offset`。对象键固定为 `forum-images/{id}`，复用 `ARCHIVE_BUCKET`；只保存最终文件，不生成多份缩略图、不跨帖子去重。URL 从 ID 推导，不保存第三方资源地址或删除凭据。

上传接口 `POST /api/discussions/images` 保留现有 multipart 参数。服务端认证、同源、目标能力和速率校验独立执行；实际文件最多 2 MiB，multipart 额外允许 16 KiB 表单开销。以内容校验格式、块边界、必要头尾、帧尺寸和动画标识，不只信 MIME 或后缀。服务端只检查容器结构，不分配完整位图或宣称已完成像素解码验证。每账号仍最多 12 条一分钟内更新的上传记录，重试至少间隔一分钟，不设每日新记录配额。

同用户同客户端标识只对应一个指纹、记录和对象键；指纹不同返回冲突。上传认领使用数据库条件更新；R2 条件写入避免覆盖已存在对象，并记录指纹与 MIME。R2 写入成功但 D1 回写失败时，保留可核对状态；重试核对对象大小、类型与指纹，补齐 ready，或在对象缺失时重传。只有 D1 确认 ready 才返回成功，进入清理的记录不能重新绑定或复活。

图片绑定在现有 D1 发布／编辑事务内执行，通过 JSON 列表集合更新；SQL 语句数量不随图片数量增长。保留所有权、ready 状态、绑定目标、图片身份唯一性、UTF-16 正文位置及内容版本校验；失败不能部分解除或改写关联。图片只归属一个楼层，主题图片归属首帖。DTO 保持 id/url/thumb/width/height/size/format/offset，url 与 thumb 指向同一最终图片。搜索不索引 URL 与文件名，纯图片摘要使用“图片 × N”。

`GET /api/discussions/images/[id]` 每次读取重新判权：ready 且绑定公开帖子时公开；未绑定 ready 图片仅上传者和论坛管理员可读；隐藏或删除帖子中的 ready 图片仅论坛管理员可读；未完成上传、cleanup、cleaned 均不可读。返回正确 MIME、nosniff、same-origin 资源策略和 no-store，不公开桶、不使用作品图片一年 immutable 缓存。隐藏、删除不能撤回已被用户下载的文件。

`/admin/discussions/images` 沿用 forum.content.moderate_any 权限。上传结果不确定时管理员可先核对 R2 状态，不写入新图片。清理列表与写入共用资格规则：图片未关联楼层，或所属帖子、主题自身已隐藏或删除；仅作者账户停用导致不可公开不满足清理条件。删除及重试清理先展示图片 ID、作者、所属主题和楼层（或未关联状态），说明永久删除及无法完整恢复关联内容的后果；取消获得初始焦点，确认后才提交。清理操作在数据库中原子重新检查资格并标记 cleanup，然后删除 R2 对象；失败保留对象键并可重试，缺失对象视为已删除。最后原子记录 cleaned 和审计，重复操作幂等。保留已清理图片的原绑定作为状态记录；恢复帖子或主题的事务拒绝包含 cleanup/cleaned 图片的恢复，不能静默恢复为缺图帖子。隐藏本身不删除图片。

未发布、编辑移除和删除内容的图片保留供人工清理；无自动过期、后台压缩或定时删除任务。归档一致性扫描排除 forum-images/，由论坛人工清理边界负责；作品 GC 不接管论坛对象。

离线导出的讨论 JSONL 包含完整 `forum_images` 元数据，包括对象键、指纹、上传与清理状态、楼层绑定、图片顺序及正文位置，但不包含图片文件；D1 备份同样不包含 R2 字节。完整恢复需另行备份 `ARCHIVE_BUCKET` 的 `forum-images/` 对象，保留对象键与内容元数据，并与数据库备份对应、按指纹核对文件。讨论 JSON 导出不负责跨 D1／R2 的一致性快照，也不替代包含关联账户等记录的整站备份。

本地初始化按 [README](../README.md#本地启动) 应用仓库 migration；已有开发数据的更新入口见[本地展示数据](./local-demo-data.md#更新方式)。

## 10. 权限与管理

讨论区复用现有 session、角色、权限并集和自定义角色机制，不建立第二套论坛角色。

### 普通用户规则

公开阅读不需要权限 key。活跃登录用户可以发布主题、自建或选择多个 TAG、发表普通回复和楼中楼、点赞、举报，并按第 5 节的所有权和内容状态编辑或删除自己的内容。这些属于论坛领域规则，通过身份、所有权和状态判断，不为每个普通动作增加 permission key。点赞或取消点赞只作用于当前可公开的首帖和普通楼层，不改变主题活跃时间。

所有使用 session cookie 的写请求继续执行同源校验。页面或 route 只做身份和粗粒度权限检查；主题公开性、作者所有权、锁定状态、楼层与楼中楼关系、TAG 规范化和状态转换由论坛领域服务再次确认。

### 管理权限

权限 key、能力说明及系统角色授权以 [lib/authz/permissions.ts](../lib/authz/permissions.ts) 的 `PERMISSIONS` 和 `SYSTEM_ROLE_PERMISSIONS` 为唯一清单。需要独立版主时，通过现有自定义角色选择所需能力，不新增角色 kind，也不自动获得其他领域权限。

仅有 `forum.topic.feature_any` 时，只能查看和策展公开主题、纠正其 TAG，不能读取隐藏内容、举报人或内部备注，也不能管理全站 TAG 实体。仅有 `forum.tag.manage` 时只能进入 TAG 管理。`/admin/discussions` 按能力显示对应视图；待处理举报及非公开帖子需要 `forum.content.moderate_any`，不能只因用户能打开后台路径就返回全部视图数据。论坛内审计入口只展示其获授权管理范围的记录；现有全站审计入口仍遵守原权限。

### 公共管理动作

- 普通楼层和楼中楼的“更多”菜单按权限显示编辑、删除、举报、隐藏或恢复；
- 主题“更多”菜单按所有权、权限和状态显示编辑、删除／请求处理、举报、隐藏、锁定、解锁、加精、取消加精和调整 TAG；隐藏主题的恢复在管理界面执行；
- 管理动作打开确认对话框，并要求填写简短原因；
- 成功后原位刷新状态；主题变为不可见时进入统一不可用状态并提供返回讨论入口，不把用户送入管理后台；
- 操作菜单按当前操作者权限显示，公开接口不返回他人的角色、permission key 或内部审核身份；服务端不得仅依赖按钮是否可见做授权。

活跃登录用户举报公开的主题、普通楼层或楼中楼时，共用举报对话框。原因选项为“垃圾广告”“人身攻击或骚扰”“隐私或人身安全”“违法内容”“其他”；选择“其他”时必须填写说明，其余原因可以补充说明。“请求处理”也使用此对话框，预选“其他”，允许填写删除请求或加精建议；提交请求不代表一定执行。提交中禁用重复操作，用户不能在公开页面看到处理人、内部备注或其他举报者。

举报目标明确区分 `topic`、`post`、`comment`，每条记录只能选择一种。主题入口与首帖 `#1` 的举报统一归为 `topic`；`post` 只用于 `#2` 及之后的普通楼层，`comment` 对应单条楼中楼。去重按举报人、规范目标类型与 ID 判断；已有待处理记录时返回既有提交结果，不覆盖原原因和说明。队列明确标出目标类型，主题举报的标题和 TAG 上下文不能被误作普通回复。待处理期间目标被编辑、隐藏或删除时，处理页显示当前状态并重新校验动作，不依据过期摘要直接修改内容。

作者删除自己的内容与管理员隐藏内容是不同动作：作者删除使用简短确认且不要求管理原因；管理员隐藏、恢复、锁定、解锁、加精、取消加精或调整 TAG 必须在确认界面显示目标摘要并记录原因。危险动作的确认按钮使用 destructive，取消始终为低强调按钮且获得初始焦点。

### 管理界面

`/admin/discussions` 使用现有后台列表模式，提供：

- 待处理举报、主题和帖子三个视图；
- 按标题、TAG、正文、作者、状态和 ID 查询；
- 打开公开主题、准确楼层或楼中楼；
- 隐藏、恢复、锁定、解锁、加精和取消加精；
- 举报处理结果“已处理”或“无需处理”；
- 操作者、时间、原因和状态变化的审计入口。

管理页不复刻 Discourse 后台。页面使用现有后台 `PageHeader`、筛选表单、表格包装和分页：

- “待处理举报”默认视图按最早待处理时间排序，行内显示原因、目标类型、短摘要、举报人和时间；
- “主题”显示标题、TAG、作者、公开状态、精品、锁定、回复数和更新时间；
- “帖子”统一查询普通楼层与楼中楼，并明确标记类型、主题、楼层、作者和状态；
- 点击行进入同页详情面板，展示当前目标、所属主题与父楼上下文；可公开目标提供永久入口，不可公开目标在受权限保护的面板内审阅，公开永久入口仍统一不可用；不在列表行塞入全文；
- 举报详情完整显示举报人、时间、原因和补充说明，不截断说明；与当前内容分区展示。打开长详情时从顶部阅读，不因取消按钮获得焦点而滚到末尾；内容类型与状态使用中文名称；
- 移动端列表保留目标摘要、状态和操作，作者、举报人及时间进入详情；讨论 TAG 列表同样保留名称、状态、主题数和操作，创建者与更新时间可在管理详情查看；
- 批量隐藏、批量恢复和批量改 TAG 不在首版范围，每次只处理一个明确目标；
- 处理举报时选择“已处理”或“无需处理”，填写内部备注，并可在同一确认流程中执行一次对应的管理动作；“已处理”可以记录已由先前操作解决的结果，但必须有说明。隐藏普通楼层不会误变为隐藏整个主题，首帖例外按主题处理。处理举报需要审核权限；附带加精或调整主题 TAG 还必须具备 `forum.topic.feature_any`，不能由审核权限隐式获得。缺少附带能力时允许有权人员先完成相应操作，再由审核人员记录结果。

`/admin/discussion-tags` 提供 TAG 查询、改名、合并、停用、恢复和隐藏。表格显示 ID、名称、公开主题使用数、状态、创建者和更新时间。默认按公开使用数倒序、ID 升序，支持按名称和状态筛选。ID 创建后不修改；合并对话框必须显示源与目标 TAG、受影响主题数、重复关系处理规则和旧筛选链接失效的结果。所有 TAG 管理动作填写原因并写审计；改名、合并、停用、隐藏和恢复的行为以第 7 节为准。后台不承担普通 TAG 的日常新建，首次使用时由发帖流程创建。

首版不增加论坛专用禁言模型。严重滥用继续由具备现有用户状态权限的管理员处理；是否需要限定论坛范围和期限的禁言，待出现真实管理需求后另行设计。

## 11. 视觉系统与组件

### 视觉方向

视觉取舍的优先顺序固定为：本文的论坛交互语义、本站现有设计 token 与组件、Discourse 的信息层级。发生冲突时，不能为了“像 Discourse”覆盖本站的颜色、字体、圆角、焦点或按钮行为。

颜色和阴影以 `app/globals.css` 的语义 token 为唯一事实来源，不在论坛组件内另建色板：页面使用 `background`，正文使用 `foreground`，内容面使用 `card`，分隔使用 `border`，主操作和链接使用 `primary`，精品等策展强调使用 `accent`，危险动作使用 `destructive`。普通列表和帖子没有阴影，只有 minibar、菜单和对话框使用 `shadow-surface`。

字体沿用本站：页面与正文使用 `font-sans`，紧凑页面标题可以使用现有 `PageHeader` 的 `font-display`，楼层号、计数和时间使用 `font-mono` 与等宽数字。正文基准字号为 `16px`，次信息与普通操作为 `14px`，计数、时间和 TAG 辅助状态不小于 `12px`。正文行高至少 `1.7`。

主题列表和帖子布局分别以第 4、5 节为准。不引入 Discourse 的版块分类、信任等级、徽章、用户卡、右侧帖子时间轴、无限滚动、复杂富文本工具栏或反应表情组。

组件复用本站 `PageHeader`、`Button`、`Input`、`Textarea`、`UserAvatar`、Radix 菜单、`AlertDialog`、`EmptyState` 和分页原语。标题区仅放搜索、发布与更多动作；空状态只保留必要提示和一个直接操作。主操作使用 `Button default`，取消、重试等次操作使用 `outline`，帖子内动作使用 `ghost size=sm`；危险确认使用 `destructive`。`Badge` 只用于精品、锁定和管理状态，静态 TAG 遵循第 7 节。

圆角保持现有 `rounded-md` 量级，不增加装饰渐变、玻璃拟态、蓝紫色主题或论坛专用色板。`Rm2kButton` 不用于高频论坛操作。

论坛页面只使用 `4/8/12/16/24/32px` 的现有间距节奏。交互目标复用现有按钮并在需要时调整尺寸：桌面紧凑操作至少 `36px`，移动端主要操作和纯图标目标至少 `40px`；不能假定 `size=sm` 已满足此要求。焦点统一使用现有 `focus-visible` ring；不能另做只改变文字颜色、在浅米色背景上难以辨认的焦点样式。

### 组件职责

[DiscussionWorkspace](../app/discussions/workspace.tsx) 拥有唯一草稿与回复目标；[ForumEditor / ForumReplyBar](../app/discussions/editor.tsx) 共享正文、表情和提交反馈，并承载第 6 节的三种编辑器外壳。楼内编辑器由父楼渲染，不能因复用而移动到底部。TAG 展示与选择复用 [shared.tsx](../app/discussions/shared.tsx) 中的 `DiscussionTagLink`、`ForumTagEditor` 与本站 token 输入原语。

组件只共享展示和交互原语；公开性判断、授权和领域状态转换由服务层负责。组件可以调用查询服务、呈现其结果并管理本地交互状态，不能在组件中另写一套领域规则。

## 12. 响应式与无障碍

### 响应式

移动端以 **2021 年标准版 iPhone 13 的竖屏 `390px` CSS 宽度**为主要设计基准，参考视口为 `390 × 844px`。布局按 CSS 像素计算，不按设备物理像素计算；页面继续自适应实际可用宽高，不固定为设备尺寸。浏览器地址栏、软键盘和安全区会改变可用高度，`844px` 仅用于常规预览。

移动端的间距、信息密度、图片展示和工具栏排列优先在 `390px` 下确定。常规楼层操作与发布器主操作优先保持紧凑单行；长文案或字号放大时允许换行，不能缩小触摸目标来强行容纳。移动端视觉复核和交付截图默认使用 `390 × 844px`。

- `>=1024px`：左侧 `192px` 讨论导航与主列表并列，主题列表显示回复、浏览和活跃三列；
- `768–1023px`：单主栏，左侧导航折叠为标题下方的最新／精品切换与 TAG 筛选，主题列表保留回复和活跃，隐藏浏览；
- `<768px`：主题列表改为单栏内容流，作者、回复数和活跃时间进入标题下方；帖子作者栏折叠为帖子头；
- `<480px`：页面左右边距保持 `16px`，主题操作允许分成两行，TAG 可以在标题前换行，但数值和操作不得造成横向滚动；
- 楼中楼在所有宽度都只有相对普通楼层的一次视觉缩进；移动端把左侧内边距降至 `8px`，不能继续按回复目标增加缩进；
- 主题新建／编辑在桌面为居中弹窗、移动端为全屏表单；普通楼层 minibar 在所有宽度都按主楼可见性切换主楼下方与视口底部；楼内回复编辑器在所有宽度都保持父楼内联；
- 所有横向布局必须用长中文标题、长用户名、长 URL 和系统字号放大验证溢出。

断点之间不改变信息含义或操作名称。服务器输出的正文、TAG 顺序、楼层号和楼中楼顺序保持一致；响应式只调整排列和次要信息可见性。浏览器宽度变化时，已经输入的主题或回复草稿不能丢失或更换目标。

### 无障碍

- 页面使用一个 `h1`；主题列表使用带名称的 `section`，帖子使用 `article`；
- 最新、精品和 TAG 导航提供可见焦点和 `aria-current`；
- 编辑器字段均有持久标签，错误信息与对应字段关联；
- 图标按钮具有中文 `aria-label` 和 `title`；
- 精品、锁定、隐藏和删除状态不能只靠颜色表达；
- 打开编辑器或对话框后移动焦点，取消关闭后返回触发按钮；提交成功则遵循目标定位规则，触发按钮已消失时回到所在主题头或相关状态提示；
- 楼层或楼中楼锚点跳转后，目标内容获得可感知的短暂高亮和可编程焦点；
- 点赞等乐观更新通过状态文本向辅助技术宣布，不重复播报整条帖子。

主题列表行使用语义化列表或表格化网格，但不得同时伪装为可点击按钮。楼中楼容器以“{楼层号}的回复”命名，展开按钮携带 `aria-expanded` 和对应容器 ID；楼中楼分页使用“{楼层号}楼中楼分页”作为独立名称，避免与主题普通分页混淆。

所有菜单、TAG 选择器、主题表单和回复编辑器均可只用键盘完成。`200%` 缩放时，固定控件不能遮住正文或提交操作，允许通过换行适配。系统要求减少动态效果时，取消滚动动画和高亮淡出动画，但仍保留静态焦点反馈。

| 精品为空                 | “还没有精品主题。”                                                                                    |
| TAG 建议加载失败         | 保留已选 TAG 和输入，显示“TAG 建议加载失败”；仍允许提交合法的新 TAG                                   |
| 搜索词为空               | “输入关键词搜索讨论。”                                                                                |
| 举报成功                 | “已提交，管理人员处理后这里不会公开显示处理结果。”                                                    |
| 重复点赞或重复提交       | 服务端保持幂等，界面回到服务端确认的状态                                                              |

加载失败、发布失败和权限变化都必须保留仍然有效的用户输入。成功提示使用非阻塞状态文本；删除、管理动作和舍弃修改使用确认对话框，普通发布、编辑保存和点赞不再增加一次确认。不能用临时 toast 作为删除确认、错误恢复或回复目标的唯一载体。

界面不使用“强大”“自由”“永不删帖”等无法由产品保证的宣传语。自托管表示本站掌握日常管理和数据备份，不表示内容不受站点规则、基础设施条款或适用法律约束。

## 14. 实现验收边界

第 2–13 节是完整行为契约；后续变更按受影响章节核对，不能把必需状态降为可选项。下表仅保留容易误解的边界示例，不重述页面主流程，也不表示这些场景已经验收通过。

| 边界示例 | 核对重点与规则来源 |
| --- | --- |
| 第 21 个普通楼层或同楼第 21 个条目前存在删除／隐藏占位 | 公开目标位于第二页；按第 3 节的真实序列计算，不能只计公开正文。 |
| 未改动的预填正文与已修改草稿分别切换回复目标 | 仅后者触发舍弃确认；取消后保留原输入与目标，见第 6 节。 |
| 同名 TAG 并发创建、隐藏后保存或合并后重访旧筛选 | 按第 7 节核对唯一性、可保留关系、顺序和失效 ID；不以隐藏状态绕过五项上限。 |
| 命中内容隐藏、恢复或作者禁用 | 索引公开性与源状态同事务维护，后续查询立即生效，见第 8 节。 |
| 删除父楼；隐藏父楼后再恢复 | 按第 5 节区分楼中楼可见性；删除不可恢复，恢复隐藏父楼不改写子回复自己的状态。 |
| 删除主题同时收到新增回复 | 按第 9 节原子核对删除资格，不能同时删除成功和新增回复成功。 |
| 发布成功但响应丢失；编辑期间内容或 TAG 被修改 | 重试返回原目标，过期版本返回冲突；版本与写入边界见第 9 节。 |
| 仅授予策展权限；处理举报时附带策展动作 | 按第 10 节分别核对审核与策展能力，不能从后台入口推导额外权限。 |
| 同一用户依次举报主题、首帖和普通楼层 | 前两次归为同一主题的待处理记录，普通楼层是独立目标；不覆盖原说明，见第 10 节。 |

响应式、键盘、中文输入法、缩放和焦点规则见第 7、12 节；错误恢复与确认方式见第 6、13 节。文档、权限目录和 migration 各自保持唯一事实来源，兼容策略遵循根目录 [AGENTS.md](../AGENTS.md)。

这些示例不要求在敏捷阶段全部转为测试或浏览器流程。测试授权与分层遵循 [AGENTS.md](../AGENTS.md)，执行方式见[维护与回归手册](./maintenance-regression.md)；本节不另设回归流程。

## 15. 页面架构与离线运维

论坛采用React Router Framework Mode SSR：根布局统一渲染全站页头，保留导航、搜索、账户菜单和未读提示；跨页使用 React Router Link、Form 与路由导航，共享布局持续存在。论坛主体保持简化布局。主题页服务端输出当前页主楼、批量楼内预览和登录能力，直接水合为同一组件树。元数据与页面共用请求内详情读取。

论坛 API、图片、管理入口和 sitemap 通过 Hono handler 调用数据服务，保留认证、同源检查、请求上限及 `no-store` 响应。原生下载入口继续独立分发。主楼与楼中楼使用序号范围读取，预览和图片批量查询，列表与搜索使用数字页码和精确总数。楼内展开只加载对应楼层；正文只读取引用表情，完整表情目录在打开选择器时加载。编辑冲突保留输入，并分别核对标题、TAG 和图文正文。

普通 TAG 查询不聚合热度，分页最多 100 项，输入后自动查询建议并支持加载更多。热门榜按需聚合最多 100 个统计候选，Cache API 缓存有效期为 24 小时，只缓存 ID、数值和时间；显示前实时读取名称与状态，返回前十个可公开 TAG。图片先认证、限流、限字节，再核对格式、容器、尺寸和指纹；服务器不转码，读取重新核对当前权限并流式返回 R2。

sitemap 每片按主题 ID 范围覆盖最多 1,000 个主题，不读取正文；隐藏和禁用账号主题不输出。主站和论坛日常开发使用 `npm run dev`，打包后的 Worker 与下载链路使用 `npm run preview`。

数据转换、导出和备份方法见[论坛开发与数据维护](./forum-maintenance.md)。离线维护保留源 ID、正文、互动和图片引用。
