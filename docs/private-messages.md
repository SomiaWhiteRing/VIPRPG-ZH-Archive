# 短信箱

个人中心的 `/me/messages` 紧接概览；`/me/messages/:userId` 是与指定用户的一对一会话。默认头像快捷入口为短信箱、收藏、表情库，已有自定义顺序保留。我的目录继续可选，不增加用户搜索。

头像红点同时覆盖提醒和私信。提醒数字只统计原有收件箱；私信数字显示在短信箱快捷入口旁，未选该入口时显示在个人中心旁。个人中心桌面和手机导航中的短信箱也显示未读数。`/api/inbox/unread` 保留原有 `unread` 字段并增加 `messagesUnread`；入口共用根 loader 与同一份客户端未读状态。

## 收发与隐私

登录用户在其他活跃用户主页的好友按钮旁发起私信。自己、游客、停用或注销的目标、关闭接收私信的目标不显示发信按钮。隐私与偏好提供默认开启的“接收私信”；关闭后拒绝新的来信，历史记录仍可读取。旧隐私表单不含此字段时保留原值。

基础用户角色获得 `message.send`，单项禁用可以独立收回发送能力；历史读取只允许当前活跃账户读取本人参与的会话，不授予管理员全站读取权限。发送在 D1 批次中重新检查当前权限和收件人状态。每用户每分钟最多发送 30 条消息，图片上传每分钟最多 12 次。客户端提交 UUID 防止同一请求重复生成消息。

会话顶部仅头像和名字跳转主页，右侧三点菜单提供“屏蔽设置”和红色“举报用户”。私信拒收由屏蔽设置中的“私信”控制，独立于全局收信开关：发送方仍能发送并保留自己的记录，对话显示“对方已停止接收你的信息”；接收方不显示拒收期间的新消息，也不计入未读、列表摘要或更新顺序。每条消息在写入时固定投递状态，恢复接收不补收旧消息，原有历史继续保留。

私信举报使用论坛的原因选项，进入讨论管理的同一待处理举报队列。拥有 `forum.content.moderate_any` 的管理员通过 `/admin/discussions/messages/:reportId` 查看该举报对应双方的会话和图片；不能以此读取其他会话。详情仅提供处理结果与内部备注并记入审计，不附带处罚或权限修改入口。普通私信图片接口仍只向发送者和已实际投递的接收者开放；管理员图片访问使用带举报 ID 的独立鉴权入口。

文字最多 4,000 字，支持已有脸图表情和 HTTP(S) 链接，不提供提及通知、HTML 或讨论版扩展元素。已发消息不提供编辑、撤回和双方删除。未读位置独立保存，正常阅读时只有页面可见、获得焦点且消息末尾实际进入滚动窗口后才推进，长消息也能正常标记已读；预取、列表摘要、后台窗口不标记已读。主动开启私信拒收会清除该会话的已有未读。会话列表的更早内容在当前列表底部追加，提醒和私信入口共用未读角标样式。

Android App 内会话沿用永恒之海的整页滚动方式，保持与网页相同的会话框尺寸，滚动时固定会话头和输入区，避免原生下拉刷新抢占查看历史消息的手势；普通浏览器保留内部列表滚动。首次定位、新消息与图片加载后的底部跟随、加载更早消息的位置补偿均使用对应滚动容器；Android 的已读检测使用视口，并扣除固定会话头、输入区和页脚区域的遮挡。消息气泡在不支持颜色混合的旧版 WebView 中也保留浅色和深色背景。手机表情面板展开时，工具栏保持在面板上方。这是网站侧适配，生效需要更新连接站点的网页，无需更换 APK。

注销沿用账户匿名化与会话撤销，并关闭收信；双方历史记录保留。停用或关闭收信不会清除历史正文。

## 屏蔽设置

登录用户在其他活跃用户主页的私信按钮旁打开“屏蔽设置”；没有私信发送权限或对方关闭收信时，屏蔽入口仍然可用。窗口和私信三点菜单复用同一组件，提供“私信”“作品评论”“回帖与回复”“@提及”“点赞”“好友申请”六项，以及全部屏蔽／全部取消。修改在保存时生效，取消丢弃草稿；按钮以设置滑杆、圆圈减号、禁止符号表示未屏蔽、部分屏蔽、全部屏蔽，分别使用项目中性色、强调橙色和危险红色，全部屏蔽采用红色浅底与边框。配色沿用项目语义变量及其夜间主题，悬停保持各状态色。三态仅按六项个人设置计算，不受全局偏好和浏览器推送权限影响。

`user_block_settings` 按 `(user_id,blocked_user_id)` 保存单向关系，六项字段为 `block_private_messages`、`mute_comments`、`mute_replies`、`mute_mentions`、`mute_likes`、`mute_friends`，缺行等价于全部关闭，全部取消后删除设置行。设置不创建私信会话，不改变好友关系、公开内容、发言权限或永恒之海的管理禁言。

“作品评论”覆盖自己上传的作品、自己的目录的新主评论；“回帖与回复”覆盖评论区、讨论版和动态现有的回帖、回复；“@提及”独立控制评论区和讨论版的提及；“点赞”覆盖评论、讨论和动态；“好友申请”沿用添加与回加好友事件，不改变现有单向好友关系。同一内容、同一接收人只保留一条通知；同时命中主评论或回复和提及时，保留两种触发原因，任一项未屏蔽即可接收。发布时及系统推送分发、投递前均按该规则判断；只屏蔽其中一项不会将这条合并通知标记已读。全局偏好、业务权限和内容可见性继续生效；角色、审批、举报和维护者申请等业务事项不受个人屏蔽影响。

互动写入在原有批次中设置 `inbox_items.interaction_kind`（`comment/reply/like/friend`）与 `suppressed`。纯提及沿用 `metadata_json.mention` 标记及已发布的 `reply` 存储值；合并通知在原评论或回复记录上保存 `metadata_json.alsoMention`，保留原类型和通知 ID。原通知被屏蔽而提及可接收时，在同一发布事务内解除抑制并补入一条推送待办。展示时优先沿用可接收的原类型，原类型被屏蔽时显示为提及。评论区的纯提及及仅因提及可接收的通知归入“回复”分类。命中屏蔽的事件保留去重键和内容引用，但不进入提醒列表、详情、分页数量、未读和推送待办；恢复接收不补发，取消后重新点赞也不重建原提醒。好友的独立新添加事件不会被旧抑制记录阻挡。保存设置时，在同一批次中将命中当前开关的已有未读互动标记已读，开启私信拒收时推进会话已读位置；已读提醒及已投递历史保留。

`GET/PUT /api/users/:userId/block-settings` 只读取或修改当前账户对目标用户的设置，PUT 要求完整的六项布尔值；兼容旧客户端的五项请求，缺少 `muteMentions` 时沿用其 `muteReplies` 值。旧 `POST /api/messages/:peerId/receiving` 继续只修改私信这一项，不覆盖其他设置；`receiveMessages`、`acceptsMessages` 继续由新表计算，对方不会获得自己的其他屏蔽选项。保存后复用未读刷新事件，私信设置沿用 MessageRoom 的变化事件。系统推送投递前复核当前屏蔽和未读状态，已展示的系统通知不保证撤回。

## 图片

每张图片单独成为一条消息，使用已有浏览器图片处理，支持 PNG、JPEG、WebP、GIF，处理后不超过 2 MiB。选择、粘贴或拖入图片后，先预览并确认，再发送；取消不会发送图片，也不会清除文字草稿。不采用评论区的图文草稿或多图正文格式。

图片不套文字气泡；加载撑高后，处于跟随状态的会话继续滚到底部，手动上翻后保留阅读位置。客户端保留失败图片的处理结果和提交编号，重试不会重复保存；发送成功后的历史读取失败不报为发送失败，图片显示到历史后再次主动发送仍会生成新消息。消息编号生成支持手机通过局域网 HTTP 验收。

上传跟踪只用于完成 R2 与 D1 写入，上传完成后才分配消息 ID，避免较慢的图片被增量读取漏过。图片存放在同一私有 bucket 的 `private-messages/` 前缀，下载经过 `/api/messages/images/:messageId` 的当前会话双方鉴权，使用 `private, no-store`，不复用评论审核权限。未绑定的中断上传满七天后由既有归档清理任务顺带回收，每次至多 100 项；已发送图片不自动过期。

## 实时连接与费用边界

会话页使用独立 `MESSAGE_ROOM` binding 和 SQLite-backed `MessageRoom` 类。每对用户房间名固定，每用户最多四个连接。DO 仅发出无正文的变化事件，不访问 D1/R2、不持久保存消息、不设置定时器；使用 `acceptWebSocket` 与运行时 `ping`/`pong` 自动应答，空闲时可休眠。正文、图片和权限继续由普通请求读取。通知失败不撤销已写入 D1 的消息，重连和重新显示页面时补取历史。

只有聊天标签可见时连接；手机和平板还要求文档获得焦点。桌面不单独因窗口失去焦点而断开，但浏览器把页面判定隐藏时暂停。切页、隐藏或手机切后台时关闭，恢复时按消息 ID 补取；纯网页不能保证操作系统冻结进程前一定执行关闭事件。断线重连指数退避至三十秒，只有成功同步历史后才重置退避；历史接口持续失败时也不会因握手成功而密集重连。不持续轮询消息或全站保持 WebSocket。

这些约束降低 DO 活动时长和空查询，不构成计费硬上限。DO 请求、时长、Workers CPU 与 R2 容量仍使用全账户共享额度。未修改套餐、预算提醒、计费策略或线上资源。

## 迁移与验证

`0046_private_messages.sql` 增加接收开关、发送权限、会话、个人已读位置、消息、图片及表情引用，固定开发种子同步结构与账本。部署前需要应用迁移并配置 `MESSAGE_ROOM` 与 `MessageRoom` 导出；示例和 CI 模板已包含声明，资源 secret 不覆盖代码声明。正式发布和正式迁移按正式操作边界另行确认。

`0048_message_receiving_and_reports.sql` 增加按会话接收设置、不可变的逐条投递状态和独立私信举报表；旧消息默认已投递，不改写已发布迁移。固定开发种子同步该迁移并保留既有业务记录。拒收、恢复不补收、发送记录保留、未读和图片隔离、举报去重及审核范围使用临时内存数据库和接口检查验证，本次未重建浏览器验收环境。

`0051_user_block_settings.sql` 将会话拒收迁入独立用户屏蔽关系；旧拒收只开启私信项，显示为部分屏蔽。旧 `receive_messages` 列暂留供发布切换期间的旧 Worker 读取，当前代码统一使用新表，不维护第二套接收设置。迁移回填既有互动种类，保留提醒、逐条投递状态和已读位置，并让推送触发器跳过被抑制事件。固定开发种子同步结构与迁移账本，已有业务记录数量保持不变。发布代码须配套应用此迁移；回退到旧接收逻辑前仍须预览并同步新表中的私信拒收状态。

`0052_separate_user_mention_blocks.sql` 新增 `mute_mentions`，以原 `mute_replies` 值初始化，保留升级前合并开关的屏蔽效果。固定开发种子同步此列及迁移账本；发布新代码前须应用该迁移。
