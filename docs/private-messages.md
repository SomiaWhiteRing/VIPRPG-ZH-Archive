# 短信箱

个人中心的 `/me/messages` 紧接概览；`/me/messages/:userId` 是与指定用户的一对一会话。默认头像快捷入口为短信箱、收藏、表情库，已有自定义顺序保留。我的目录继续可选，不增加用户搜索。

头像红点同时覆盖提醒和私信。提醒数字只统计原有收件箱；私信数字显示在短信箱快捷入口旁，未选该入口时显示在个人中心旁。个人中心桌面和手机导航中的短信箱也显示未读数。`/api/inbox/unread` 保留原有 `unread` 字段并增加 `messagesUnread`；入口共用根 loader 与同一份客户端未读状态。

## 收发与隐私

登录用户在其他活跃用户主页的好友按钮旁发起私信。自己、游客、停用或注销的目标、关闭接收私信的目标不显示发信按钮。隐私与偏好提供默认开启的“接收私信”；关闭后拒绝新的来信，历史记录仍可读取。旧隐私表单不含此字段时保留原值。

基础用户角色获得 `message.send`，单项禁用可以独立收回发送能力；历史读取只允许当前活跃账户读取本人参与的会话，不授予管理员全站读取权限。发送在 D1 批次中重新检查当前权限和收件人状态。每用户每分钟最多发送 30 条消息，图片上传每分钟最多 12 次。客户端提交 UUID 防止同一请求重复生成消息。

会话顶部仅头像和名字跳转主页，右侧三点菜单提供“不再接收此用户的信息／重新接收此用户的信息”和红色“举报用户”。单向拒收独立于全局收信开关：发送方仍能发送并保留自己的记录，对话显示“对方已停止接收你的信息”；接收方不显示拒收期间的新消息，也不计入未读、列表摘要或更新顺序。每条消息在写入时固定投递状态，恢复接收不补收旧消息，原有历史继续保留。

私信举报使用论坛的原因选项，进入讨论管理的同一待处理举报队列。拥有 `forum.content.moderate_any` 的管理员通过 `/admin/discussions/messages/:reportId` 查看该举报对应双方的会话和图片；不能以此读取其他会话。详情仅提供处理结果与内部备注并记入审计，不附带处罚或权限修改入口。普通私信图片接口仍只向发送者和已实际投递的接收者开放；管理员图片访问使用带举报 ID 的独立鉴权入口。

文字最多 4,000 字，支持已有脸图表情和 HTTP(S) 链接，不提供提及通知、HTML 或讨论版扩展元素。已发消息不提供编辑、撤回和双方删除。未读位置独立保存，只有页面可见、获得焦点且消息末尾实际进入滚动窗口后才推进，长消息也能正常标记已读；预取、列表摘要、后台窗口不标记已读。会话列表的更早内容在当前列表底部追加，提醒和私信入口共用未读角标样式。

注销沿用账户匿名化与会话撤销，并关闭收信；双方历史记录保留。停用或关闭收信不会清除历史正文。

## 图片

每张图片单独成为一条消息，使用已有浏览器图片处理，支持 PNG、JPEG、WebP、GIF，处理后不超过 2 MiB。选择、粘贴或拖入图片即可发送，不采用评论区的图文草稿或多图正文格式。

图片不套文字气泡；加载撑高后，处于跟随状态的会话继续滚到底部，手动上翻后保留阅读位置。客户端保留失败图片的处理结果和提交编号，重试不会重复保存；发送成功后的历史读取失败不报为发送失败，图片显示到历史后再次主动发送仍会生成新消息。消息编号生成支持手机通过局域网 HTTP 验收。

上传跟踪只用于完成 R2 与 D1 写入，上传完成后才分配消息 ID，避免较慢的图片被增量读取漏过。图片存放在同一私有 bucket 的 `private-messages/` 前缀，下载经过 `/api/messages/images/:messageId` 的当前会话双方鉴权，使用 `private, no-store`，不复用评论审核权限。未绑定的中断上传满七天后由既有归档清理任务顺带回收，每次至多 100 项；已发送图片不自动过期。

## 实时连接与费用边界

会话页使用独立 `MESSAGE_ROOM` binding 和 SQLite-backed `MessageRoom` 类。每对用户房间名固定，每用户最多四个连接。DO 仅发出无正文的变化事件，不访问 D1/R2、不持久保存消息、不设置定时器；使用 `acceptWebSocket` 与运行时 `ping`/`pong` 自动应答，空闲时可休眠。正文、图片和权限继续由普通请求读取。通知失败不撤销已写入 D1 的消息，重连和重新显示页面时补取历史。

只有聊天标签可见时连接；手机和平板还要求文档获得焦点。桌面不单独因窗口失去焦点而断开，但浏览器把页面判定隐藏时暂停。切页、隐藏或手机切后台时关闭，恢复时按消息 ID 补取；纯网页不能保证操作系统冻结进程前一定执行关闭事件。断线重连指数退避至三十秒，只有成功同步历史后才重置退避；历史接口持续失败时也不会因握手成功而密集重连。不持续轮询消息或全站保持 WebSocket。

这些约束降低 DO 活动时长和空查询，不构成计费硬上限。DO 请求、时长、Workers CPU 与 R2 容量仍使用全账户共享额度。未修改套餐、预算提醒、计费策略或线上资源。

## 迁移与验证

`0046_private_messages.sql` 增加接收开关、发送权限、会话、个人已读位置、消息、图片及表情引用，固定开发种子同步结构与账本。部署前需要应用迁移并配置 `MESSAGE_ROOM` 与 `MessageRoom` 导出；示例和 CI 模板已包含声明，资源 secret 不覆盖代码声明。正式发布和正式迁移按正式操作边界另行确认。

`0048_message_receiving_and_reports.sql` 增加按会话接收设置、不可变的逐条投递状态和独立私信举报表；旧消息默认已投递，不改写已发布迁移。固定开发种子同步该迁移并保留既有业务记录。拒收、恢复不补收、发送记录保留、未读和图片隔离、举报去重及审核范围使用临时内存数据库和接口检查验证，本次未重建浏览器验收环境。

本次已完成 TypeScript、改动文件 ESLint、既有 UI／公共边界／样式命名静态检查、安全检查及时间线持久契约检查。临时内存数据库与模拟 API 检查覆盖收发隔离、权限与收信开关、请求去重、双向分页、已读位置、事务回滚、图片读取权限及中断上传清理；固定种子的完整性、外键、既有业务数量和迁移结构一致性也已核对。未新增永久测试入口。

另在隔离的本地 D1/R2 环境完成实际 WebSocket 收信、文字与图片发送、未读分流、会话衔接加载、历史位置保留及图片延迟加载滚动检查。浏览器故障注入验证历史读取失败与上传响应丢失后的图片去重；长消息末尾阅读清除未读也已验证。退避失败序列和恢复重置通过临时内存模拟检查，未新增永久测试代码。
