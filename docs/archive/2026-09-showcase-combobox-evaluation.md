# 展柜选择器迁移与体验评估

历史记录：以下为 2026-09-21 的迁移与当时验收，不是待执行工作，也不代表当前版本再次通过检查。当前交互职责见[共享选择器](../ui-feedback.md#共享选择器)，展柜规则见[展柜契约](../profile-showcase.md)。

评估日期：2026-09-21。范围：个人中心 `/me/showcase` 的作品、作者单选搜索框。使用本地开发服务、Chrome 和开发超管账户，先操作旧实现，再迁移到 `react-aria-components@1.21.1`，按相同路径复测。作者/译者多选和角色选择器不在本次迁移范围内。

## 对照结果

| 场景 | 迁移前浏览器实测 | 迁移后浏览器实测 |
| --- | --- | --- |

| 搜索「魔王」 | 原作与中文译本两项 | 相同两项；结果图像和名称保留 |

| 作者键盘选择 | 首项已高亮，因此 ↓、Enter 选中第二项 | ↓、↓、Enter 选中同一作者「本地测试译者」 |
| 选中之后 | 清空查询，已选名称作为占位符；显示预览并启用附言 | 相同，焦点保留在输入框；仍为未保存草稿 |
| 鼠标重复选择同一作者 | 原实现按点击回调选择 | 新实现实测仍能选择，关闭弹层并保留输入焦点 |

底部定位额外使用较矮窗口验证：实际 CSS 视口高度 555px 时弹层底边约 543.6px；高度 355px 时 `data-placement="top"`，顶边约 12.6px、底边约 254.3px。恢复正常桌面尺寸后，最终版本确认列表内部滚动和末项选择均可用。以上是浏览器 DOM 几何值及截图观察，未视作手机软键盘测试。

## 实现与修正

- 保留 200ms 防抖、AbortController 取消、服务端名称/别名过滤、错误重试和最多 12 项提示。
- React Aria 接管选项语义、键盘焦点、弹层定位；通过 render 接口复用项目 Input/Label 外观。
- 查询和所选目标分别控制，只对实际结果 ID 调用业务选择回调，保留查询清空和外部预览行为。
- 弹层最大高度使用组件的 `maxHeight={256}`；ListBox 在 flex 容器内收缩并滚动，避免整页被选项导航带动。
- 搜索框内 Enter 阻止外层表单提交，同时保留组件自己的选择操作。

组件行为依据：[React Aria ComboBox 官方文档](https://react-spectrum.adobe.com/react-aria/ComboBox.html)，并核对已安装版本的类型定义。没有替换其他 combobox，也没有增加测试代码或修改数据库 schema。

## 测试期间的异常与边界

中间版本的一次连续方向键/Enter 操作意外触发表单保存并跳转。返回页面确认展柜仍为空，未保存新的展示项；本地账户发生过一次空展柜保存，不能声称全程零写入。随后补上 Enter 提交保护，逐键验证展开时选择、关闭时 Enter、无结果 Enter 均不会提交。最终移除临时所选作品并取消启用，页面回到三个条目均未启用、无未保存提示的原状态。

新增依赖触发 Vite 依赖优化和页面重载，期间有浏览器控制超时。控制台在本次过程曾记录一次 `Cannot read properties of undefined (reading 'transaction')`（00:55:46 UTC）；来源尚未定位，最后重新加载后的复测未再出现新记录。不将它擅自归因为组件库或浏览器扩展。

未验证：真实中文输入法组合事件、读屏器、触摸/手机软键盘、接口故障下的重试、12 项上限提示和生产服务。没有测量加载性能提升；重复展开仍重新请求，增加依赖也有包体积成本。结论限于已实测的桌面交互。

## 验收结论

已测试路径的搜索、选择、草稿和关闭行为与原需求相符；首次方向键、明确的展开入口、窗口边界处理和列表导航更易用。建议本次作为作品/作者单选试点，其他复杂多选另行按其创建、删除、别名及已选项规则评估。

通过 TypeScript 检查、目标文件 ESLint、UI self-check（256 个文件）及客户端/SSR 生产构建。构建仍提示已有灯箱模块静态与动态导入混用，以及插件耗时提示；本次不改灯箱。
