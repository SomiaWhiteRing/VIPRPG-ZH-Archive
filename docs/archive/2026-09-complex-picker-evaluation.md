# 复杂选择器迁移与体验评估

历史记录：以下为 2026-09-21 的迁移与当时验收，不是待执行工作，也不代表当前版本再次通过检查。当前交互职责见[共享选择器](../ui-feedback.md#共享选择器)，展柜规则见[展柜契约](../profile-showcase.md)。

日期：2026-09-21。环境：本地开发服务、Chrome、开发超管。沿用展柜试点的“迁移前记录 → 迁移 → 浏览器复测”流程。

## 迁移范围与组件职责

| 组件 | 使用位置 | 本次处理 |
| --- | --- | --- |
| `CreatorPicker` | 制作人员署名、作者/译者标签编辑弹窗 | 使用共享搜索组件，保留身份锁定、署名编辑、别名匹配和更换身份 |
| `CreatorTokenPicker` | 上传/编辑作品的作者、译者 | 共用搜索、键盘、焦点与弹层；保留按人物身份去重和标签编辑 |
| `TokenPicker` | 作品标签、别名、讨论 TAG | 共用搜索交互；保留规范化、校验、数量上限、失焦提交及排序 |
| `CharacterPicker` | 上传/编辑作品、管理作品的登场角色 | 共用搜索；保留角色创建、头像素材、作品内别名和身份编辑 |
| `CharacterMergeTargetField` | 管理角色的合并目标 | 共用搜索；保留名称/编号排序、50 项上限、隐藏表单字段和清除操作 |
| `ShowcaseTargetPicker` | 个人展柜作品、作者 | 回收试点中的重复交互逻辑，共用同一组件；保留异步搜索与草稿 |
| `CharacterTreeSearch` | 角色素材工作台的角色切换 | 改用 React Aria Tree，保留分类路径、搜索、当前角色祖先展开和 Radix 弹层 |
| `CharacterMembershipPicker` | 分类管理的加入已有角色 | 从大型 editor 拆出，使用 Autocomplete + ListBox，保留常驻候选列表与双语显示名编辑 |

`app/components/ui/search-combobox.tsx` 统一管理 ComboBox、Input、ListBox、Popover、焦点、方向键、Enter 提交保护、Backspace 末项删除入口和 token 布局接入。过滤、去重、创建与数据更新规则留在对应领域组件，避免把业务分支塞进通用 UI。

选项弹层挂在选择器所在容器内，保证作者编辑等 Radix 对话框中的选项仍可操作。最大高度统一为 288px，内部列表可以收缩和滚动。`TokenInput` 支持组合后的输入字段，并跳过没有相邻元素的排版标记，兼容选项集合的隐藏渲染阶段。

删除没有调用者的 `app/components/ui/combobox.tsx`，不再保留手写方向键和选项 activeIndex 实现。分类成员的名称字段和选择逻辑收拢在 `character-membership-picker.tsx`，大型 editor 只负责持有草稿及提交。

## 迁移前记录

- 作者搜索「本地」：显示「本地测试译者 / 1 部作品」及「本地 / 新建」，首项自动高亮，直接 Enter 添加。标签进入编辑弹窗后，修改署名仍保留已关联身份；取消不改变原标签。
- 标签搜索「剧情」：显示「剧情向」和「剧情 / 新建」。Enter 添加首项，空输入 Backspace 移除末项。
- 角色搜索「卡萝尔」：4 个结果；直接 Enter 添加卡萝尔，显示头像、主角身份和详情编辑入口。
- 角色合并目标搜索「#2」：精确编号排第一，其余为前缀匹配，110 个匹配只显示前 50 个；未提交表单。
- 角色树搜索「#2」：保留「王国军 → 其他（王国军）→ 2003卡萝尔」路径。
- 分类成员搜索「卡萝尔」：常驻列表显示 4 个匹配，原实现为逐个按钮，缺少搜索输入与结果之间的统一键盘导航。

| 场景 | 结果 |
| --- | --- |
| 作者搜索与直接 Enter | 同样的现有/新建候选，输入后 Enter 添加首项、清空查询，保留多选快捷方式 |
| 作者弹窗更换身份 | 从「雪灯」别名关联到「雪灯工作室」，鼠标选择成功，署名仍显示「雪灯」 |
| 作者身份去重 | 已选雪灯后，再搜同一别名不重复提供该身份 |
| 译者多选 | 翻译作品的译者输入可搜索并追加「本地测试译者」，原有自动填入的署名保留 |
| 标签添加与退格 | 「剧情」Enter 添加「剧情向」，空输入 Backspace 移除末项 |
| 角色选择与详情 | 「卡萝尔」仍为相同 4 项；Enter 添加，键盘通过标签按钮打开作品内别名/身份编辑弹窗 |
| 角色创建入口 | 「迁移临时角色」显示新建候选；Enter 打开名称弹窗并预填日语名；取消返回查询，不创建角色 |
| 分类成员键盘选择 | 搜索结果仍为相同 4 项；↓ 聚焦首项，Enter 加入待选，出现双语显示名控件；候选排除已选项；取消后恢复 |
| 角色合并目标 | 编号/名称候选、选择提示和清除正常；未执行合并提交 |
| 角色树键盘 | 搜索框 ↓ 进入树，树内上下导航；#2 搜索下 Enter 切换至 2003卡萝尔素材页；左右键收起/展开王国军；Escape 关闭并返回搜索框 |
| 论坛 TAG 数量上限 | 已有草稿中含 5 项，新增候选禁用，Enter 不增加第六项；清空临时查询并重新打开后原 TAG、顺序、标题「发帖测试」、空正文保持 |
| 展柜回归 | 首次 ↓ 到第一项，End 到末项且列表内部滚动；Enter 更新草稿，关闭时再按 Enter 不提交；最终恢复空展柜草稿 |

多选保留原有“输入后 Enter 添加”，但初始焦点不再假装已经选中首项。平面列表的方向键、Home/End、焦点管理由组件库处理。树形搜索的交互有明确变化：输入框使用搜索框语义，方向键进入实际树焦点，层级导航由 Tree 接管；不再手写 aria-activedescendant 与展开索引。

## 异常修复与验证边界

迁移中间版本曾因 TokenInput 的悬停排版读取空相邻节点而报错，已修复；另外修复了共享组件初次查询时空集合导致未自动展开的问题。最终主要路径已重新验证。类型检查不能替代这些浏览器发现。

本轮没有点击发布作品、发布主题、保存角色资料、加入所选角色、合并角色或保存展柜。浏览器只更改本地草稿/待选状态；论坛有既存草稿，仅检查数量上限并复核其保留。上传的临时选择、分类待选和合并目标已清理，展柜恢复未启用状态。

未做：真实输入法组合输入、读屏器、手机软键盘、实际新增实体/上传素材/合并提交、接口错误注入，以及论坛已有 TAG 的拖动和失焦提交回归。排序、校验及失焦业务逻辑保留原实现，但不能据此声称这些交互已实测通过。制作人员紧凑布局及管理作品页使用同一组件，未逐页面重复操作。

TypeScript 检查、相关文件 ESLint、UI self-check（257 个页面/组件文件）及客户端/SSR 生产构建通过。构建仍有既有灯箱导入与插件耗时提示。本次复用已安装的 React Aria，无新增项目依赖。

结论：已测业务路径保持原规则；统一了平面选择器交互，补齐分类成员键盘导航，并将树层级导航交给成熟组件。复杂选择器分成通用交互、领域选择规则、外层草稿提交三层，后续修正焦点和弹层只需改共享实现。
