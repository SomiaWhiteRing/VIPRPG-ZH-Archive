# 个人中心窄栏显示反馈与加固

2026-09-25，根据匿名截图处理个人中心及其子页的正文异常压窄。反馈称 Chrome 异常、Edge 正常，但缺少浏览器版本、扩展及实际样式信息，原始触发原因未确认。

## 已确认的布局弱点与修改

原布局使用 `232px minmax(0, 1fr)` 两列 Grid，正文自动排位。桌面侧栏被额外样式隐藏时，正文会进入第一列；四列作品卡片随之压窄。

`app/me/layout.tsx` 改为桌面 Flex：侧栏固定 232px 且不收缩，正文使用 `flex-1 min-w-0`。侧栏隐藏后正文自然占据可用宽度。保留移动端导航、32px 栏间距以及作品编辑页的全宽模式。

此次修改只处理正文压窄；不声称解决顶部导航消失，也不将故障模拟视为匿名用户环境的复现。不修改框架版本、全站导航或浏览器兼容策略。

使用当前 Chromium、实际 `AccountLayout`、`AccountNavigation` 和个人页内容组件，配合合成路由数据及修改前后的 Tailwind 编译 CSS，执行隔离布局检查。未连接应用服务器或远端数据，未验证登录、目录创建、完整编辑表单或历史浏览器版本。

- 修改前：1280px 容器内隐藏侧栏后，正文为 232px，四列卡片单张为 49px；单独隐藏侧栏及覆盖全局 `.hidden` 都能触发。
- 修改后：同样条件下正文为 1280px，卡片为 311px；正常桌面正文仍为 1016px，卡片为 245px。
- 320px、390px、767px 和 768px 视口，以及桌面、移动端全宽标记场景均通过；共 12 个修改前后场景，没有页面横向溢出。
- 变更文件 ESLint 与 `git diff --check` 通过。CSS 编译前后均存在日期选择器依赖的 `@charset` 优化警告，与本次布局修改无关。

本地临时验证脚本、宽度报告和截图保存在忽略的 `output/account-layout-hardening-20260925/`，未加入永久测试套件。浏览器基础兼容范围仍参考 [Tailwind 官方说明](https://tailwindcss.com/docs/compatibility)，不将依赖的兼容下限当作整站已经完成验收的承诺。

## 移除产品样式中的 `:has()`

同日继续加固，全站产品样式的 5 处 `has`／`group-has` 变体已替换：

- 个人中心通过 React Router 的 `useMatch("/me/uploads/:workId")` 选择全宽模式，并在该模式下不渲染导航。普通页面仍使用上述 Flex 布局；移除作品编辑页的 `data-account-full-width` 标记。
- 论坛回复栏改用 `data-mobile-emoji-open` 属性选择器。`EmojiPicker` 通过手机面板占位节点的 ref 回调报告实际挂载状态，经编辑器传给回复栏，替代从父节点反查后代的样式规则。桌面切换、管理弹窗、禁用和卸载都会更新状态；移除 `data-mobile-emoji-spacer` 标记。
- `scripts/system-self-check.ts` 中保留的 `form:has(...)` 仅为 Playwright 表单定位器，不进入产品 CSS，也不影响浏览器页面布局。

当前 Chromium 的隔离交互验证使用实际个人中心布局、表情库、论坛编辑器、回复栏和表情选择器，开启 React Strict Mode，路由数据和表情接口由本地夹具提供。共 23 个场景通过：桌面与手机尺寸、断点边界、列表与编辑页来回切换、带查询参数和尾斜线的编辑路径、侧栏隐藏、表情库，以及手机面板开关、跨屏宽切换、管理弹窗返回、禁用恢复和编辑器卸载。回复栏内容底部间距在手机面板打开时为 0，关闭后恢复 12px。

TypeScript、变更文件 ESLint 和差异检查通过；单独编译当前 CSS 并检查所有选择器，`:has()` 数量为 0。验证脚本、报告和截图保存在忽略的 `output/account-layout-no-has-20260925/`。此轮未连接应用服务器或远端数据，未进行历史浏览器或真机安全区验证，仍不认定匿名报告由 `:has()` 引起。
