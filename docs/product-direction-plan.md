# 产品方向

状态：当前产品契约

本文只定义产品边界和信息架构。认证、角色、授权和审计以[认证与权限基线](./authentication-authorization-baseline-plan.md)为准；游戏资料和归档对象以[游戏领域架构](./game-domain-architecture.md)为准。

VIPRPG.org 是围绕 RPG Maker 作品发现、游玩、下载和讨论组织的玩家空间，不是博物馆、祭典宣传页或数据库展示页。

## 1. 产品边界

### 玩家空间

- 根路径始终是作品发现首页；登录状态只改变账户动作，不切换到另一套首页。
- 作品是公共导航、搜索结果和详情页的主对象。
- 作品详情第一屏回答：这是什么、能否在线游玩、如何下载。
- 作者、角色、标签和目录是发现与筛选工具，不与作品争夺首页主层级。
- 作品详情承载作品讨论：登录用户可以发表主楼评论、同主楼回复和点赞；评论不复用提醒。
- 评论正文只支持纯文本与站点自定义表情短代码，不提供评分、Markdown、附件或匿名评论。

### 上传空间

- 上传是在当前浏览器会话内完成的一次操作，不是长期项目管理。
- 2k 系游戏流程为：选择文件 -> 识别或关联作品 -> 填写必要信息 -> 上传 -> 查看结果；其他引擎流程为：填写作品资料与外部下载地址 -> 直接发布。
- 浏览器 Worker、文件白名单、哈希、去重、preflight、commit、引用关系和服务端 import job 是完整性边界；服务器的 `processing` 只表示上传处理，不是长期作品草稿。
- 不承诺跨浏览器重启恢复、跨标签页接管、多设备接力或长期本地任务历史。

### 管理空间

- 管理空间承载内容维护、角色管理、归档一致性、存储维护和审计。
- 管理页面可以展示内部字段与危险操作，但不能反向决定公共页面结构。
- 危险操作必须保持权限检查、确认、状态转换和审计边界。

## 2. 信息架构

```text
公共空间
  首页：推荐、最近加入、热门游玩或下载、随机发现
  作品：搜索、筛选、分类浏览
  作品详情：简介、截图、在线游玩、下载、游玩统计、讨论与收藏
  辅助索引：作者、角色、标签、目录

账户空间
  我的账户、消息、上传权限状态、最近游玩、我的评论和收藏

上传空间
  新建上传、当前会话进度、完成结果

管理空间
  内容、归档版本、用户、审计、维护
```

“最近更新”只能表示真实的新版本或新归档。没有对应数据时使用“最近加入”“热门下载”等可由现有数据解释的分区，不用文案伪装推荐、讨论、收藏或历史能力已经存在。

## 3. 产品规则

- 一个事实只有一个生产来源；UI、标签映射和文档不分别维护同一规则。
- 公共玩家路径、上传、管理和在线游玩按各自任务组织，不为视觉统一引入共享业务抽象。
- 只保留有生产消费者、外部契约或数据安全职责的复杂度。
- 行为变化必须说明影响范围和验证路径；废弃内部模型直接删除，不保留兼容层。
- 不把旧截图、已完成计划或部署记录作为当前产品指令。

## 4. 非目标

- 未登录 HERO、品牌宣传页或另一套首页。
- 在普通用户页面解释 Work、ArchiveVersion、manifest、D1 或 R2 关系。
- 用户画像、协同过滤、复杂推荐事件、评分系统、评论通知和独立评论历史页。
- 匿名评论、Markdown、HTML、附件、@通知、评论表情反应和反垃圾服务。
- 把作者、角色、标签和目录做成首页平级功能墙。
- 把一次上传扩展成跨会话长期任务中心。
- 为视觉效果新增泛型 UI 抽象或依赖。

## 5. 必须保留的能力

- Work / ArchiveVersion 边界及作品关系。
- manifest、SHA-256、blob、core pack、白名单与引用校验。
- import job、preflight、单次 commit 和失败后的显式重试。
- EasyRPG 本地安装、缓存与存档隔离。
- 认证、权限、审计、GC 和危险操作保护。

## 6. 变更验收

- 运行 `npm run check`。
- 在受影响的桌面和移动视口验证主任务路径、长文本换行、焦点、溢出和控制台错误。
- 验证入口仍可发现，且未把管理或归档内部信息推回公共首屏。
- 不使用旧阶段截图或 festival 相似度作为验收指标。
