# 提醒产品与界面契约

提醒提供条目评论、讨论与时间线互动、用户提及、好友、申请及系统消息的站内入口。讨论内容规则见[讨论设计](./forum-discussion-design.md)，角色与维护申请见[认证与权限基线](./authentication-authorization.md)。

## 接收范围

| 事件 | 接收人 | 导航目标 |
| --- | --- | --- |
| 作品新增主评论 | 开启评论提醒的活跃作品维护者 | 作品评论区 |
| 目录新增主评论 | 活跃的目录创建者 | 目录评论区 |
| 条目评论收到回复 | 直接回复目标的作者；未指定时为主评论作者 | 对应评论区 |
| 条目评论或回复收到点赞 | 被赞评论的作者 | 对应评论区 |
| 评论或讨论新增用户提及 | 被提及的活跃用户 | 对应评论或讨论内容 |
| 主题新增普通楼层 | 主题作者 | 新楼层 |
| 无定向楼中楼回复 | 父帖作者 | 新楼中楼 |
| 定向回复楼中楼 | 被回复楼中楼的作者 | 新楼中楼 |
| 首帖或普通楼层收到点赞 | 被赞帖作者 | 被赞楼层 |
| 楼中楼收到点赞 | 被赞回复作者 | 被赞楼中楼 |
| 时间线吐槽收到回复 | 吐槽作者 | 对应吐槽与新回复 |
| 时间线吐槽收到点赞 | 吐槽作者 | 被赞吐槽 |

仅向活跃账户生成互动提醒。每次回复只通知直接接收人，不额外抄送主题或父楼作者；自己回复或点赞自己的内容不提醒。参与讨论不等于订阅。

作品评论与好友提醒的接收设置见[账户偏好](./account-preferences.md)，提及去重见[用户提及](./user-mentions.md)。[私信](./private-messages.md)使用独立的会话与未读状态；[浏览器系统通知](./web-push.md)按订阅投递符合资格的站内提醒和私信。

## 持久事件与内容边界

- 回复和提醒在同一 D1 批次中提交，沿用论坛发布的请求幂等与写入门控。失败、重试、编辑与恢复内容都不会重复生成提醒。
- 点赞关系实际新建时才尝试写入提醒。同一操作者、目标帖与接收人只有一个点赞事件；取消点赞不删除历史提醒，再次点赞不新增、不重置已读、不改变原时间。
- 点赞提醒说明曾发生的互动，不表示当前点赞关系或实时点赞总数。
- 楼中楼点赞沿用上述接收与去重规则，事件键与普通楼层点赞分开。提醒定位到被赞回复；只要回复仍可公开，父楼已删除或其回复对象已不可用不会使点赞提醒失效。回复自身、父楼或主题隐藏以及账户状态造成回复不可公开时，按不可用提醒展示。
- 复用 `inbox_items` 和 `inbox_item_reads`，互动类型仅支持定向个人收件；时间线互动沿用 `system_notice` 与具有外键的 `timeline_event_id`／`timeline_reply_id`，列表单独归入回复或赞，不归入系统分类。角色申请由申请人及当前管理员（含超级管理员）共同读取，不按自定义角色中的 permission 扩大收件范围。事件唯一键和论坛引用由 migration 约束，不在自由文本中保存可执行跳转地址。
- 列表、未读数、单条读取及全部已读采用相同收件可见性。申请列表和待办计数采用相同当前审批能力判定；可查看申请不等于可以处理。
- 标题和摘要从当前可公开内容生成，纯文本显示，不保存正文快照用于绕过公开性检查。目标、必要上下文或账户不可公开时，显示“相关内容已不可用”，不输出相关原正文、标题、身份或用户链接。
- 已注销账户在仍可公开的内容中显示本站统一名称与默认头像，不提供主页链接。恢复内容公开性不会制造新事件或新的未读。
- 不可用提醒仍可单独或批量标记已读，未读计数不会静默排除它。

讨论写入入口为 [publishForum / likeForum](../app/.server/forum/mutations.ts)，提醒语句集中在 [notifications.ts](../app/.server/forum/notifications.ts)；条目评论写入位于 [work-community.ts](../app/.server/db/work-community.ts)，提及写入位于 [mentions.ts](../app/.server/mentions.ts)。查询与阅读操作集中在 [inbox.ts](../app/.server/db/inbox.ts)。

## 页面与列表

`/inbox` 的分类和页码通过 URL 保存。列表包含已读与未读提醒，按时间倒序，同时间按 ID 倒序，每页 30 条，使用站点数字分页。越界页码回到有效页；切换分类回到第一页。

| 分类 | 内容 |
| --- | --- |
| 全部 | 当前用户可见的全部提醒 |
| 评论 | 作品和目录主评论提醒，以及条目评论中的提及 |
| 回复 | 条目评论和时间线吐槽收到的回复 |
| 讨论版 | 讨论楼层、楼中楼回复和提及 |
| 赞 | 点赞事件 |
| 好友 | 对方添加自己、对方回加自己的提醒 |
| 系统 | 角色与维护申请、角色变更、举报提醒及系统通知 |
| 待处理 | 当前用户仍可处理的申请或举报；仅有相应处理能力者可见 |

页头数字表示全部未读，待处理入口数字表示待办数；普通分类不堆叠计数。申请人可在系统分类查看自己的申请与结果。

使用紧凑 `PageHeader` 和单份响应式列表，沿用站点浅米背景、青绿色主色、字体、按钮、头像和分页组件。行间分隔线替代独立带阴影卡片，不重复输出桌面表格和移动卡片，也不显示角色说明或统计卡。

每条互动以操作者、事件、主题标题、楼层位置和时间为主要信息，回复及点赞提醒展示对应公开正文的最多两行摘要。普通楼层点赞展示被赞帖子，楼中楼点赞展示被赞回复；摘要从当前公开内容读取，沿用 180 字截取与表情纯文本转换。用户主页与内容目标分别为独立链接。未读通过圆点、字重和可访问状态共同表达。申请状态只在角色申请上展示，不给所有消息套审批状态。

桌面端时间和操作靠右，移动端放到内容下方；以 390px 宽度和左右 16px 页面留白为基准。分类可横向滚动，页面本身不得横向溢出。长中文标题、长用户名和 200% 缩放允许换行，操作保留键盘焦点与触摸范围。

分类与分页加载期间保留已有结果。空状态按当前分类展示；加载失败与空列表分别处理。标记和审批的操作结果使用[全局 toast](./ui-feedback.md)，失败后原按钮仍可重试，成功后焦点回到稳定筛选工具栏。

## 阅读、定位与申请处理

- 无需当前用户处理的提醒，在列表或提醒详情的可见区域连续停留 1 秒后，通过 POST 自动标记已读；页面在后台、预取或仅加载到屏幕外的条目不计为看过。需要当前用户处理的申请保留手动已读及审批操作；添加好友提醒保留「加为好友／忽略」操作，不自动已读。回加回执仍按普通提醒自动已读。
- 自动已读同步行状态、页头未读数和全站入口；已读条目保留在当前列表，排序与分页位置不随阅读状态变化。自动标记失败保留未读与手动标记入口。
- 内容链接经过 `/inbox/[itemId]` 验证收件人与当前公开性；讨论内容用 `forumLocation` 计算当前页码及锚点，时间线内容进入指定吐槽并展开对应回复。失效目标提供不可用提示与标记已读入口。
- 主题页保留提醒 ID，在目标内容实际展示且页面可见后，通过 POST 标记该条已读；支持新标签页打开。服务端再次校验收件人及主题、楼层、楼中楼关联。GET 和路由预取不写已读。
- 标记失败不拦截阅读，提供重试与返回提醒入口。
- “全部标记已读”跨分类、跨分页，作用于服务端写语句开始时的全部可见未读记录；集合式写入不设条数截断，之后到达的新事件保持未读。
- 阅读状态与申请业务状态独立。已读申请仍可待处理；批准或驳回后，在原有审批事务中标记当前操作者已读，不改变其他管理员的个人阅读状态。
- 批准／驳回继续受现有权限、账户与角色层级、本人限制及角色状态约束。并发已处理时显示最新结果，不声称重复操作成功。
- 申请显示用户填写的纯文本理由。关闭开放申请、停用角色或开启全员开放时，待审申请显示“已关闭”及原因，并向申请人发送一次系统通知；全员开放不自动转为个人角色授权。

## 全站入口与更新

好友提醒与关系独立：对方添加自己时单向关系已经成立，「加为好友」只增加本人发起的反向关系，并发重复操作不会制造重复提醒；「忽略」只将当前提醒标记已读，不改变任一方向的关系或通知对方。双方当前账号与添加权限仍由现有服务端入口校验；停用、注销的发送者使用不可点击的状态名称和默认头像，不能回加。名单与提醒始终读取当前关系状态，历史提醒不表示双方目前仍是好友。好友提醒单独归入「好友」，不占权限申请的「待处理」分类。

隐私设置中的「接收他人的好友提醒」默认开启；关闭后不写入发给该账号的新添加提醒或回加回执，不阻止关系建立，也不删除已有提醒。关系与提醒写入保持同一 D1 batch，提醒语句读取数据库中收件人的最新选择；重新开启不补发关闭期间的提醒。

提醒入口位于页头用户菜单内，桌面和移动端均显示“提醒”及未读数。未读更新组件保持挂载，不依赖菜单是否展开；头像红点与私信角标的组合规则见[短信箱](./private-messages.md)。

页面首次进入使用服务端初值；站内导航、窗口重新聚焦、页面恢复可见时查询未读数量。短时间重复触发合并，禁止重叠请求；标记已读或处理申请后立即同步。请求失败保留上次成功值，下次事件触发时重试。

未读计数由上述事件触发查询。系统通知的 Service Worker 操作也可通知已打开页面更新状态；具体投递条件和浏览器支持边界见[浏览器系统通知](./web-push.md)。普通计数更新不重排当前提醒列表，不干扰帖子草稿。

入口组件为 [InboxIndicator](../app/components/inbox-indicator.tsx)，查询端点为 [GET /api/inbox/unread](../app/.server/endpoints/api/inbox/unread/route.ts)，由 [Hono API](../app/.server/api.ts) 注册，返回当前登录用户的 `unread` 和 `messagesUnread`，分别表示提醒和私信未读数，并禁止响应缓存。

测试授权和验收分层遵循根目录 [AGENTS.md](../AGENTS.md)，操作入口见[维护与回归手册](./maintenance-regression.md)。
