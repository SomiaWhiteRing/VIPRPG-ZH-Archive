# 上传工作台发布声明与译者字段契约

本文定义上传工作台中“发布声明”“翻译作品”和“译者”的界面、状态、缓存与提交契约。作品、Creator 和 `work_staff` 的通用数据归属仍以[游戏领域架构](./game-domain-architecture.md)为准。

## 1. 目标与范围

本契约适用于：

- `/upload` 新建归档作品与外链作品。
- `/me/uploads/[workId]` 复用上传工作台维护已有作品资料，并按当前引擎提供游戏文件或外部下载来源。
- 上传草稿的保存与恢复。

本契约要求以下结果：

1. 将“本作品为我原创。”从作者字段的附属选项改为独立的“发布声明”字段。
2. 在“发布声明”中并列提供“本作品为我原创。”和“本作品为翻译作品。”两个复选框。
3. 两项声明互斥，但允许都不选择。
4. 选择翻译作品后，在作者字段之后显示译者输入框。
5. 新建上传时，译者默认使用当前登录用户的显示名，并记住用户之后填写的默认译者及翻译声明选择。
6. 将译者作为 Creator 的作品职员关系提交，不允许上传流程修改 Creator 的个人资料。

以下内容不在本契约范围内：

- 作者或译者个人链接、简介等 Creator 资料维护。
- 作者或译者自动补全、消歧和账号绑定。
- 原作语言、目标语言、翻译组、校对者等更多翻译元数据。
- 公开作品页的徽标、筛选和搜索入口。
- 跨设备同步上传偏好。

## 2. 名词与数据归属

| 名称 | 含义 | 持久化归属 |
| --- | --- | --- |
| 作者 | 原作品的作者或制作人员 | `creators` + `work_staff.role_key = "author"` |
| 译者 | 当前翻译作品的翻译人员 | `creators` + `work_staff.role_key = "translator"` |
| 原创声明 | 当前上传者声明“本作品为我原创。” | Work 的 `is_original` |
| 翻译声明 | 当前作品是一份翻译作品 | Work 的 `is_translation` |
| 上传偏好 | 当前账号在当前浏览器常用的译者文本与翻译声明选择 | 浏览器本地存储，不是领域数据 |

当前用户的显示名只用于生成译者输入框的初始值，不代表 User 与 Creator 已建立身份绑定。提交后仍按 Creator 名称执行现有的匹配与创建规则。

## 3. 界面结构

### 3.1 字段顺序和宽度

作品资料区按以下顺序排列：

1. 中文名、原名。
2. 作者。
3. 译者，仅在翻译声明选中时出现，并紧接作者之后。
4. 发布声明。
5. 简介及后续字段。

桌面双列布局下：

- 作者占半行。
- 译者显示时占作者右侧的半行。
- 译者不显示时，不拉伸作者；作者仍保持半行。
- 发布声明独占一整行。

窄屏下各输入字段按现有响应式规则占满一行；两个声明复选框位于同一个“发布声明”字段内，空间不足时允许自然换行。

### 3.2 发布声明

字段标签固定为“发布声明”，内部使用两个受控复选框：

- `本作品为我原创。`
- `本作品为翻译作品。`

必须使用复选框而不是单选按钮，因为“均未选择”是合法状态。两个复选框应组成一个可访问的控件组，并共享“发布声明”名称。

### 3.3 译者输入框

- 字段标签固定为“译者”。
- 使用单行输入框，不使用 textarea。
- 一个输入项表示一个完整的 Creator 名称；提交时只去除名称首尾空白，不按名称中的标点拆分。
- 翻译声明未选择时不显示译者字段。
- 翻译声明选择后显示译者字段，但不主动抢走当前键盘焦点。
- 同一页面内关闭再重新选择翻译声明时，应恢复刚才的译者输入，不因隐藏字段而清空。

### 3.4 作者与译者名称边界

- 作者和译者名称中的半角逗号 `,`、全角逗号 `，`、顿号等字符都是姓名正文。
- 客户端、API 和领域服务均不得用逗号、换行或其他标点拆分作者或译者名称。
- 如需表达多位作者或译者，界面必须将每个人作为独立项目添加，接口使用数组或重复字段传输；不得使用带分隔符的单个字符串编码多人列表。
- 同一职责中的多个结构化项目按现有名称比较规则去重，但不得因姓名中含有逗号而产生额外 Creator。

## 4. 声明状态机

| 原创声明 | 翻译声明 | 译者字段 | 是否允许提交 | 有效译者提交值 |
| --- | --- | --- | --- | --- |
| 否 | 否 | 隐藏 | 是 | 空 |
| 是 | 否 | 隐藏 | 是 | 空 |
| 否 | 是 | 显示且必填 | 译者非空时允许 | 规范化后的译者关系 |
| 是 | 是 | 不得出现 | 否 | 不适用 |

交互规则：

- 选择原创声明时，立即取消翻译声明并隐藏译者字段。
- 选择翻译声明时，立即取消原创声明并显示译者字段。
- 再次点击当前已选择的声明时只取消该声明，进入两项均未选择的状态。
- 切换声明不得清空页面内的译者草稿值或浏览器中的译者默认值。
- 表单被锁定或正在提交时，两个复选框与译者输入框沿用作品资料区的统一禁用状态。

## 5. 初始值与优先级

表单初始值必须按下列顺序解析，前一项存在时不得被后一项覆盖：

1. **恢复上传草稿**：使用草稿内保存的原创声明、翻译声明和译者关系。
2. **编辑已有作品**：使用服务端 Work 和 `work_staff` 的现有值。
3. **新建上传且存在当前账号的浏览器偏好**：恢复缓存的翻译声明和译者默认值。
4. **新建上传且没有缓存**：原创声明与翻译声明均不选择；内部译者草稿值使用当前用户显示名，待选择翻译声明后显示。

补充规则：

- 原创声明不进入浏览器偏好；新建上传不得自动沿用上一次原创声明。
- 编辑已有作品时，浏览器偏好不得覆盖服务端数据。
- 恢复上传草稿时，浏览器偏好不得覆盖草稿数据。
- 服务端数据或草稿的初始化过程本身不得反向写入浏览器偏好；只有用户主动编辑译者或改变翻译声明时才更新偏好。

## 6. 浏览器缓存契约

该偏好使用 `localStorage`，不并入上传草稿的 IndexedDB。原因是它是轻量、跨上传任务复用的账号偏好，而不是某个上传任务的可恢复业务状态。

缓存必须按登录账号隔离，键名为：

```text
viprpg.upload.translation-preference.v1:<userId>
```

值使用带版本的 JSON：

```ts
type UploadTranslationPreferenceV1 = {
  version: 1;
  isTranslation: boolean;
  translatorText: string | null;
};
```

写入规则：

- 用户选择或取消翻译声明时，写入 `isTranslation` 的最新布尔值。
- 用户选择原创声明而导致翻译声明取消时，也写入 `isTranslation: false`。
- 用户修改译者输入时，保存去除首尾空白后的非空文本。
- 用户清空译者输入时，写入 `translatorText: null`；下一次新建上传回退到届时当前用户的显示名。
- 不缓存原创声明、作品作者或其他表单字段。

读取和失败处理：

- 缓存中的 `translatorText` 非空时优先于当前显示名；为空或不存在时使用当前显示名。
- 缓存中的 `isTranslation: true` 会在新建上传时自动选择翻译声明并显示译者字段，同时保证原创声明为否。
- 缓存中的 `isTranslation: false` 或不存在时，两项声明默认均不选择。
- JSON 无法解析、版本不支持、字段类型错误或浏览器拒绝存储时，忽略缓存并使用无缓存默认值。
- 缓存异常不得阻止页面打开、资料填写或提交。

## 7. 校验与提交

### 7.1 客户端校验

提交前生成有效值，不直接提交隐藏控件中的草稿值：

- `isOriginal && isTranslation`：阻止提交。正常 UI 不应产生该状态，但仍需防御异常状态。
- `isTranslation === true` 且去除首尾空白后的译者名称为空：阻止提交，在译者字段显示“请填写译者。”并将焦点移到译者输入框。
- `isTranslation === false`：有效译者关系强制为空，不论页面内或浏览器缓存是否仍有译者文本。
- 原创声明和翻译声明均为否：允许提交。

归档作品与外链作品使用完全相同的声明、译者和校验规则。

### 7.2 服务端校验

服务端不得信任客户端互斥或隐藏行为，必须再次校验：

- 原创声明与翻译声明不得同时为真。
- 翻译声明为真时至少有一条非空译者关系。
- 翻译声明为假时忽略客户端携带的译者文本，并将该 Work 的译者关系归一化为空。
- 新建和更新必须使用相同规则；不得只在 UI 层实现。

### 7.3 Creator 与职员关系

- 作者和译者名称共同参与 Creator 名称匹配与创建，名称比较沿用现有不区分大小写的规则。
- 作者写入 `work_staff.role_key = "author"`，译者写入 `work_staff.role_key = "translator"`，默认 `role_label` 分别为“作者”和“译者”。
- 同一 Creator 可以同时拥有作者和译者职责；每种职责内部去重。
- Creator 名称规范化不得删除、替换或解释逗号；例如 `A, B` 必须始终是一个名称，而不是 `A` 与 `B` 两个人。
- 上传流程只能关联或创建 Creator，不得写入或覆盖已有 Creator 的 `website_url`、原名、简介等公共资料。
- 更新作品时，只替换该作品的作者与译者职责；其他职员职责不因本表单未显示而被删除。
- 取消翻译声明并保存时，必须删除该作品现有的译者职责。

## 8. 持久模型与接口契约

### 8.1 Work

在当前唯一模型中为 `works` 增加：

```sql
is_translation INTEGER NOT NULL DEFAULT 0
  CHECK (is_translation IN (0, 1))
```

并在 `works` 表上增加声明互斥约束：

```sql
CHECK (NOT (is_original = 1 AND is_translation = 1))
```

项目尚无需要兼容的生产数据，因此直接更新当前 migration、查询投影、种子数据和领域类型，不增加旧字段兼容层或双写路径。

### 8.2 上传元数据与归档 manifest

- `ArchiveCommitMetadata.game` 增加 `isTranslation: boolean`。
- 生成的归档 manifest 的 `game` 部分增加同名字段，确保归档快照携带完整作品声明。
- `workStaff` 使用现有的 `translator` 角色承载译者，不新增译者文本列或译者表。
- 上传草稿保存完整元数据，因此自然包含翻译声明与译者关系；恢复时不得再从浏览器偏好推导。

### 8.3 创建、编辑和读取接口

所有写入路径必须同步支持：

- 归档上传 commit。
- 外链作品创建。
- 作品资料编辑。

作者和译者必须使用独立名称字段或结构化数组解析，不得复用会按逗号或换行拆分标签、别名、角色的通用 `readList` / `lines` helper。

所有读取路径必须返回：

- `isTranslation`。
- `role_key = "translator"` 的译者列表。

`/upload` 还需把当前用户 `displayName` 传给客户端，用于新建上传的译者默认值；已有作品编辑以服务端资料为准。

## 9. 验收场景

1. 新账号首次进入新建上传时，两项声明均未选择；选择翻译声明后，译者出现并预填当前显示名。
2. 用户修改译者并保持翻译声明为真，重新进入新建上传后自动恢复该译者并选中翻译声明。
3. 用户取消翻译声明，重新进入新建上传后不再自动选中；译者默认文本仍可在以后再次选择翻译声明时复用。
4. 选择原创声明会取消翻译声明；选择翻译声明会取消原创声明；任一已选项都可以单独取消。
5. 翻译声明为真且译者为空时无法提交，并显示“请填写译者。”。
6. 翻译声明为假时，即使页面内仍保留译者草稿，提交结果也不包含译者关系。
7. 编辑已有翻译作品时，以服务端声明和译者为准，不受当前账号缓存影响。
8. 恢复上传草稿时，以草稿声明和译者为准，不受当前账号缓存影响。
9. 取消已有翻译作品的翻译声明并保存后，Work 的 `is_translation` 为否且译者职责为空。
10. 原创声明与翻译声明同时为真的伪造请求被服务端拒绝。
11. 翻译声明为真但没有译者的伪造请求被服务端拒绝。
12. 新建或关联译者不会覆盖同名 Creator 已有的个人资料。
13. localStorage 缺失、损坏或不可用时，页面仍可正常填写和提交，并回退到当前显示名默认值。
14. 作者名或译者名为 `A, B` 时，新建归档、外链创建、编辑资料和草稿恢复都只产生一个完整名称为 `A, B` 的 Creator。
15. 多位作者或译者只能通过多个结构化项目提交，不能通过半角逗号、全角逗号或换行分隔。

## 10. 实现检查面

实现时至少同步检查以下权威入口，避免只改上传页面：

- `migrations/0001_init_archive_schema.sql`：`works` 声明字段与互斥约束。
- `lib/archive/manifest.ts`：`ArchiveCommitMetadata` 与归档 manifest 类型。
- `lib/server/db/archive-commit.ts`：元数据校验、Work 写入和作者/译者职责替换。
- `lib/server/db/game-library.ts`：Work 读写 DTO、作品资料更新和 Creator 关系读取。
- `app/upload/upload-client.tsx`：发布声明、译者动态字段、客户端校验与偏好恢复。
- `app/upload/page.tsx`：为新建上传传入当前用户显示名。
- `app/api/works/external/route.ts`：外链作品创建参数与服务端校验。
- `app/me/uploads/[workId]`：复用上传工作台完成资料编辑、来源切换和单一保存入口。
- `app/upload/upload-worker.ts` 与上传草稿：manifest 生成、保存和恢复。
