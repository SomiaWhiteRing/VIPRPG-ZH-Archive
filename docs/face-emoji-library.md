# 角色脸图表情库

表情来自已审核角色脸图的 48×48 格子。图片哈希和行列唯一确定一个不可变表情引用，角色绑定仅用于搜索与来源展示。多人共用脸图不推断格子人物；取消收藏、角色改名、合并或解绑不改变已发布内容。素材审核撤销、图片不可用或尺寸不匹配时显示不可用占位。

## 用户入口

头像菜单与个人中心的「表情库」进入 `/me/emojis`，页面复用脸图工作台的左右分栏与选格画布。左侧是人物树下拉框和脸图表，右侧固定显示「我的表情」，不再使用三个标签页。下拉框的首个选项为「全站热门」，角色按现有分类树展开，角色项左侧显示统一高度的默认脸图；中文名、日文名和别名搜索走服务端分页，分类展开时才加载成员。桌面端脸图表固定三列；窄屏按左栏、右栏依次排列，脸图表保持每行两张素材。工具界面仅保留名称、操作与状态反馈，不显示操作说明和排序说明。

点击左侧格子或右侧表情进行单项预览，预览右侧提供「加入我的表情」或「从表情库移除」，不提供多选或批量管理。移动端仅在选中表情时显示预览，并固定在视口底部；页面为预览保留空间。桌面端右侧表情悬停时显示小型主题色移除按钮，支持从左向右拖拽加入、从右向左拖拽移除，以及个人库内部拖动排序。拖动时其他表情平滑让位，浮图只包含所选 48×48 格子；个人库内松手后自动保存顺序，保存失败恢复原顺序。取消拖拽或松手到其他区域不改变收藏与顺序。「补充默认表情」收在更多菜单中。

左侧脸图使用角色详情素材表的固定顺序：角色绑定排序、素材来源排序、素材 ID，未设置排序的项目排在已设置项之后。点击右侧已有表情时，左侧自动切到关联角色，加载对应脸图所在分页并滚动定位、高亮具体格子，不将素材移到最前；可继续加载前后分页。共用脸图优先沿用当前角色，否则取来源列表首项，预览旁显示相关角色供切换，不推断格子人物。没有角色绑定的可用表情直接显示原脸图，不可用表情提示当前状态。角色素材的看图工具栏提供「收藏为表情」入口，正文表情可预览与收藏同款。

个人库首次打开时显式初始化默认清单，初始化标记独立于收藏记录。移除全部表情不触发再次初始化。「补充默认表情」仅补缺项。收藏与手动排序随账号保存，编辑器沿用同一顺序；成功新发表后，只移动正文中已收藏的表情，按首次出现顺序置前。新增收藏按选择顺序置前，重复收藏不重排。手动排序只移动指定表情，相对顺序保留；后续新增或使用仍按原规则置前，不影响其他项的相对顺序。预览、草稿、失败提交、论坛幂等重试和编辑旧正文不触发最近使用更新。选择面板在下次打开时刷新，操作期间保持位置。

热门榜按近 30 天公开正文中使用过该格子的不同用户数排序，同分按最近有效发表时间、表情 ID 排序。正文编辑同步当前引用，时间窗口仍使用原发表时间；可见性跟随既有评论和论坛公开规则。隐藏、删除或父内容不可公开访问的记录不计入。没有热门数据时单独展示默认推荐。

## 默认清单

`/admin/emojis` 使用同一工作台管理默认清单，右侧显示默认清单；可拖动排序，或选中后前移、后移，统一点击保存。权限为 `emoji.defaults.manage`，沿用原表情管理角色范围；保存写入审计。默认清单变更不覆盖个人库。首批默认内容由管理员选定；未配置时清单为空，用户仍可自行收藏。

本站不再提供独立表情图片上传、人工短代码、表情分类和退休模型。默认清单只引用脸图库内容。

## 编辑与接口

评论与论坛共用 `BodyEditor`。表情为不可拆分的行内节点，输入和已发布正文中默认显示 24×24 图片，支持删除、撤销、复制和重新编辑。桌面鼠标悬停或手机点击表情打开预览浮窗，上方显示相关角色名，中间按整数倍放大为 96×96，下方提供「加入表情库」按钮。鼠标可移入浮窗操作，离开后延迟关闭；点击外部或按 Escape 关闭，悬停预览不抢占输入焦点。表情库和选择面板仍以 48×48 展示单格。论坛主题和普通回复继续支持正文插图；其他评论使用文字与表情模式。

快捷表情选择器不使用整屏弹窗。桌面端贴着表情按钮弹出可滚动网格，空间不足时自动避让，选中后插入原光标位置并收起。手机端网格接在输入区工具栏下方，系统键盘收起，支持连续插入而不重新聚焦输入框；表情按钮切换为键盘图标，点击可收起面板并继续输入。点击外部或按 Escape 也可关闭。面板复用个人库顺序，提供加载、空态和重试反馈；加号按钮单独打开管理工作台，关闭管理后返回选择器，保留草稿和原选区。

正文以 `:face_<引用 ID>:` 序列化表情；它是存储及剪贴板格式，不作为普通页面标签。复制编辑器或已发布正文时，富文本保留表情引用，纯文本使用这一稳定标记；站内粘贴可恢复图片节点。正文摘要、提醒和搜索内容转换为 `[表情]`。表情按一个 Unicode 字符计入正文长度，插图偏移继续使用序列化字符串的 UTF-16 偏移，不能落在表情标记中间。正文只解析并加载实际引用的表情。

`/api/emojis` 的 GET 提供 `resolve`、`library`、`defaults`、`hot`、`categories`、`characters`、`sheets` 查询；公开正文引用解析允许匿名，其余查询要求登录。`characters` 可按 `categoryId` 分页加载分类成员，同时返回可公开访问的默认脸图；`sheets` 可用 `focus` 图片哈希定位素材自然顺序中的分页，响应包含该页 `offset`，前后翻页只传 `offset`，不传 `focus`。POST 提供 `initialize`、`replenish`、`add`、`remove`。新增格子提交图片哈希和行列；接口批量添加或移除一次最多 256 项，工作台逐项操作。`/api/admin/emojis` 的 GET/POST 读取和保存有序默认格子清单。所有写入要求同源，个人库只操作当前账号。

POST `reorder` 接收待移动的 `id` 和插入位置后的 `beforeId`（`null` 表示末尾）。在同一 D1 batch 中根据当前账号的即时收藏顺序完成移动，仅更新已有收藏的排序字段，不添加或移除收藏、不生成热门使用记录；移动项和位置锚点均须属于当前账号，失效返回冲突。并发设备的新增和移除保留。

`face_emoji_refs` 保存不可变格子，`user_emoji_library_state` 保存初始化与排序序号，`user_face_emojis` 保存个人库，`default_face_emojis` 保存默认清单。评论、论坛楼层、楼中楼分别用引用表关联原正文并遵守外键。正文、引用和最近使用更新在同一 D1 batch 中执行；论坛引用同步受已有写入版本门控。新引用在服务层与数据库触发器中核实可用性，原有下架引用可随旧正文保留。

## 开发与验证

统一初始化 SQL 和固定开发快照使用这一模型。快照原有开发短代码已替换为实际脸图引用或不可用文字，保留其他业务数据和单条初始化迁移账本；默认清单留空，由后台配置。表情引用纳入 blob 清理保护。

现有数据库不会随同名初始化 SQL 自动升级；备份、重建与部署需要单独授权。检查遵循维护与回归手册：相关类型与 lint、现有论坛契约、种子完整性及路由构建；不默认新增测试代码或进行浏览器验收。
