# 《2005～25キャラ歴史まとめ》数据化与角色库补充评估

分析日期：2026-09-16。源目录：`D:\Downloads\2005～25キャラ歴史まとめ`。

## 结论

这部游戏适合作为角色仓库的第二种资料来源，最有价值的是角色介绍、历史记录、登场作品线索和素材与人物的对应位置。图像也有补充空间，但不能将所有未匹配文件或年表条目直接导入。

- 当前本地 D1 有 **934 位角色**。游戏中 **1,418 个事件页**的首条标题与现有日文默认名或别名唯一匹配，涉及 **574 位角色**；这 574 位当前简介均为空。这是待核实的简介补充范围，不是已验证的 574 份人物传记。
- 经过整图和格子比较，优先候选表包含 **235 个未匹配的图像格位：93 个脸图格子、142 个行走图角色块**，涉及 **172 位名称匹配的现有角色**。这些是不同的源文件／格位，也有不同的规范化像素签名；仍需确认身份、差分和原素材出处。
- 找到 **4 位没有默认头像的现有角色**，游戏里有明确首屏脸图位置，可优先补齐：イザベル、プリシア、リード、カッターラビット。
- 存在新角色候选，也存在异写、改名、服装形态、多人合集和已有素材漏绑。必须分开处理。

本次只生成独立提取包、候选表和报告，没有更改角色、分类归属、素材正式清单、D1 或 R2。

## 提取方法与完整性

使用 [EasyRPG 官方工具](https://easyrpg.org/tools/)中的 **LCF2XML**，从[官方下载页](https://easyrpg.org/tools/downloads/)所链接的 Windows 构建下载。以 **CP932（932）** 解码日文，转换 `RPG_RT.ldb`、`RPG_RT.lmt` 和全部 `.lmu`。输入副本放在输出目录，原游戏不受转换器写入影响。

EasyRPG 输出是 XML，但扩展名分别为 `.edb`、`.emt`、`.emu`。80 个输出均成功解析。转换器下载地址、可执行文件 SHA-256 和执行结果保存在 `conversion.json`；每个源文件的路径、大小和 SHA-256 保存在 `source-files.json`。

| 内容 | 数量与处理 |
| --- | --- |
| 地图 | 78 张，保留地图名、父节点、年表上下文 |
| 事件页 | 4,530 页，包含 4,288 页文字事件 |
| 地图消息 | 15,422 个消息块、28,057 行，保留选项分支 |
| 公共事件 | 10 条记录，其中 3 条有指令，另外保存 28 行消息文本 |
| 完全相同正文去重 | 2,593 组；原位置全部保留 |
| 不同首条标题 | 2,308 个；不是角色人数 |
| 图片 | 2,695 个文件，2,673 个不同文件哈希；原图按哈希复制到提取包 |
| 地图图片引用 | 行走图、切换脸图、显示图片均解析；缺失或有歧义的本地文件引用为 0 |

保留全部原始事件指令，而不是只导出对白。`10130` 的首个参数是脸图索引，`11110` 表示显示图片，`12330` 表示调用事件；语义对照了 [EasyRPG Player 的解释器实现](https://github.com/EasyRPG/Player/blob/master/src/game_interpreter.cpp)。公共事件调用可能循环，因此保留调用指令和公共事件记录，不将其无限展开。

没有运行游戏或进行浏览器／人工 UI 测试，也没有使用本地模型翻译。提取包保存日文原文。本报告中的中文说明是分析摘要。

## 图像补充评估

身份匹配以当前 D1 只读快照为准。图像比较基线为当前磁盘清单中的 **5,187 条脸图、11,897 条其他素材**；清单哈希也已记录。D1 还有 2 个不在清单中的脸图文件，分别绑定ザック和アルベルト，本轮没有对它们做像素比较。因此“未匹配”特指本轮清单与已扫描格子范围。

| --- | ---: | ---: | ---: | ---: |
| 脸图 | 1,212 | 665 | 194 | 353 |
| 行走图 | 1,326 | 535 | 132 | 659 |
| Monster | 65 | 0 | 0 | 65 |
| Picture／Battle | 41 | 1 | 0 | 40 |

整图共排除 1,527 个重复文件。仓库有 1 个 PNG 无法被当前 Pillow 解码，仍完成文件字节比较，具体记录在 `repository-image-decode-errors.json`；没有把它计作成功的像素比较。

进一步按游戏实际引用的位置比较：脸图使用 48×48 格子，标准 288×256 行走图使用 72×128 角色块。扫描仓库 **82,557 个脸图格子、30,440 个行走图角色块**，又发现 **186 个整图未匹配但格子已存在的引用位置**。还将整图一致但仓库分类不同的素材视为已有，避免类别差异造成假新增。

格子比较分别记录原有透明度与调色板第 0 色透明的解释，并清理完全透明像素的隐藏 RGB；不缩放，不做相似图猜测。它仍不能识别改色、重新绘制、不同尺寸或非标准拼图的同源素材。

优先图像候选限定为：标题唯一匹配现有角色，且素材来自事件行走图或首次标题前设置的脸图。介绍中途出现的其他脸图、插图只作为事件证据，不自动归给标题人物。候选均标明需要复核。

## 角色信息补充与身份消歧

**简介与关系。** 例如 Map0008/E0001 的アンデッドナイ介绍了武器、性格、目标和与其他人物的关系。可整理为中文简介，但“某作品中的设定”“经常采用的设定”和编者评价应保留区别。不要把本文本中每一次关系提及都写为固定设定。

**创作过程。** Map0007/E0002 的作者房间直接说明アクアフラッド是其制作的第一位玉露将军，最初想做成アグネファイア的对手，并解释了行走图的改造动机。Map0007/E0014 还有第二次玉露热潮的回忆。这类文字适合以“本游戏作者自述”保存，价值高于简单复述 Wiki 名称。

**年代与登场作品。** 年表既记录角色出现，也记录后来新增脸图或行走图；不能将所在年份一律当作角色诞生年份。例如リズティア的旧条目写 2014 年登场，2023 年条目讲的是表情素材增加。`yearContext`、原文日期提及及“登場作品”选项文本分别保存，作品号只是进一步查证线索。

### 值得优先调查的缺失身份候选

- **リストレイン**：Map0065/E0016、Map0036/E0043。原文为草属性拘束魔法具现化，提到「2024年 夏の陣 No.31／廃材・アイデア・デフォ戦」。目前日文名与别名均未匹配，脸图与行走图及对应格子也未匹配。
- **とげとげ言葉バリア**：Map0073/E0018、Map0037/E0066。原文为抵挡尖刻言语的屏障魔法具现化，提到「2025年GW／行き当たりばったりビーム」。同样未匹配名称、两类整图及对应格子。

这两项有“标题＋人物图像＋说明＋作品线索”，优先级高于仅文件名或一个模糊标题的候选。尚未核查所指作品或 Wiki 其他页面，不宣称已确认独立新身份。

Map0070「保管庫でまだ埋まっている」有多个同名ストーンIII、スターライトIII等旧设计；即使与现有名字精确相等，也需要单独消歧。Map0072「急募部屋」明确存在作者尚不知道年代的怪物娘，不能推断其年份。2025 年地图中还有「MV一般人8種」「乔治的船」和形态变化，说明不能把未匹配的 2,426 个事件页当作新角色。

## 如何接入现有模型

1. **先整理证据。** 按真实 `characterId` 合并重复介绍，保存游戏文件指纹、地图／事件／页、指令索引、原文和编辑后的摘要。`character-evidence.json` 已按 574 个候选角色聚合完全相同的正文。
2. **先补简介与已确认头像。** 简介沿用 `characters.description`；脸图沿用 `face_sheets`、角色绑定及格子头像规则；其他图片沿用三类素材及多人绑定。不另建第二套角色身份。
3. **再核实异写、漏绑与新身份。** 已有身份可补来源支持的别名；分类仍由当前分类与归属关系管理，不能照搬游戏房间树覆盖现有分类。素材类别与角色分类是不同概念。
4. **为本地游戏补来源表达。** 当前 `character_sources` 接受 HTTP(S) URL，不能塞入 `D:\...` 路径；现有素材来源清单也围绕网页字段。正式接入时应给本游戏建立可引用的归档／来源页，另外保存文件 SHA-256 和事件定位。现有 `extra_json` 可以承载经设计的结构化历史证据，或另建明确的资料引用记录；不要伪造 Wiki URL、`sourceKind=atwiki` 或网页顺序。

65 张 Monster 图片没有被地图事件直接引用。它们已保存在资产清单中，但不能仅凭文件存在绑定给某角色。场景／系统图也不作为角色素材候选。
