# 上传素材引用清理

新上传固定清理未引用素材，存档默认等待上传者勾选。需要保留的文件在主游戏就绪后通过“追加文件”选择，确认作品资料时再上传。勾选的存档进入主游戏清单，其他追加文件随普通下载附带。标准素材目录中的排除文件收纳在默认折叠、没有文件夹图标的“游戏中未引用的素材”区域，包含清理排除素材及同目录下类型不支持的文件；存档单独收纳为“存档文件”区域，其他排除文件独立显示。恢复旧草稿沿用其已准备的主游戏清单，不追溯改写历史归档。

## 范围

- 候选是标准素材目录中的图片、音频和视频，包括 RTP、自定义、修改版及改名副本。
- 保留程序、数据库、地图、字体、Logo、配置、说明、翻译文本和未知目录；原有文件类型白名单独立执行。
- 扫描数据库全部记录、全部地图及事件、公共/战斗事件和移动路线，所有字符串引用都保护同名候选；不按剧情可达性继续删减。
- 地图树中的区域节点不要求独立 `.lmu`：类型为 2，或非标准的类型 0，且具有有效非空区域矩形、父节点为已扫描的实际地图时，按区域处理。仍扫描区域自身的全部引用；不按 `AREA` 名称跳过缺失地图。
- 地图树登记但上传目录中不存在的 `.lmu` 只记录提示，不阻止清理；按实际提供的文件分析引用。已提供但未扫描、损坏或解析失败的核心文件仍保留全部候选。缺失素材检测继续提示此类缺失地图导致检查不完整。
- 多编码结果取并集。动态加载保护相关目录；插件、未知指令/字段、未扫描完整或超过预算时保留全部候选。
- 显示图片指令支持 RPG Maker 2003 1.12 的 30 参数格式：未启用文件名替换且不含字符串变量标志时，按字面文件名扫描。动态或未知参数布局继续保护图片目录，并标记缺失检测不完整；基础版清理与缺失检测使用相同判定，日志中的相同原因只显示一次。
- 根目录的 `harmony.dll` 和 `ultimate_rt_eb.dll` 属于标准 RPG Maker 2000/2003 运行库，不因其存在放弃清理；根目录的 Maniac `accord.dll` 按下述规则分析，其他 DLL 仍按未分析扩展保护。运行库文件本身不属于清理候选。
- 普通数据库字段、对白、改名、称号和资源文件名按字面值参与素材引用匹配，不因 `@` 或 `$` 前缀保护全部素材。标准 ExFont `$A`～`$Z`、`$a`～`$z`、Maniac ExFont `$[x,y]` 和 EasyRPG 的 `$` 大尺寸角色图文件名均不属于注释脚本。
- 扩展注释只在注释指令 `12410`／`22410` 中识别，标记必须位于第一个字节：根目录 `dynloader.dll` 对应 `@` DynRPG 命令，`Destiny.dll` 对应 `$` DestinyScript；存在未分析的根目录 `EasyRPG.ini` 时，另识别 `@easyrpg_` 命令。未识别的 DLL 和扩展配置仍保留全部素材，不根据脚本文本猜测加载资源。普通注释或前导空白不被当作脚本；未知指令和字段继续保守保护。[EasyRPG 脚本入口源码](https://github.com/EasyRPG/Player/blob/e68fff4a13a3dd5d40678ae66ee60f85ccb04153/src/game_interpreter.cpp#L2113)、[DynRPG 文档](https://wiki.easyrpg.org/development/technical-details/patches/dynrpg)。
- 静态分析不能证明任意自定义 EXE、补丁或旧存档的隐式资源需求；需要把排除素材随下载保留时，可在“追加文件”中选择。

只从本次上传归档中排除素材，不修改本地原文件。下载和在线游玩仍使用同一份归档；需要保留排除文件时使用“追加文件”；勾选的存档也进入在线安装清单。

## Maniac 作品

上传端沿用引擎检测结果，结合根目录的 `accord.dll` 选择 Maniac 图片和音频规则。只有事件编号提供扩展证据时，扫描器合并基础版和 Maniac 的可能引用。服务端用同一读取器复核，读取已验证的核心包和配置文件。根目录 `EasyRPG.ini` 中已识别的 Maniac 开关和 Netplay 开关可以继续分析，其他未分析设置沿用整包保护。

- 字符串变量表按记录读取，扩展术语按字符串扫描，敌人、物品、状态、系统中的已知数值字段按整数读取。数据库、地图与事件中的固定名称仍参与同名保护。
- 显示图片的文件名模式、数字替换与位置、颜色、缩放等控制位分别处理。数字替换按原名截断的 UTF-16 位数、补零宽度、符号和可能的整数位数匹配现有文件。同目录下的同名多扩展、子目录以及指向其他素材目录的相对路径均参与匹配。
- 对固定图片名的数字替换，扫描器追踪全局编号变量的常量、复制、随机范围、算术及有界循环。条件分支取并集，标签跳转按目标合并，间接写入和可能并行的事件进入同一份写入检查。只有每个使用点都能排除某个编号，才从该模板的保留范围移走对应文件。同名多扩展、其他模板和脚本引用分别继续参与判断。零初值顺推、其他事件里出现过的编号和局部条件可用于复核，不能单独授权删除。未限定写入、外部脚本或超过分析预算时沿用文件名模板保护。
- 编号表达式中的常量上下限 Clamp 可以限定结果。已读且无数值写入的地图事件页调用保留调用前的变量事实。单条脚本中对固定数值槽的简单写入只影响相应的事件内追踪；项目含脚本时仍保守处理全局数值。计数器使用后调用公共事件、由调用方传入 SELF 上限并在递增到上限时复位的模式，可作为保留编号的证据，不单独授权排除文件。
- 文字图片 `3007` 单独读取系统图字段。移动路线追加动作 `3027` 区分角色图、音效和其他动作。音频、头像和远景等指令按文件名的模式位判断。只要路径可来自任意字符串，同类媒体在其他目录中的文件也可能被 `../` 引用。
- 对直接用字符串变量取名的指令，汇总所有地图、数据库事件中的可能写入，再处理消费该槽的指令。全局槽跨文件合并，SELF 按所属核心文件合并，并计入调用方传入的参数和可能写入该槽的间接赋值。字面量、已有 BGM 名称、数据库物品名称和说明、十进制数值及追加数字分别处理。变量复制继续追到源槽。追加数字时将可能的字面前缀按消费指令的素材目录解析，保留可生成的路径，包括显式跨目录引用。无法限定的写入、读取共享存档字符串、动态执行的事件等继续保守处理。
- 生成指令 `3019` 按目标编号、参数模式和写入的数据类型判断。JavaScript 的 `3030/3031` 合并为脚本后，使用 Acorn 静态解析。不同事件中的共享对象、函数、回调实参、返回值和对象字段一起传播，分支取并集。画布绘图、图片文件属性和头像回退分别记录依赖。未知图片名保留可能的图片，无法限定的宿主调用、外部脚本、未支持的语法或分析超过预算时保留整包。扫描不会执行作品脚本。

原版参数资料见 [Maniac 250921 指令清单](https://github.com/SomiaWhiteRing/EasyRPG-Player-Kai/blob/f3b410535249c0adfdc71ac41da7353e9e3eb399/docs/maniac-250921-command-inventory.csv)。图片文件名求值和文字图片资源读取见 [Kai 事件解释器](https://github.com/SomiaWhiteRing/EasyRPG-Player-Kai/blob/f3b410535249c0adfdc71ac41da7353e9e3eb399/src/game_interpreter.cpp#L3535) 和 [文字图片实现](https://github.com/SomiaWhiteRing/EasyRPG-Player-Kai/blob/f3b410535249c0adfdc71ac41da7353e9e3eb399/src/maniac_text_picture.cpp#L419)。

## 数据与复核

高级选项中的“检测缺失素材”默认关闭，开启后检查标准资源字段和事件中的静态文件名。检出疑似缺失或检查不完整时，在上传进度下方的文本区域提示，详情与引用来源以红字写入高级选项的检测日志。检测日志显示疑似缺失项、引用来源、检测不完整／跳过原因，以及播放器替换和 RTP 自动补充记录，不显示未引用素材清理明细。播放器替换和 RTP 补充记录不受缺失检测开关影响。检测开关独立于固定清理流程，在选择文件前设置；结果随本地上传任务与恢复草稿保存，不进入服务端 manifest，不阻止上传。按素材目录匹配大小写和支持的扩展名；空名及 `(OFF)` 不告警，普通对白、名称、注释不作为缺失引用。

上传根目录包含 `accord.dll`（忽略大小写）时，已开启的缺失检测自动跳过，日志记录“检测到Maniac补丁，自动跳过缺失检测”，不更改用户保存的检测偏好。RTP 自动补充独立执行；扩展保护不阻断此只读扫描，遇到未知但可按长度跳过的字段或事件指令后继续读取标准引用。素材清理独立执行上节的 Maniac 规则。上传预填将当前 2000 或普通 2003 引擎自动切换为 2003 Maniac；此识别优先于 `ultimate_rt_eb.dll` 的普通 2003 识别，不读取 DLL 内容。

RTP 自动补充始终开启，按标准资源字段和事件中的静态文件名匹配：先查当前引擎家族的精确名称，没有候选时查其他 RTP 包的精确名称，然后依次查当前家族及其他家族的已知别名。同一优先级的候选按 SHA 去重，只有一个不同内容时补充；出现不同 SHA 时停止，不通过低优先级匹配掩盖歧义。上传中已有同名素材时保留原文件。别名使用 EasyRPG 的 RTP 命名表，生成时按各包实际使用的语言列匹配资源，避免把另一语言的同名资源混入候选。补充路径保留游戏实际引用的名称，例如 `SystemC` 可引用 `system4` 的同一 SHA，归档路径仍为 `System/SystemC.png`。

Maniac 的音效 `11550` 和 BGM `11510` 分别支持已确认的 5／6 参数布局：文件名模式为第 4／5 个参数的低四位，值为 0 时使用字面名称；音量、速度等其他参数使用变量不阻断补充。字符串变量、间接字符串变量和未知参数布局继续跳过，不推断动态文件名。清理另按原版指令的缺省参数规则处理省略尾部零值的记录。

此检查仅说明上传文件中未找到引用，不证明运行必需：数据库中未使用的记录也可能产生提示，外部 RTP 不在检查范围。未指定编码时尝试多种编码，任一匹配即视为存在，显示名称可能有歧义。扩展、动态文件名、解析失败或超过预算会标明检查不完整；最多列出 200 个不同资源。缺失诊断独立于清理决策，沿用同一 LCF 读取器但不改变既有排除规则与报告协议。

`lib/archive/lcf-reference-scan.ts` 是共用只读 LCF 扫描器；`resource-cleanup.ts` 固定生产候选规则及报告版本 `resources-static-v11`，历史 RTP 对照规则版本为 `rtp-exact-static-v3`。上传文件策略为 `rpgm2000-2003-resources-v18`，不接受旧策略的新提交。

同名候选通过原地追加建立索引；每个名称命中后释放该索引项，后续重复引用不再遍历已保护候选。多编码的相同解码结果只处理一次，扩展命令判断仅在符合上述补丁证据与前缀条件的注释指令中生效。整个扫描的候选遍历总量受候选文件数约束。

客户端哈希后扫描已缓存的核心文件，排除未引用候选并重建 blob 集合；仍被其他保留路径使用的同内容 blob 不删除。“检查素材引用”阶段的统计、排除明细和保护原因随 `archiveVersion.resourceCleanup` 存入 manifest 和草稿。

服务端校验报告版本、允许的素材路径、摘要格式、重复项、统计及路径冲突，在现有核心包逐文件校验期间复核实际引用。仍被引用、核心未完整扫描或需要保护的排除项会被拒绝；commit 绑定 source-ready 验证后的完整 manifest 摘要。服务端不能证明客户端未上传的原始文件内容，报告不是原包完整性证明。

历史指纹清单 `rtp-catalog.json` 和 `rtp-cleanup.ts` 仅用于离线历史对比。生产上传的 `rtp-upload-catalog.json` 只携带补充所需的路径、长度、SHA、CRC 和已知别名，不携带 RTP 图片或音频；补充继续引用项目库中已有的固定 SHA，source-ready 校验对象账本。生成器校验 RTP 字节，记录别名表来源、内容摘要和许可；许可副本位于 `public/licenses/easyrpg-player/COPYING`。重新生成命令为 `python scripts/import-upload-rtp.py --rewriter ../RPGRewriter-Ownuse --player ../Player`。修改素材清理规则或 LCF schema 时同步提升清理版本和文件策略版本；仅调整补充匹配不改变清理报告版本。

## 验证与历史对照

既有 `scripts/rtp-cleanup-check.ts` 同时检查 RTP 对照规则和当前全素材规则，包括引用保护、自定义素材、动态/未知结构回退和无效报告。`system-self-check.ts flow` 使用固定清理规则，执行上传恢复、提交、下载及安装等既有流程。

```powershell
npx tsx scripts/rtp-cleanup-check.ts
npm run build
npx tsx scripts/system-self-check.ts flow --game output/resource-cleanup/zen/original.zip --archive-only --report output/resource-cleanup/production/flow-enabled.json
```

2026-09-23 的三组空间实验见 [resource-cleanup-experiment.md](resource-cleanup-experiment.md)；此前 RTP-only 实现和实测记录见 [rtp-cleanup.md](rtp-cleanup.md)。这些是历史成本证据，不代表当前默认策略。

2026-09-24 接入核验使用《[醤油]膳》的同一原始白名单 ZIP，两轮在隔离 D1/R2 中串行执行。开启时排除 971 个文件，保留 469 个，排除路径/大小/摘要与此前全素材实验完全相同；关闭时保留全部 1,440 个文件，`resourceCleanup` 为 null。两轮均通过偏好刷新持久化、Tooltip 展示、控件点击不触发文件选择，以及实际上传、草稿恢复、提交、下载逐文件校验、安装/刷新和启动。此处的启动检查不代表全剧情或旧存档验证。
